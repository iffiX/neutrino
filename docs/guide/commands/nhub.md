# nhub commands

`nhub` is the hub's command line, installed with the hub package on the machine that runs the hub. The table lists its subcommands in the order `nhub --help` prints them.

## Subcommands

The **Root** column marks the subcommands that need root on Linux and macOS, or a terminal opened as administrator on Windows. Run without it, such a subcommand prints the line to run instead and exits with status 2.

The **Asks first** column marks the subcommands that ask one `[y/N]` question before they act. `--yes` answers it, and a `no` exits with status 1 and changes nothing. With no terminal on standard input and no `--yes`, the subcommand prints one line naming `--yes` and exits with status 1.

| Command             | Arguments and flags                                                                                                                                                                                           | Root | Asks first | What it does                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `nhub setup`        | `--stdin` reads every answer as one JSON object from standard input; `--json <path>` reads them from a file; the two exclude each other                                                                       | yes  | no         | Sets this machine up one time, through the browser wizard or the terminal's screens. A machine with a panel password already set is rejected.                                                                                                                                                                                                                                                                       |
| `nhub run`          | `--host`, `--port`, `--reload`, `--interface`; one of `--only-web`, `--only-xray`, `--only-cliproxyapi`, `--only-dnsmasq`, `--only-supplicant`, `--only-dhcpcd`, `--only-router`                              | no   | no         | Runs one hub process in the foreground. It is the entry every `neutrino_hub_*` unit runs; `start` and `stop` control the units.                                                                                                                                                                                                                                                                                     |
| `nhub open`         | `--print` prints the address another machine opens; `--start-service` is the elevated step `nhub open` runs itself; `--output <path>` writes that step's address to a file                                    | no   | no         | Opens the panel, or the setup wizard before setup, in the default browser. When the hub's service is stopped, it shows the system's administrator prompt (UAC, the macOS dialog or `pkexec`), starts the service, then opens the address. A declined prompt exits with status 1.                                                                                                                                    |
| `nhub start`        | `--interface`; `--yes`; one of `--only-router`, `--only-xray`, `--only-dnsmasq`, `--only-cliproxyapi`, `--only-relay`, `--only-web`, `--only-supplicant`, `--only-dhcpcd`                                     | yes  | yes        | Starts every enabled unit of the hub, routing state first and panel last, or the one unit named. A unit already running stays as it is. `--only-supplicant` and `--only-dhcpcd` need `--interface`. On macOS and Windows it starts the hub's one service.                                                                                                                                                           |
| `nhub stop`         | `--interface`; `--yes`; one of `--only-web`, `--only-relay`, `--only-cliproxyapi`, `--only-dnsmasq`, `--only-xray`, `--only-router`, `--only-supplicant`, `--only-dhcpcd`                                     | yes  | yes        | Stops what the hub runs, panel first and routing state last, or the one unit named. The optional modules and the virtual network engines keep running, and every unit starts again at the next boot. On macOS and Windows it stops the hub's one service.                                                                                                                                                           |
| `nhub status`       |                                                                                                                                                                                                               | no   | no         | On Linux, prints one line per hub unit: not installed, or running or stopped, and enabled or disabled. On macOS and Windows, prints the state of the hub's one service. Exits with status 0 while the panel runs, and 1 otherwise.                                                                                                                                                                                  |
| `nhub service run`  | `run` is the only action                                                                                                                                                                                      | yes  | no         | Runs the hub as the Windows service. It is the entry the service control manager starts; started from a terminal, it exits with status 1, and on another system with status 2.                                                                                                                                                                                                                                      |
| `nhub apply`        | `--only <component>` for `router`, `xray`, `dnsmasq`, `cliproxyapi` or `overlay`, repeatable; `--dry-run` prints the rendered files and changes nothing; `--skip-apply` writes the files and restarts nothing | yes  | no         | Renders every generated configuration from `config/`, validates it and applies it, in the order the panel's own apply uses.                                                                                                                                                                                                                                                                                         |
| `nhub unlock`       |                                                                                                                                                                                                               | yes  | no         | Clears the panel's login lockout and every fail2ban SSH ban.                                                                                                                                                                                                                                                                                                                                                        |
| `nhub reset`        | `all`, `network` or `password`; `--stdin` reads the new password from standard input; `--yes`                                                                                                                 | yes  | yes        | `password` stores a new panel password and signs every session out. `all` hands the network back, returns every file in `config/` to its example, deletes the keys, tokens and certificates the machine collected, and stops the hub. `network` hands the network back and changes no file in `config/`; removing the package runs it. With no target it lists the three, changes nothing, and exits with status 2. |
| `nhub update`       | `--yes`; `--package <file>` installs that package file instead of the newest release                                                                                                                          | yes  | yes        | Installs the newest release outside its own process, holds a health gate of three minutes, and puts the previous version back when the new one fails it. On Linux the `neutrino_hub_update` unit runs the install. The command prints how the update ended.                                                                                                                                                         |
| `nhub vault rekey`  | `--stdin` reads the new passphrase from standard input                                                                                                                                                        | yes  | no         | Wraps the vault's data key under a new master passphrase. Nothing sealed is encrypted again.                                                                                                                                                                                                                                                                                                                        |
| `nhub scan-secrets` | `--staged`, `--history`, `--no-entropy`, `--no-vendor`, `--quiet`                                                                                                                                             | no   | no         | Checks the working tree, the staged files or every commit for credentials. A development command.                                                                                                                                                                                                                                                                                                                   |

Each `--only-` flag names one systemd unit, `--only-relay` being the SSH Relay's, and exists on Linux alone; elsewhere it exits with status 2. `--only-xray` and the `xray` component exist in the full edition only, the one that includes the proxy.

## Global flags

| Flag        | Where                         | What it does                                                                                                 |
| ----------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `--version` | `nhub`                        | Prints the package version and exits.                                                                        |
| `--dev`     | `nhub`, before the subcommand | Runs against `hub_dev_root/` in a working copy and lifts the root check. A packaged hub exits with an error. |
| `-h`        | every level                   | Prints that level's help and exits.                                                                          |

## Exit statuses

| Status | When                                                                                                                                                                                          |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0      | The subcommand finished, or found nothing to do.                                                                                                                                              |
| 1      | The answer to `[y/N]` was no, a step failed, or `nhub status` found the panel stopped.                                                                                                        |
| 2      | A subcommand that needs root ran without it; `nhub` or `nhub reset` ran with nothing named; an `--only-` flag ran off Linux; `nhub update` cannot run from this installation, a working copy. |
| 130    | Ctrl-C stopped the subcommand.                                                                                                                                                                |
