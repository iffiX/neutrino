# 设置

**设置**（Settings）页管面板自身：HTTPS，面板的密码、语言和主题，配置备份，以及 hub 自己的更新。在终端里重置这台机器的命令列在本页最后。

## HTTPS

面板占两个端口：HTTP 走面板端口，默认 `8080`；HTTPS 走 HTTPS 端口，默认 `443`。不管 HTTPS 开没开，两个端口都提供面板，都在[网络](./network.md#面板端口)页的**面板端口**（Panel ports）里改。HTTPS 端口用的证书由这个 hub 自己生成的证书颁发机构签发，浏览器装过这个颁发机构，打开时就不报警告。

**开启 HTTPS**（Enable HTTPS）之后，HTTP 端口把每个浏览器转到 HTTPS 地址，会话 cookie 也带上 `Secure`，下一个请求就生效。每台设备的顺序都一样：先装颁发机构，再重启浏览器，最后开启 HTTPS。

### 安装颁发机构

开始之前，在要设置的设备上用 `http://` 地址打开面板。然后安装：

1. 在 **HTTPS** 一节点**安装证书**（Install certificate）。浏览器下载 `neutrino-<hub>-ca.crt`，其中 `<hub>` 是这个 hub 的名称。
1. 在系统标签条里选你的系统。当前设备的系统已经选好，标着**本机**（this device）。
1. 照标签条下面的步骤做。
1. 关掉浏览器，再重新打开。

| 系统           | 下载之后的步骤                                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------------------------ |
| Windows        | 打开文件，选「安装证书」和「本地计算机」，放进「受信任的根证书颁发机构」。                                         |
| macOS          | 打开文件，钥匙串访问把它加入登录钥匙串。在钥匙串访问里打开 Neutrino 颁发机构，把「使用此证书时」设为「始终信任」。 |
| Linux：Chrome  | 打开 `chrome://certificate-manager`，依次选「自定义」→「受信任的证书」→「导入」，选中文件。                        |
| Linux：Firefox | 打开「设置」→「隐私与安全」→「查看证书」，在「证书颁发机构」页导入文件，勾选「信任由此证书颁发机构来标识网站」。   |
| Android        | 打开「设置」→「安全」→「加密与凭据」→「安装证书」→「CA 证书」，选择「仍然安装」，再选中文件。                      |
| iPhone 和 iPad | 在 Safari 里下载文件，在「设置」里安装描述文件，再到「通用」→「关于本机」→「证书信任设置」里打开完全信任。         |

在 macOS 上，关闭证书窗口时输入密码确认，信任设置才生效。

![钥匙串访问的信任设置，设为始终信任](/guide/os/os_mac_keychain_trust.webp)

在证书警告页上点过「继续访问」的 Chrome，导入之后仍显示「不安全」，重启之后才恢复。

### 开启 HTTPS

浏览器重启后，用 `http://` 地址打开面板。**HTTPS** 一节从 HTTPS 端口取一个测试地址，按钮左边的一行给出结果：

| 提示                                                                             | 含义                                      |
| -------------------------------------------------------------------------------- | ----------------------------------------- |
| **这个浏览器已信任证书**（This browser trusts the certificate.）                 | 可以点**开启 HTTPS**                      |
| **先安装证书并重启浏览器**（Install the certificate, then restart the browser.） | 浏览器不认这张证书，**开启 HTTPS** 是灰的 |

点**开启 HTTPS**，页面跳到 `https://` 地址；此后 HTTP 端口把每个浏览器都转过去。**关闭 HTTPS**（Disable HTTPS）让页面回到 `http://` 地址，在那里重新登录：切换时会话被结束，此后 HTTPS 端口把每个浏览器送回 `http://`，顺手删掉旧 cookie。

![HTTPS 已开启，下面是各条状态](/guide/zh/settings_https_on.webp)

证书上的名字包括这台机器的私有地址和虚拟网地址、`127.0.0.1`、`localhost`、主机名和 `hub.neutrino.internal`。用公网地址打开面板时，即使装了颁发机构，浏览器也会报警告。

### 看状态行

| 状态行                                     | 显示什么                                                      |
| ------------------------------------------ | ------------------------------------------------------------- |
| **访问地址**（Addresses）                  | 这台主机的 `http://` 和 `https://` 地址，正在用的标着**当前** |
| **颁发机构 SHA-256**（Authority SHA-256）  | 颁发机构的指纹，用来和设备上显示的核对                        |
| **颁发机构生成于**（Authority created）    | 颁发机构生成的时间                                            |
| **证书上的名字**（Certificate names）      | 面板证书覆盖的每个地址和名字                                  |
| **证书签发于**（Certificate issued）       | 当前证书的签发时间                                            |
| **证书到期于**（Certificate expires）      | 当前证书的到期时间                                            |
| **上次自动续签**（Last automatic renewal） | hub 上一次自己签发新证书的时间                                |

机器的地址变了，或者离证书到期还剩 30 天时，hub 自己签发一张新证书。信任颁发机构的浏览器照样接受新证书。

### 重新生成颁发机构

**重新生成证书**（Regenerate certificate）换掉颁发机构和证书。装过旧颁发机构的浏览器都会重新报警告，直到装上新的。在 `https://` 页面上这个按钮是灰的，旁边写着**先关闭 HTTPS，才能重新生成证书**。

1. 如果 HTTPS 开着，点**关闭 HTTPS**。页面回到 `http://` 地址，在那里重新登录。
1. 点**重新生成证书**并确认。浏览器马上下载新的颁发机构。
1. 照[安装颁发机构](#安装颁发机构)装上它，再重启浏览器。
1. 点**开启 HTTPS**。

颁发机构存在 `config/` 里，所以恢复备份后，浏览器已经信任的那一个仍然有效。

## Hub 名称、密码、语言和主题

| 分节                           | 字段                                                                                                 | 按钮                            |
| ------------------------------ | ---------------------------------------------------------------------------------------------------- | ------------------------------- |
| **Hub 名称**（Hub name）       | **名称**（Name），已加入的客户端用它显示这台 hub                                                     | **应用名称**（Apply name）      |
| **面板密码**（Panel password） | **当前密码**（Current password）、**新密码**（New password）、**确认新密码**（Confirm new password） | **修改密码**（Change password） |
| **语言**（Language）           | **语言**，面板显示所用的语言                                                                         | **应用语言**（Apply language）  |
| **外观**（Appearance）         | **主题**（Theme）：**跟随系统**（System）、**深色**（Dark）或**浅色**（Light）                       | **应用主题**（Apply theme）     |

改密码之后，其他会话保持登录。跟随系统时，配色取自浏览器。桌面客户端有自己的语言和主题设置。

## 备份配置

在**配置存档**（Configuration archive）一节点**下载备份**（Download backup），浏览器保存一个 `.tar.gz`，里面是整个 `config/`。

存档里的凭据以保险库主口令封存；其余内容，谁拿到文件都能读。存档只有配置：共享里的文件、Gitea 仓库、容器的卷和 ZFS 数据集都留在各自的机器上。

## 恢复备份

1. 在**配置存档**一节点**从文件恢复**（Restore from file），选中存档。
1. 在对话框的**保险库主口令**（Vault master password）里，填这份备份所属保险库的主口令。
1. 点**恢复**（Restore）。

存档里的文件替换 `config/` 下的每个文件，hub 随即应用，面板重启。页面自己刷新，用恢复后的密码登录。

文件不是 `.tar.gz` 时，hub 返回 `backup_wrong_extension`。存档损坏时返回 `backup_corrupt`，口令不对时返回 `vault_passphrase_wrong`，这两种情况下什么都不恢复。应用没有完成时，文件已经恢复；按对话框写的原因处理好，再运行 `sudo nhub apply`。

被控端和客户端会自己重新连上。恢复到另一台机器时，每个 AI 订阅账号要重新登录一次，因为这些登录信息保存在 `config/` 之外。

## 更新 hub

**更新**（Update）一节把 hub 升级到更新的发行版本，就装在它运行的这台机器上。

1. 在**更新**一节点**检查更新**（Check for updates）。这一节列出最新发行版本的日期、大小、**发行说明**（Release notes），以及安装要占的磁盘空间和剩余空间。
1. 点**安装**（Install）加版本号的按钮，再确认。

![更新一节显示有更新的发行版本](/guide/zh/settings_update.webp)

面板下载安装包，按发行版本的 `SHA256SUMS` 核对。然后由 systemd 单元 `neutrino_hub_update` 在面板之外安装。页面回到登录页，登录后这一节写出旧版本、新版本和更新日期。

安装后最多三分钟里，这个单元检查面板是否应答、路由服务是否在运行。检查不通过时，单元装回上一个版本，这一节写出原因，并给出**安装日志**（Install log）。没有可以装回的旧安装包时，确认框会事先写明。

机器可用内存不到 300 MB 时，单元在解包前先停下面板和 AI 网关，装完再启动它们。检查通过后，单元从新 hub 重装 hub 这台机器自己的被控端。其他机器上的被控端，只要新 hub 仍接纳它们的协议，就会从新 hub 自行更新。

新的大版本不从这里安装，因为大版本会改变 `config/` 的结构。从源码检出运行的 hub 显示**这个 hub 从检出运行，请用 git 更新。**

在终端里，`sudo nhub update` 做同样的事，安装前先要你确认。`--yes` 跳过确认，`--package` 安装你自己下载的安装包文件。单元的日志用 `journalctl -u neutrino_hub_update` 查看。

## 从 0.4 升级

hub、被控端和客户端共用一个版本号，0.5.0 只说协议 3。0.3 或 0.4 的被控端和客户端连上来，hub 返回 `protocol_too_old`，意思是对方的协议号低于 hub 能接纳的最低值。这些对端保留绑定，但不会从 hub 自行更新。按下面的顺序升级：

1. 在 hub 这台机器上，从**更新**一节、用 `sudo nhub update`，或者按[安装 hub](./install.md) 里的方法装 0.5.0。
1. 如果 hub 这台机器自己的设备在[设备](./devices.md)页显示离线，在 hub 这台机器上用 `apt` 或 `dnf` 装 0.5.0 的被控端安装包。
1. 对 hub 能经 SSH 登录的每台 Linux 机器，在抽屉里点**重新安装被控端**（Reinstall agent），完成 SSH 对话框。
1. 在其他每台 Linux 机器上，用 `apt` 或 `dnf` 装 0.5.0 的被控端安装包。
1. 在每台 Windows 机器上，运行 0.5.0 的被控端 `.msi`。
1. 在每台 Mac 上，安装 0.5.0 的被控端 `.pkg`。
1. 在每个人的电脑上装 0.5.0 的客户端安装包，在每部手机上装 Android 应用。

每个被控端和客户端用原来的绑定重新连上。hub 仍然拒绝的，在**设备**或**客户端**页拿一条新链接重新加入。

## 在终端里重置

| 命令                       | 效果                                                                                |
| -------------------------- | ----------------------------------------------------------------------------------- |
| `sudo nhub reset password` | 设一个新的面板密码，登出所有会话                                                    |
| `sudo nhub unlock`         | 解除多次登录失败后的锁定，同时清掉 fail2ban 的所有 SSH 封禁                         |
| `sudo nhub reset all`      | 交还网络，把 `config/` 换回示例，删掉这台机器生成的密钥、令牌和颁发机构，再停下服务 |

`nhub reset all` 保留这台机器自己的被控端。之后只能经 SSH 登录这台机器，直到再次运行 `nhub setup`。`nhub` 的全部子命令在 [nhub 命令](../commands/nhub.md)里。
