# 设置

**设置**（Settings）页管面板自己：HTTPS，中枢名称、面板密码、语言和主题，配置的备份和恢复，以及中枢自己的更新。在终端里重置中枢的命令列在本页最后一节。

## HTTPS

面板占两个端口：HTTP 端口默认 `8080`，HTTPS 端口默认 `443`。不论 HTTPS 开没开，两个端口都提供面板，都在[网络](./network.md#面板端口)页的 **面板端口**（Panel ports）里改。HTTPS 端口的证书由中枢自己生成的证书颁发机构签发。浏览器装了这个颁发机构，打开时就没有警告。

**开启 HTTPS**（Enable HTTPS）之后，HTTP 端口把每个浏览器转到 HTTPS 地址，会话 cookie 也带上 `Secure`。每台设备都按同一个顺序做：先装颁发机构，再重启浏览器，最后开启 HTTPS。

### 安装颁发机构

开始之前，在要设置的设备上用 `http://` 地址打开面板。

1. 在 **HTTPS** 一节选择 **安装证书**（Install certificate）。浏览器下载 `neutrino-<hub>-ca.crt`，`<hub>` 是这台中枢的名称。
1. 在系统标签条里选你的系统。当前设备的系统已经选好，标着 **本机**（this device）。
1. 照标签条下面的步骤做。
1. 关掉浏览器，再重新打开。

| 系统           | 下载之后的步骤                                                                                                   |
| -------------- | ---------------------------------------------------------------------------------------------------------------- |
| Windows        | 打开文件，选「安装证书」和「本地计算机」，放进「受信任的根证书颁发机构」。                                       |
| macOS          | 打开文件，钥匙串访问把它加入登录钥匙串。双击 Neutrino 证书颁发机构，把「使用此证书时」设为「始终信任」。         |
| Linux：Chrome  | 打开 `chrome://certificate-manager`，依次选「自定义」→「受信任的证书」→「导入」，选中文件。                      |
| Linux：Firefox | 打开「设置」→「隐私与安全」→「查看证书」，在「证书颁发机构」页导入文件，勾选「信任由此证书颁发机构来标识网站」。 |
| Android        | 打开「设置」→「安全」→「加密与凭据」→「安装证书」→「CA 证书」，选择「仍然安装」，再选中文件。                    |
| iPhone 和 iPad | 在 Safari 里下载文件，在「设置」里安装描述文件，再到「通用」→「关于本机」→「证书信任设置」里打开完全信任。       |

在 macOS 上，关闭证书窗口时输入密码确认，信任设置才生效。

![钥匙串访问的信任设置，设为始终信任](/guide/os/os_mac_keychain_trust.webp)

在证书警告页上点过「继续访问」的 Chrome，导入之后仍显示「不安全」，重启浏览器之后才恢复。

### 开启 HTTPS

浏览器重启后，用 `http://` 地址打开面板。**HTTPS** 一节从 HTTPS 端口取一个测试地址，按钮左边的一行给出结果：

| 提示                                                                               | 含义                                      |
| ---------------------------------------------------------------------------------- | ----------------------------------------- |
| **这个浏览器已信任证书。**（This browser trusts the certificate.）                 | 可以选择 **开启 HTTPS**                   |
| **先安装证书并重启浏览器。**（Install the certificate, then restart the browser.） | 浏览器不认这张证书，**开启 HTTPS** 不可用 |

选择 **开启 HTTPS**，页面跳到 `https://` 地址。此后 HTTP 端口把每个浏览器都转过去。

**关闭 HTTPS**（Disable HTTPS）让页面回到 `http://` 地址，你在那里重新登录。切换时当前会话结束，此后 HTTPS 端口把每个浏览器送回 `http://`。

![HTTPS 已开启，下面是各条状态](/guide/zh/settings_https_on.webp)

证书上的名字包括机器的私有地址和虚拟网地址、`127.0.0.1`、`localhost`、主机名和 `hub.neutrino.internal`。用公网地址打开面板时，装了颁发机构也照样有警告。

### 看状态行

| 状态行                                     | 显示什么                                                       |
| ------------------------------------------ | -------------------------------------------------------------- |
| **访问地址**（Addresses）                  | 这台主机的 `http://` 和 `https://` 地址，正在用的标着 **当前** |
| **颁发机构 SHA-256**（Authority SHA-256）  | 颁发机构的指纹，用来和设备上显示的核对                         |
| **颁发机构生成于**（Authority created）    | 颁发机构生成的时间                                             |
| **证书上的名字**（Certificate names）      | 面板证书覆盖的每个地址和名字                                   |
| **证书签发于**（Certificate issued）       | 当前证书的签发时间                                             |
| **证书到期于**（Certificate expires）      | 当前证书的到期时间                                             |
| **上次自动续签**（Last automatic renewal） | 中枢上一次自己签发新证书的时间                                 |

机器的地址变了，或者离证书到期只剩 30 天时，中枢自己签发一张新证书。信任颁发机构的浏览器照样接受新证书。

### 重新生成颁发机构

**重新生成证书**（Regenerate certificate）换掉颁发机构和证书，装过旧颁发机构的浏览器都要装新的。在 `https://` 页面上这个按钮不可用，旁边写着 **先关闭 HTTPS，才能重新生成证书。**（Turn HTTPS off first to regenerate the certificate.）

1. HTTPS 开着时，选择 **关闭 HTTPS**，在 `http://` 地址上重新登录。
1. 选择 **重新生成证书** 并确认。浏览器下载新的颁发机构。
1. 照“安装颁发机构”一节装上它，再重启浏览器。
1. 选择 **开启 HTTPS**。

颁发机构存在 `config/` 里，所以恢复备份后，浏览器已经信任的那一个仍然有效。

## 中枢名称、密码、语言和主题

| 分节                           | 字段                                                                                                 | 按钮                            |
| ------------------------------ | ---------------------------------------------------------------------------------------------------- | ------------------------------- |
| **中枢名称**（Hub name）       | **名称**（Name），已加入的客户端用它显示这台中枢                                                     | **应用名称**（Apply name）      |
| **面板密码**（Panel password） | **当前密码**（Current password）、**新密码**（New password）、**确认新密码**（Confirm new password） | **修改密码**（Change password） |
| **语言**（Language）           | **语言**，面板显示用的语言                                                                           | **应用语言**（Apply language）  |
| **外观**（Appearance）         | **主题**（Theme）：**跟随系统**（System）、**深色**（Dark）或 **浅色**（Light）                      | **应用主题**（Apply theme）     |

改密码之后，其他会话保持登录。主题跟随系统时，配色取自浏览器。桌面客户端有自己的语言和主题设置。

## 备份配置

在 **配置存档**（Configuration archive）一节选择 **下载备份**（Download backup），浏览器保存一个 `.tar.gz`，里面是整个 `config/`。

存档里的凭据用保险库主口令封存，其余内容谁拿到文件都能读。存档里只有配置。共享里的文件、Gitea 仓库、容器的卷和 ZFS 数据集都留在各自的机器上。

## 恢复备份

1. 在 **配置存档** 一节选择 **从文件恢复**（Restore from file），选中存档。
1. 在对话框的 **保险库口令**（Vault passphrase）里，填这份备份封存时的保险库主口令。
1. 选择 **恢复**（Restore）。

存档里的文件替换 `config/` 下的每个文件，中枢随即应用，面板重启。页面提示面板正在重启，用恢复后的密码登录。

| 中枢返回                  | 原因                                                 |
| ------------------------- | ---------------------------------------------------- |
| `backup_wrong_extension`  | 文件不是面板导出的备份                               |
| `backup_corrupt`          | 存档已损坏                                           |
| `vault_passphrase_wrong`  | 口令打不开这份备份                                   |
| `backup_mode_unavailable` | 备份里的形态本中枢不提供，例如国内版没有旁路网关形态 |

出现这几个码时，中枢什么都不恢复。文件已经恢复、应用却没完成时，对话框写出原因。处理好原因，再在终端里运行 `sudo nhub apply`。

被控端和客户端自己重新连上。恢复到另一台机器时，每个 AI 订阅账号要重新登录一次，因为这些登录存在 `config/` 之外。

## 更新中枢

**更新**（Update）一节把中枢升级到更新的发行版本，装在它运行的这台机器上。

1. 在 **更新** 一节选择 **检查更新**（Check for updates）。这一节列出最新版本的日期、大小、**发行说明**（Release notes），以及安装要占的磁盘空间和剩余空间。
1. 选择 **安装**（Install）加版本号的按钮，再确认。

![更新一节显示有更新的发行版本](/guide/zh/settings_update.webp)

面板下载安装包，按发行版本的 `SHA256SUMS` 核对，然后由 systemd 单元 `neutrino_hub_update` 在面板之外安装。页面回到登录页，登录后这一节写出旧版本、新版本和更新日期。

安装后最多三分钟里，这个单元检查面板是否应答、路由服务是否在运行。检查没通过时，单元装回上一个版本，这一节写出原因，并给出 **安装日志**（Install log）。没有可以装回的旧安装包时，确认框事先写明。

机器可用内存不到 300 MB 时，单元在解包前先停下面板和 AI 网关，装完再启动它们。检查通过后，单元从新中枢重装中枢所在机器上的被控端。其他机器上的被控端，只要新中枢仍接纳它们的协议，就从新中枢自行更新。

新的大版本不从这里安装，这一节只写明它是新的大版本。从源码检出运行的中枢也不从这里更新，要用 git 更新。

在终端里，`sudo nhub update` 做同样的事，安装前先问你确认。`--yes` 跳过确认，`--package` 安装你自己下载的安装包文件。单元的日志用 `journalctl -u neutrino_hub_update` 查看。

## 从 0.4 过来

0.5.0 不能原地升级 0.4.0 的中枢，0.4 的备份也不能恢复到 0.5.0。

1. 在 0.4.0 的中枢所在机器上，删掉 0.4.0 的中枢安装包。
1. 全新安装 0.5.0 的中枢，步骤在[安装中枢](../install/hub.md)。
1. 运行 `sudo nhub setup`，走完初始化向导。

0.3 和 0.4 的被控端和客户端连上来时，中枢返回 `protocol_too_old`，意思是对方的协议版本低于中枢接纳的范围。在每台机器上装 0.5.0 的被控端或客户端，再用一条新链接加入。被控端的步骤在[安装被控端](../install/agent.md)，客户端的步骤在安装客户端那一页。

## 在终端里重置

下面的命令在中枢所在的机器上运行。每条 `reset` 先问一句 `[y/N]`，回答 `y` 才执行；加 `--yes` 跳过这一问。

| 命令                       | 效果                                                                                |
| -------------------------- | ----------------------------------------------------------------------------------- |
| `sudo nhub reset password` | 设一个新的面板密码，登出所有会话                                                    |
| `sudo nhub unlock`         | 解除多次登录失败后的锁定，同时清掉 fail2ban 的所有 SSH 封禁                         |
| `sudo nhub reset network`  | 交还机器的网络（防火墙、引擎、解析器），停下面板，`config/` 不变                    |
| `sudo nhub reset all`      | 交还网络，把 `config/` 换回示例，删掉这台机器生成的密钥、令牌和颁发机构，再停下服务 |

`nhub reset all` 之后，中枢所在机器上的被控端还在。在再次运行 `nhub setup` 之前，只能经 SSH 登录这台机器。
