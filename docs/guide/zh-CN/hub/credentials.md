# 凭据

**凭据**（Credentials）页替你保管 SSH 密钥、登录信息和令牌，别的页面从这里引用，不用再粘贴一次。

## 三类

![凭据页](/guide/zh/credentials.webp)

| 类型                     | 内容                                  | 添加按钮                      |
| ------------------------ | ------------------------------------- | ----------------------------- |
| **SSH 密钥**（SSH keys） | 一把私钥，加密的私钥另填 **密钥口令** | **添加密钥**（Add key）       |
| **登录信息**（Logins）   | 一对用户名和密码，或者只有一个密码    | **添加登录信息**（Add login） |
| **令牌**（Tokens）       | 一个带名字的秘密值                    | **添加令牌**（Add token）     |

每一类只写不读。保存后页面显示名称、类型和添加时间，值不再显示；要换就删掉重加。每行写着这份凭据在几台设备、几个节点或几个提供方上使用；删除时确认框列出这些使用者。SSH 密钥要粘贴私钥，即不带 `.pub` 后缀的那个文件；粘贴公钥时 hub 拒绝。

## 谁用它们

| 用处                              | 用哪一类                                 |
| --------------------------------- | ---------------------------------------- |
| [设备](./devices.md)页的 SSH 安装 | SSH 密钥或登录信息，加 sudo 用的登录信息 |
| [代理](./proxy.md)页的出口节点    | 令牌                                     |
| [AI](./ai.md) 页的提供方          | 令牌，作为提供方的 API 密钥              |

在那些页面的下拉框里选已保存的凭据。

## 保险库

保险库的主口令在初始化第二屏设定。hub 生成一把数据密钥，用主口令封存；每份凭据的值、名字和类型都用数据密钥加密后写进 `config/credentials/vault.json`。配置存档里带的是这份密文，恢复时要输主口令才能打开。

## 换口令与丢口令

换主口令在 hub 这台机器上运行：

```bash
sudo nhub vault rekey
```

它把数据密钥重新封存在新口令下，已加密的内容不变；之前下载的存档仍然用当时的旧口令打开。主口令丢失时，保险库里的内容再也打不开，每份凭据和每个 AI 账号都要重新录入。
