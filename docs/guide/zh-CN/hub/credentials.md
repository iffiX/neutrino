# 凭据

**凭据**（Credentials）页把 SSH 密钥、登录信息和令牌存进中枢的保险库，每样只存一次。别的页面要登录什么，就从列表里选一份存好的凭据。

![凭据页上的 SSH 密钥、登录信息和令牌](/guide/zh/credentials.webp)

## 密钥、登录信息和令牌

| 分节                     | 一份凭据里有什么                   | 添加按钮                      |
| ------------------------ | ---------------------------------- | ----------------------------- |
| **SSH 密钥**（SSH keys） | 一把私钥；私钥加密时再加它的口令   | **添加密钥**（Add key）       |
| **登录信息**（Logins）   | 一对用户名和密码，或者只有一个密码 | **添加登录信息**（Add login） |
| **令牌**（Tokens）       | 一个带名字的秘密值                 | **添加令牌**（Add token）     |

添加一份凭据：

1. 点**添加密钥**、**添加登录信息**或**添加令牌**。
1. 填**名称**（Name）和值：**私钥**（Private key）、**用户名**（Username）和**密码**（Password），或者**值**（Value）。
1. 私钥加密时，填**密钥口令**（Key passphrase）。
1. 点**保存密钥**（Save key）、**保存登录信息**（Save login）或**保存令牌**（Save token）。

私钥要整段粘贴，包括 BEGIN 和 END 两行。粘贴公钥时，中枢返回 `key_is_public`；加密的私钥没填口令时，返回 `key_passphrase_needed`。保存之后，页面只显示名称、添加时间和使用情况，值不再显示。要换值，就删掉这一份再重新添加。

## 谁在用

| 用在哪里                      | 选哪一类                                   |
| ----------------------------- | ------------------------------------------ |
| **设备**页的**安装被控端**    | SSH 密钥或登录信息，外加 sudo 用的登录信息 |
| Windows 机器上的 VS Code 实例 | 实例所用账户的 Windows 登录信息            |
| **AI** 页的提供方             | 令牌，作为提供方的 API 密钥                |
| **代理**页的出口节点          | 令牌，节点链接里带令牌时才用               |

Windows 用账户的用户名和密码启动 VS Code 实例，所以 Windows 上的实例要选一份登录信息。Windows 拒绝这份登录信息时，实例报告 `credential_invalid`；更新存好的登录信息，再应用一次。实例的设置见 [VS Code](../agent/modules/vscode.md)。

每一行写着有几处在用，例如 **2 台设备**或 **1 个提供方**。点**删除**（Delete）时，确认框列出同样的数目。设备或提供方失去凭据后，要换一份新的；出口节点失去令牌后会停用。

## 保险库

所有值都在 `config/credentials/vault.json` 里。一把数据密钥加密这些值，连同名称和类型一起加密。数据密钥本身用主口令封存，主口令在 `nhub setup` 时设定。`config/` 的备份里只有密文，恢复时要输入备份当时的主口令。

中枢这台机器在 `config/` 之外留着数据密钥的一份工作副本，所以中枢读保险库时不需要主口令。缺了这份副本，保险库处于锁定状态，用到凭据的操作都返回 `vault_locked`。

## 更换主口令

在中枢这台机器上运行下面的命令，新口令输入两遍：

```bash
sudo nhub vault rekey
```

命令用新口令重新封存同一把数据密钥，已加密的内容不动。加 `--stdin` 时，从标准输入读新口令。换口令之前做的备份，仍然用当时的旧口令打开。

## 丢了主口令

正在运行的中枢不需要主口令，所以旧口令丢了也能用 `sudo nhub vault rekey` 设一个新的。换完之后，重新备份一次 `config/`。

::: warning
备份只能用当时的主口令打开。那个口令丢了，备份里的密钥、登录信息和令牌就再也打不开，恢复后要逐个重新录入。
:::
