# 网络

**网络**（Network）页决定中枢所在的机器在你的网络里扮演什么角色。在这一页上，你选形态、给网口定角色、设置 DHCP 和无线，也设定机器在哪些网络上应答。每一节有自己的应用栏，只应用这一节显示的内容。

| 节                                  | 出现在               | 设置什么                       |
| ----------------------------------- | -------------------- | ------------------------------ |
| **模式**（Mode）                    | 所有形态             | 机器的形态                     |
| **上游网关**（Upstream gateway）    | 旁路网关             | 转发的流量送往哪台路由器       |
| **拓扑**（Topology）                | 路由器               | 网口和网口上设备的示意图       |
| 网口标签页                          | 路由器               | 每个网口的角色和地址           |
| **静态地址分配**（Fixed addresses） | 路由器，有 LAN 时    | 总拿到同一个地址的设备         |
| **已知网络**（Known networks）      | 路由器，有无线网卡时 | WAN 无线网卡加入的网络         |
| **路由行为**（Routing behavior）    | 路由器               | 多条上行和多个服务网络怎么配合 |
| **开放范围**（Exposure）            | 所有形态             | 机器在哪些网络上接受连接       |
| **面板端口**（Panel ports）         | 所有形态             | 面板的 HTTP 端口和 HTTPS 端口  |

macOS 和 Windows 上的中枢只有服务器形态。那里的网络页只有模式、开放范围和面板端口三节。

## 选择形态

![模式一节的三种形态](/guide/zh/network_modes.webp)

| 形态                         | 做什么                             | 机器上的地址 |
| ---------------------------- | ---------------------------------- | ------------ |
| **服务器**（Server）         | 不做路由，在它所连的网络上提供服务 | 保持机器原样 |
| **旁路网关**（Side gateway） | 为把它设为网关的主机转发流量       | 保持机器原样 |
| **路由器**（Router）         | 在上行网口和它服务的网络之间路由   | 由中枢接管   |

初始化向导里还有单臂路由：一根有线主干，不打标签出网，带 VLAN 标签服务内网。面板把它存成 **路由器**，主干的角色是 **拆分**（Split）。

换形态：

1. 在 **模式** 里选一个形态。当前形态带 **使用中**（active）标记。
1. 选择 **应用模式**（Apply mode）。

应用栏在应用之前写出这次切换的代价。进入路由器形态时，中枢接管网口。DHCP 上行可能换到新地址，你的会话要在新地址上重新打开。离开路由器形态时，网口交还给机器自己的网络管理器。服务网络随之结束，上面的设备失去 DHCP、DNS 和网关。离开旁路网关时，把这台机器设为网关的主机失去出网的路。

从服务器切到路由器时，每个网口的开放设置保留，角色清空。路由器形态下，开放的网口不能是 **停用**（Disabled）角色。所以选中路由器之后、应用模式之前，给每个开放的网口选一个不是停用的角色。

## 上游网关

旁路网关形态下，设备把这台机器设为网关就走代理，网络原来的路由器照旧发放租约。**上游网关** 填那台路由器的地址，机器把转发的流量送到那里。选择 **应用上游网关**（Apply upstream gateway），中枢重写默认路由并重载防火墙。

## 接口角色

路由器形态下，每个网口一个标签页，**角色**（Role）四选一：

| 角色                 | 含义                 |
| -------------------- | -------------------- |
| **WAN**              | 通往互联网的上行线路 |
| **LAN**              | 网关自己服务的网络   |
| **拆分**（Split）    | 切成多个 VLAN 的主干 |
| **停用**（Disabled） | 交给系统自己管理     |

WAN 网口用 **DHCP** 从上游取地址，或用 **静态**（Static）手填 **地址**（Address）、**前缀长度**（Prefix length）和 **网关**（Gateway）。DHCP 上行的表单下方列出租约给出的解析器。静态上行在网关下方有 **DNS** 列表，每行一个地址或 `<address>:<port>`。列表空着时，下方写着 **使用内置解析器 223.5.5.5、119.29.29.29**（Built-in resolvers: 223.5.5.5, 119.29.29.29）。

**优先级**（Priority）决定多条上行的先后：

| 档位                                | 含义                     |
| ----------------------------------- | ------------------------ |
| **自动**（Automatic）               | 由网关自己排序           |
| **优先使用这条**（Prefer this one） | 固定排在最前             |
| **仅作备用**（Backup only）         | 没有其他上行线路时才使用 |

LAN 网口填 **网关地址**（Gateway address）和 **前缀长度**。第一个服务网络默认是 `192.168.8.0/24`，机器在 `192.168.8.1`。改完一个标签页，选择 **应用到**（Apply to）加网口名的按钮。

**拆分** 主干上，不打标签的流量走主网口。每个 VLAN 号在 **VLAN** 一栏里加成一个网口，应用之后各有自己的标签页。

**路由行为** 有两个开关，作用于整台网关：

- **把流量分摊到多条上行线路**（Spread traffic across uplinks）把新连接分到不同的上游线路上。
- **网络之间可以互通**（Networks reach each other）让一个服务网络里的设备访问另一个服务网络。

选择 **应用路由行为**（Apply routing behavior），中枢重载防火墙并重建上行路由。

## DHCP 与 DNS

在每个服务网络上，机器把自己在这个网络上的地址作为网关和解析器发给设备。LAN 标签页的 **DHCP** 一栏有这些项：

| 项                                                           | 含义                                             |
| ------------------------------------------------------------ | ------------------------------------------------ |
| **在这个网络上分配地址**（Allocate address on this network） | 这个网络是否发放地址                             |
| **起始地址**（Range start）、**结束地址**（Range end）       | 地址池，默认 `.100` 到 `.200`；网关地址在池外    |
| **租约时长**（Lease time）                                   | 写成 `12h`、`30m` 或 `1d` 这样的时长；默认 `12h` |

DHCP 关着时，机器照样在每个服务网络上应答 DNS。在每个服务网络上，`hub.neutrino.internal` 都解析到机器在这个网络上的地址。服务器形态不服务任何网络，不发地址，也不替别的设备解析。

解析分两层。服务网络的设备问机器，机器再问上行线路的解析器。DHCP 上行用租约给出的，静态上行用自己的 **DNS** 行；有多条上行时，按优先级排列。没有一条上行给出解析器时，机器用内置的 `223.5.5.5` 和 `119.29.29.29`。[代理](./proxy.md)页的两个解析器列表只管走代理的那部分域名。

**静态地址分配** 把一个 MAC 绑到一个固定地址：

1. 在 **静态地址分配** 里选择 **添加**（Add address）。
1. 填 **MAC 地址**（MAC address），或从已发现的设备里选一个。
1. 填 **地址**，需要时再填 **名字**（Name）。
1. 选择 **应用静态地址分配**（Apply fixed addresses）。

地址要在某个发放地址的网络里，可以在地址池之外。已经拿到动态地址的设备，下次续租时换到固定地址。填了名字的设备，在每个服务网络上都能按名字解析。

## 无线

WAN 角色的无线网卡加入一个网络，LAN 角色的无线网卡发布一个网络。

要加入网络，在无线网卡的标签页里选择 **扫描网络**（Scan for networks）。选中网络，填密码，再选择 **加入**（Join）。加入会把这个网口设为 WAN。**已知网络** 列出 WAN 无线网卡会加入的网络，靠前的优先。标着 **需要密码**（needs a passphrase）的条目，中枢读不到它的密钥。在扫描结果里选中它，再输一次密码。**忘记**（Forget）删掉一个网络的密码。

LAN 无线网卡有 **接入点**（Access point）一栏：

| 字段                         | 写法                                        |
| ---------------------------- | ------------------------------------------- |
| **网络名称**（Network name） | 这块网卡发布的网络名                        |
| **密码**（Passphrase）       | 8 到 63 个字符，仅支持 WPA2                 |
| **国家代码**（Country code） | 两个大写字母，ISO 3166-1 国家代码，可以留空 |
| **频段**（Band）             | 2.4 GHz 或 5 GHz                            |

5 GHz 能用哪些信道、用多大功率，由所在国家的法规定。所以只有填了国家代码，**频段** 里才出现 5 GHz；不填就只用 2.4 GHz。国家代码格式不对时，字段下方写着 「两个字母，例如 CN。5 GHz 需要国家代码。」应用时，中枢把系统的无线管制区设成这个国家，并写进 hostapd 的配置。不经面板、直接请求 5 GHz 而不带国家代码时，中枢拒绝并返回 `network_invalid`，字段是 `country_code`。

没有接入点模式的网卡不能设为 LAN。

## 开放范围

**开放范围** 列出机器接受连接的网络，连接的对象是机器自己的服务，例如面板、SSH、DNS 和共享。每个开着的虚拟网也占一行，标着 **虚拟网**（overlay）。SOCKS 端口和虚拟网的对端端口，在同样的网络上可达。

1. 在 **开放范围** 里勾选机器要应答的网络。
1. 选择 **应用开放范围**（Apply exposure）。页面写着 **已应用。**（Applied.）

![开放范围一节](/guide/zh/network_exposure.webp)

应用之前，应用栏写出每一种损失。开放一条上行线路，机器在它监听的每个端口上接受来自互联网的连接。取消勾选一个网络，这个网络就连不到机器，警告里写着有几台设备正经它连着中枢。机器在网络之间转发的流量不受影响。

Linux 上，装好之后才插上的网卡标着 **新网口，打开并应用后才使用**（New, not in use until turned on and applied）。在开放范围里勾选它并应用之前，它不开放。macOS 和 Windows 上，系统新加的网卡直接算开放，要在这一节里关掉。

路由器形态下，开放一个角色为 **停用** 的网口时，同一行出现角色选择。可选 WAN，有线网口还可选 LAN。**应用开放范围** 把角色和开放设置一起写入。一个网口开放而角色是停用时，中枢拒绝并返回 `network_invalid`，页面显示 **{name} 的角色是停用，不能开放。**（{name} cannot answer with the role Disabled.），其中 {name} 是网口名。

## 面板端口

面板在每个开放的网口上占两个 TCP 端口。**HTTP 端口**（HTTP port）默认 `8080`，**HTTPS 端口**（HTTPS port）默认 `443`；初始化时选过别的，就用选过的。不论 HTTPS 开没开，两个端口都提供面板。每个字段下方写着这个端口当前的访问地址。

1. 在 **面板端口** 里改 **HTTP 端口**、**HTTPS 端口**，或者两个都改。两个端口不能相同。
1. 选择 **应用面板端口**（Apply panel port）。

面板在新端口上重启。页面写着 **正在迁移到**（Moving to）加新地址，协议和你当前用的一样，到那里重新登录。从你这里访问不到新地址时，页面写着那个地址 **没有应答**（No answer at）。HTTP 端口是否把浏览器转到 HTTPS，在[设置](./settings.md#https)页切换。
