# 网络

**网络**（Network）页决定这台机器是哪种形态、每个网口扮演什么角色、面板从哪些网络可达。页面自上而下的各节：

- **模式**（Mode）
- **拓扑**（Topology）
- 接口列表
- **上游网关**（Upstream gateway）
- **路由行为**（Routing behavior）
- **已知网络**（Known networks）
- **开放范围**（Exposure）
- **面板端口**（Panel port）

每一节有自己的应用按钮，只改这一节的内容。

## 三种形态加单臂

![模式一节](/guide/zh/network_modes.webp)

| 形态                         | 做什么                                                 | 动不动机器上的地址 |
| ---------------------------- | ------------------------------------------------------ | ------------------ |
| **服务器**（Server）         | 不做路由，在收到请求的网口上应答                       | 不动               |
| **旁路网关**（Side gateway） | 为把它设为网关的主机转发流量                           | 不动               |
| **路由器**（Router）         | 在上行网口和它服务的网络之间路由                       | 接管               |
| 单臂路由                     | 路由器的一种：一根网线，不带标签出网，带 VLAN 标签入内 | 接管               |

单臂路由只在初始化向导里出现，面板把它存为路由器，网口角色是 **拆分**（split）。旁路网关下，你在要走 hub 的设备上把默认网关改成这台机器；网络原来的路由器继续发租约。

![向导里的形态屏](/guide/zh/setup_shape.webp)

## 接口角色

接口列表里每个网口一个标签页，**角色**（Role）四选一。

| 角色                 | 含义                 | 地址怎么来                                             |
| -------------------- | -------------------- | ------------------------------------------------------ |
| **WAN**              | 通往互联网的上行线路 | **DHCP** 从上游取，或 **静态**（Static）手填地址和网关 |
| **LAN**              | 网关自己服务的网络   | 手填这台机器的地址和前缀长度                           |
| **拆分**（split）    | 切成多个 VLAN 的主干 | 不打标签的流量走主接口，每个 VLAN 是独立的接口         |
| **停用**（Disabled） | 不作任何处理         | 保持机器原样                                           |

改完一个网口，点 **应用到**（Apply to）按钮，按钮名后面跟着这个网口的名字。hub 重新配置这个接口，然后重载防火墙和 DHCP。拆分主干上用 **VLAN** 一栏添加子接口，应用之后每个 VLAN 出现在自己的标签页里。有两条上行线路时，在 **路由行为** 里勾选 **把流量分摊到多条上行线路**（Spread traffic across uplinks），连接就分摊到两条线路上。

## DHCP 与 DNS

每个 LAN 角色的网口有一段 **DHCP** 设置：

- **在这个网络上分配地址**（Allocate address on this network）决定这个网络是否发放租约。
- **起始地址**（Range start）和 **结束地址**（Range end）圈出地址池，网关自己的地址在池外。默认池是 `.100` 到 `.200`，低位留给固定地址的主机。
- **租约时长**（Lease time）用 dnsmasq 的写法，例如 `12h`、`30m`、`1d`。

不论 DHCP 开不开，hub 都在这个网络上应答 DNS。**总览**（Dashboard）页的 **DNS 查询**（DNS queries）列出最近的解析。

## 无线

无线网卡能扮演两种角色。作为 WAN，它加入一个现有的 Wi-Fi：在网口的标签页里点 **扫描网络**（Scan for networks），选一个，填密码，点 **加入**（Join）；加入会把这个接口设为 WAN。LAN 角色的无线网卡则发布一个接入点，填 **网络名称**（Network name）和 **密码**（Passphrase）即可；只支持 WPA2，密码 8～63 个字符。

**已知网络**（Known networks）列出记住的 Wi-Fi。WAN 角色的无线网卡从中挑一个能看到的加入，列表靠前的优先。密钥有两个来源：hub 初始化时读自这台机器原有的配置，或者你在扫描结果里输入。条目写着 **需要密码**（needs a passphrase）时，hub 读不到这个网络的密钥；在扫描结果里选中这个网络，再输一次密码。**忘记**（Forget）删掉密码，网卡不再加入这个网络。

## 暴露与面板端口

![开放范围一节](/guide/zh/network_exposure.webp)

**开放范围**（Exposure）决定这台机器在哪些网络上接受对自身服务的连接：面板、SSH、DNS、共享。勾选网络，点 **应用开放范围**（Apply exposure），hub 重载防火墙的 input 链。虚拟网算一个网络，hub 是否在虚拟网上应答也在这里决定。

**面板端口**（Panel port）是面板在所有开放接口上监听的 TCP 端口，默认 8080。改完点 **应用面板端口**（Apply panel port），面板服务重启，浏览器跟着跳到新地址。跳不过去时，页面写出新地址，从能访问的地方重新打开。

## 换形态

形态在面板里只能在三种之间切换，改的是接口角色。要把机器退回初始化之前重新选，在这台机器上运行：

```bash
sudo nhub reset all
```

它先交还网络，再把 `config/` 换回示例，删掉这台机器收集的每一把密钥和令牌，停下服务；`/etc/neutrino/agent` 保留。重置不从任何网口上摘地址，所以发出这条命令的会话不会断。之后运行 `sudo nhub setup` 重新回答六屏问题。

::: warning
`nhub reset all` 删掉这台机器收集的每一把密钥和令牌，AI 账号的登录也一起消失。先在[设置](./settings.md)页下载一份配置存档。
:::
