# 模块

**模块**（Modules）页管一台被控端机器上的模块：文件共享、git 服务器、容器和 ZFS 存储。安装、启动、停止和配置都在这一页做。页面下方的内容属于顶部选中的那台机器，每一次操作都经由它的被控端到达机器。

开始之前，这台机器要装好被控端并保持在线。机器离线时，页面写着 **被控端已离线**（The agent is offline），按钮都点不了。

## 选择机器和模块

1. 在 **选择机器**（Which machine）里选一台机器。
1. 在 **这台机器上的模块**（Modules on this machine）里选一个标签。

标签上有模块名、一个圆点，还有一个词，说明这个模块在那台机器上处于什么状态。四个标签是 **File share**、**Gitea**、**Containers** 和 **ZFS storage**，名字取自模块清单，中文界面上也显示英文。

标签行末尾的 `+` 打开 **显示的模块**（Shown modules）。在里面打勾添加一个标签，取消打勾移除它，只对这台机器生效。没有勾选记录的机器，显示被控端上报过的每个模块；一个标签都没有时，这一行写着 **还没有模块标签；用 + 添加。**

## 状态词的含义

| 词             | 这台机器                           |
| -------------- | ---------------------------------- |
| 未安装         | 没有这个模块的软件                 |
| 已安装         | 装着软件，hub 从没配置过它         |
| 已停止         | 已应用 hub 的配置，服务停着        |
| 运行中         | 已应用 hub 的配置，服务运行着      |
| 安装中、卸载中 | 正在做这一步                       |
| 失败           | 上报了上一步失败，原因写在标签下面 |
| 不支持         | 上面的被控端没有这个模块的代码     |
| 未上报         | 没有说过这个模块的任何情况         |

机器加入时，文件共享或容器引擎上已经在提供的东西立刻收为 hub 的配置，标签读作 **运行中** 或 **已停止**。手工装上但没有东西可收的软件读作 **已安装**（installed），点 **配置**（Configure）之前，这一页不动机器上的任何东西。

## 安装、启动和停止

| 按钮 | 机器上发生什么               | 标签是这些词时可点              |
| ---- | ---------------------------- | ------------------------------- |
| 安装 | 装上软件包，不写任何配置     | 未安装、失败                    |
| 启动 | 装上软件包，应用配置，起服务 | 已安装、已停止                  |
| 停止 | 应用配置，停服务             | 运行中，或服务正在运行的 已安装 |
| 卸载 | 移除软件包和 hub 写下的配置  | 已安装、已停止、运行中、失败    |

安装和卸载的输出逐行出现在标签下面的 **输出**（Output）里，旁边的圆点写着 **运行中**、**已完成** 或 **失败**。发行版没有对应当前内核的预编译模块时，ZFS 的安装会现场编译一个内核模块，要花几分钟，过程也在这里打印。模块没有适合这台机器平台的构建时，hub 返回 `no_platform_build`。

## 卸载

**卸载**（Uninstall）弹出一个确认框，写明模块和机器。确认之前，机器上什么都不动。

::: warning
软件包会移除，hub 写下的配置会删除。存储池、共享目录、仓库和容器卷留在机器上。
:::

## 配置

**配置**（Configure）在标签下面展开这个模块自己的分区，标签随之变成 运行中：hub 的配置应用到机器上，服务启动。标签是 已安装、已停止 或 运行中 时这个按钮可点。

hub 手上还没有这个模块的配置时，第一次点 **配置** 会把机器上现成的东西收为 hub 的配置，所以第一次下发不改动机器：

| 标签        | 第一次 **配置** 收下什么                                   |
| ----------- | ---------------------------------------------------------- |
| File share  | 机器上已有的共享和用户账号                                 |
| Containers  | 机器上已有的容器，连同镜像、端口、卷和环境变量，以及镜像源 |
| Gitea       | 不收；hub 只管自己装的那个实例                             |
| ZFS storage | 不收；没有一份需要下发的池清单                             |

从此 hub 手上这份配置是唯一依据，每次应用都把整份配置重新写到机器上。

| 标签        | 里面的分区                   | 页面                    |
| ----------- | ---------------------------- | ----------------------- |

| Gitea       | 接入、管理员                 | [Gitea](./gitea.md)     |
| Containers  | 声明的容器、正在运行、镜像源 | [容器](./containers.md) |
