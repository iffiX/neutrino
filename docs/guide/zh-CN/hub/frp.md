# SakuraFrp 和 OpenFrp

两家第三方服务商 SakuraFrp (natfrp.com) 和 OpenFrp (openfrp.net) 在公网地址上运行 frp 节点。在其中一家建一条 TCP 隧道，它的一个节点就替中枢的连接端口开出一个公网端口。每个中枢安装包都带着 frp 的客户端 frpc，它连上节点，把公网端口上的每个连接转给中枢。

家里没有公网 IPv4 或 IPv6 地址、手上也没有自己的 VPS 时，用这种办法。它和别的办法怎么选，见[选哪种外部访问](../scenarios/choose_a_way_in.md)。

TLS 从客户端一直通到中枢，客户端照样核对中枢证书的指纹，和别的外部访问一样。节点只转发加密后的连接。连接经过节点时，速度上限是服务商给你账户的带宽。

## 在服务商那里准备账户

在 SakuraFrp 或 OpenFrp 的网站上：

1. 注册一个账户。
1. 完成服务商的实名认证。SakuraFrp 的实名认证收 1 元。

SakuraFrp 的免费账户有 10 Mibps 带宽，每月 5 GiB 流量，每天在它的网站上签到还能多得流量。签到由你自己去做。OpenFrp 免费账户的额度，见 OpenFrp 的网站。

## 在服务商那里建隧道

中枢只列出本地端口等于中枢连接端口的 TCP 隧道，所以本地端口就是这条隧道归中枢用的记号。frpc 自己连的是中枢在 `127.0.0.1` 上的一个端口：SakuraFrp 是 18443，OpenFrp 是 18444。这个端口和连接端口提供同一个通道。

下面这些隧道也不出现在列表里：

- OpenFrp 上开着自动 TLS 的隧道。节点在自己那里解开 TLS，换上自己的证书，每个客户端都拒绝这张证书。
- SakuraFrp 上开了强制访问认证的节点上的隧道。这种节点上的访客得先在浏览器里通过认证。

先在[网络](./network.md#端口)页的 **端口** 一节看好 **连接端口**，默认 8443，然后：

1. 在服务商的控制台里新建一条 TCP 隧道。
1. 把本地端口设成中枢的连接端口。
1. 在 OpenFrp 上，关掉自动 TLS。
1. 选一个节点，保存隧道。

本地 IP 保持控制台填的值就行，frpc 在中枢上连的是中枢自己的回环端口。

## 让中枢登录

登录之前，在[外部访问](./overlay.md)页打开 **SakuraFrp** 或 **OpenFrp** 卡片的 **启用** 开关，选择 **应用外部访问**，再选中这张卡片本身。卡片下方出现它的设置：**状态** 和 **账户**，登录之后还有 **隧道**。

### SakuraFrp

1. 从 SakuraFrp 的管理面板复制你的访问密钥。
1. 粘到 **账户** 里的 **访问密钥**。
1. 选择 **保存访问密钥**。

中枢先向 SakuraFrp 核对密钥，SakuraFrp 认可了才保存。之后 **状态** 写着 **已启用，未连接**。

### OpenFrp

1. 在 **账户** 里选择 **登录**。浏览器新开一个标签页，打开 OpenFrp 的登录页。
1. 在这个标签页里登录 OpenFrp，5 分钟内确认这次登录。

等你确认期间，面板上写着 **到 OpenFrp 的页面上确认登录。**，中枢每 5 秒向 OpenFrp 查一次结果。标签页关掉了，就选 **重新打开登录页**。登录成功后，**登录** 换成 **退出登录**。

OpenFrp 的登录有效期最长 30 天。过期后，这一节写着 **登录已过期。隧道照常运行，要换隧道得重新登录。**

访问密钥和 OpenFrp 的登录凭据存在 `config/overlay/` 下，用保险库的数据密钥封存，配置备份里也有它们。

## 选一条隧道

**隧道** 列出账户里中枢能用的隧道，一条一行。每行写着节点名、节点所在地区，以及中枢到节点的延迟。地区一栏，OpenFrp 的写 **中国大陆**、**港澳台** 或 **海外**，SakuraFrp 的写 **中国大陆** 或 **中国大陆以外**。3 秒内连不上的节点，延迟一栏空着。

1. 在 **隧道** 里选中一行。
1. 选择 **应用隧道**。

中枢向服务商取来这条隧道的配置，在中枢上写好 frpc 的文件，文件里有账户的令牌。**状态** 先是 **连接中**，一分钟内变成 **已连上**。**节点** 写着隧道所在的节点；**客户端连接地址** 是一个 `https://` 地址，由节点的主机名和隧道的公网端口组成。

打开这一节和选择 **刷新** 时，中枢重新读一次列表。列表为空时写着 **没有本地端口为 8443 的 TCP 隧道。到 SakuraFrp 建一条。**，端口和服务商按你的实际情况显示，旁边的按钮打开服务商的控制台。在那里建好隧道，再选择 **刷新**。

中枢只在这些时候访问服务商：你在 **外部访问** 页上操作时，以及所选隧道的 frpc 文件不在时。关掉卡片会删掉这个文件，备份里也没有它，所以重新打开卡片或恢复备份之后，中枢再取一次配置。

## 看懂状态

frpc 启动 5 秒后，中枢自己去连这个公网地址，之后每分钟连一次。那个地址上应答的是中枢自己的证书时，**状态** 才是 **已连上**。状态下方写着 frpc 输出的最后一行，或者检查没通过的原因。

| 状态                     | 含义                                                                           |
| ------------------------ | ------------------------------------------------------------------------------ |
| **已关闭**               | 卡片关着                                                                       |
| **未登录**               | 没存访问密钥，也没有 OpenFrp 的登录凭据                                        |
| **保险库已锁定**         | 中枢打不开存着的密钥或登录凭据                                                 |
| **已启用，未连接**       | 已经登录，还没选隧道                                                           |
| **本机端口已有程序在用** | 别的程序占着中枢给这家服务商留的回环端口：SakuraFrp 是 18443，OpenFrp 是 18444 |
| **取不到隧道配置**       | 中枢上没有所选隧道的 frpc 文件，服务商也没给出这条隧道的配置                   |
| **连接中**               | frpc 在运行，第一次检查还没做完                                                |
| **已连上**               | 公网地址上应答的是中枢自己的证书                                               |
| **节点拒绝了隧道**       | 节点拒绝这条隧道，例如公网端口已有人用，或隧道在服务商那里关了                 |
| **对外端口不通**         | frpc 在运行，公网地址却没有应答，或应答的是别的证书                            |
| **节点登录失败**         | 节点拒绝这个账户的令牌                                                         |
| **连不上节点**           | frpc 没连上节点就退出了，或者和节点的连接断了                                  |

Linux 上 frpc 是单元 `neutrino_hub_sakurafrp` 或 `neutrino_hub_openfrp`，macOS 和 Windows 上它在中枢的服务里运行。Linux 上 frpc 停下 10 秒后重新启动。状态不是 **已连上** 时怎么处理，见[故障排查](../reference/troubleshooting.md#外部访问)。

## 客户端看到什么

选好隧道以后，不管状态如何，新的客户端链接里都带着隧道的地址。已加入的客户端和被控端随中枢下一次发来的状态拿到这个地址，不用重新加入。地址列表里先是中枢自己的地址，然后是 SakuraFrp 的、OpenFrp 的，最后是 SSH 中继的。

客户端经隧道连着时，中枢一行写着 **已连接 · SakuraFrp** 或 **已连接 · OpenFrp**。客户端先用局域网和直连，其次 NetBird 和 EasyTier，最后才用两家 frp 和 SSH 中继。局域网、直连、NetBird、EasyTier 这四条里有一条连得通时，这一行写的就是那一条。

想在手机上看到隧道，先让手机的 **虚拟网** 一行处于断开状态，再关掉 Wi-Fi，看中枢那一行。

关掉卡片或应用另一条隧道，经这条隧道连着的客户端都会断开。应用栏事先给出警告。客户端随后自己经别的外部访问重新连上；没有别的路可走的客户端就一直断着。

## 改了连接端口之后

在 **网络** 页改了 **连接端口** 之后，frpc 照样把连接转到中枢自己的回环端口，隧道照常能用。中枢的列表只列本地端口等于连接端口的隧道，所以 **网络** 页的应用栏提醒你去服务商那里改本地端口。新端口是 9443 时，**状态** 面板写着 **连接端口现在是 9443。到 SakuraFrp 把这条隧道的本地端口改成 9443，再重新应用隧道。**

1. 在服务商的控制台里，把隧道的本地端口改成新的连接端口。
1. 在 **隧道** 里选择 **刷新**。
1. 选中这条隧道，再选择 **应用隧道**。

## 不再用隧道

想停掉隧道又保留账户，关掉卡片的开关，选择 **应用外部访问**。卡片关着时，账户和隧道都保留。

想让中枢不再用这个账户，SakuraFrp 选 **忘记访问密钥**，OpenFrp 选 **退出登录**，然后确认。两种做法都停掉 frpc，并从每个客户端和被控端的地址里去掉这条隧道的地址。
