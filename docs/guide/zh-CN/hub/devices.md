# 设备

中枢发现的每台机器都在 **设备** 页上。装了被控端的机器在这里显示实时状态，你在它的抽屉里重启、关机、唤醒它，也看到谁在共享桌面。

![设备页上在线的四台机器](/guide/zh/devices_managed.webp)

## 设备状态

页面分 **已管理的设备** 和 **未管理的设备** 两栏。每台设备带一种状态：

| 状态       | 含义                                     | 下一步               |
| ---------- | ---------------------------------------- | -------------------- |
| **被控端** | 已管理：被控端上报状态，从中枢接受模块   | 打开抽屉             |
| **ssh**    | 未管理，但存了登录凭据，一步就能装被控端 | **安装被控端**       |
| **已扫描** | 未管理，也没有凭据                       | **获取链接**         |
| **离线**   | 没有响应                                 | 等它上线，或网络唤醒 |

上方的筛选按状态缩小列表。**扫描局域网** 找出中枢服务的网络里连着的机器。标题旁写着已管理的台数，例如 **4 台中有 4 台已管理**。

中枢所在的机器从第一次登录起就在 **已管理的设备** 里，设置向导已经在上面装好了被控端。这一行以机器的主机名命名，在抽屉 **身份** 一节的 **显示名称** 里能改。

## 添加机器

页面顶部的 **用链接添加** 生成一条加入链接。未管理机器的抽屉里，**获取链接** 给那一行生成一条，**安装被控端** 经 SSH 把被控端装上去。步骤见[安装被控端](../install/agent.md)。

## 抽屉

选择一台机器，打开它的抽屉。已管理的机器最上面是 **实时监控**：CPU、内存、磁盘、负载、运行时长和占用最高的进程。进程旁的 **结束进程** 要按两次才执行。

监控下面是 **身份**、**操作**、**远程桌面**、**操作输出** 和 **Agent 命令结果**。**身份** 里改 **显示名称** 和 **图标**。顶部的 **终端** 和 **文件** 打开对应的页，机器已经选好。

| 操作               | 结果                                                    |
| ------------------ | ------------------------------------------------------- |
| **重新安装被控端** | 在线的被控端从中枢重装自己；不在线的弹出 SSH 安装对话框 |
| **重启**           | 机器立即重启，没保存的内容丢失                          |
| **关机**           | 机器立即关机，没保存的内容丢失                          |
| **网络唤醒**       | 中枢发出魔术包，UDP 端口 9                              |
| **忘记设备**       | 这台设备和它保存的凭据从中枢删除                        |

机器不在线时，重启和关机做不了。

路由器和旁路网关模式下，中枢向它服务的每个网络发唤醒包；服务器模式下，向每个开放网口所在的网络发。唤醒包不经 NetBird 或 EasyTier 发送。机器的固件和网卡都开启了网络唤醒，它才会开机。

忘记设备不动机器上的被控端，用一条新链接就能重新加入。

## 共享桌面

远程桌面用 RustDesk，随被控端安装包一起装。共享在模块页上这台机器的 **远程桌面** 标签里打开和关闭，步骤见[远程桌面](../agent/modules/remote_desktop.md)。抽屉里写着 **共享在这台机器的“远程桌面”标签页里设置。**，选择它就打开那个标签。

共享打开之后，抽屉的 **远程桌面** 一节显示：

- **ID**，旁边有 **复制 ID**。
- **直连端口 21118**。
- 由谁共享，也就是正坐在屏幕前登录的那个账户。
- 当前的观看人数。

![抽屉里的远程桌面一节](/guide/zh/devices_drawer_rdp.webp)

坐席密码是客户端的查看器连这台机器用的密码，由中枢发给查看器。**重置坐席密码** 让机器立即换一个密码，当前的观看者都要重新连。机器上装了 AnyDesk 或 TeamViewer 时，这一节还显示它的 ID 和 **设置无人值守密码**。

抽屉里显示错误时，见[故障排查](../reference/troubleshooting.md#模块页上的错误)。

## 各系统能跑什么

Windows 和 Mac 上能跑文件共享、终端、远程桌面、Gitea、VS Code 和 CloudCLI，Mac 还能跑 code-server。容器和 ZFS 存储只有 Linux 版。见[支持的平台](../reference/platforms.md)。

## 版本不一致的机器

版本和中枢不同的被控端，卡片和抽屉上写着 **这个被控端与中枢的版本不一致。** 中枢接纳的被控端连上时，自己更新到中枢的版本；更新失败时，在抽屉里选择 **重新安装被控端**。

0.3 和 0.4 的被控端连不上 0.5.0 的中枢，设备一直显示离线。在那台机器上装 0.5.0 的被控端，再用一条新链接加入，见[故障排查](../reference/troubleshooting.md#中枢拒绝被控端或客户端)。
