# 设备

**设备**（Devices）页列出中枢发现的每台机器。装了被控端的机器在这里显示实时状态，你在它的抽屉里重启、关机、唤醒它，也看到谁在共享桌面。

![设备页上在线的四台机器](/guide/zh/devices_managed.webp)

## 设备状态

页面分 **已管理的设备**（Managed devices）和 **未管理的设备**（Unmanaged devices）两栏。每台设备带一种状态：

| 状态                         | 含义                                     | 下一步                          |
| ---------------------------- | ---------------------------------------- | ------------------------------- |
| **Agent**                    | 已管理：被控端上报状态，并从中枢接受模块 | 打开抽屉                        |
| **SSH**                      | 未管理，但存了登录凭据，一步就能装被控端 | **安装被控端**（Install agent） |
| **仅扫描到**（Scanned only） | 未管理，也没有凭据                       | **获取链接**（Get link）        |
| **离线**（Offline）          | 没有响应                                 | 等它上线，或者网络唤醒          |

上方的筛选 **全部**（All）、**Agent**、**SSH**、**仅扫描到**、**在线**（Online）和 **离线** 用来缩小列表。**扫描局域网**（Scan LAN）找出中枢服务的网络里连着的机器。标题旁的标记写着已管理的台数，例如 **4 台中有 4 台已管理**。

中枢所在的机器从第一次登录起就在 **已管理的设备** 里，行名是 `hub`。`nhub setup` 结束前已经在它上面装好了被控端。

## 添加机器

页面顶部的 **用链接添加**（Add by link）生成一条加入链接。未管理机器的抽屉里，**获取链接** 给那一行生成一条，**安装被控端** 经 SSH 把被控端装上去。这三种做法的完整步骤在[安装被控端](../install/agent.md)。

## 抽屉

选择一台机器，打开它的抽屉。已管理的机器最上面是 **实时监控**（Live monitor）：CPU、内存、磁盘、负载、运行时长，以及占用最高的进程。每个进程旁有 **结束进程**（Kill process），按一下之后再按一次才执行。

监控下面依次是 **身份**（Identity）、**操作**（Actions）、**远程桌面**（Remote desktop）、**操作输出**（Action output）和 **Agent 命令结果**（Agent command results）。**身份** 里能改 **显示名称**（Display name）和 **图标**（Icon）。顶部的 **终端**（Terminal）和 **文件**（Files）打开对应的页，机器已经选好。

| 操作                                  | 结果                                                    |
| ------------------------------------- | ------------------------------------------------------- |
| **重新安装被控端**（Reinstall agent） | 在线的被控端从中枢重装自己；不在线的弹出 SSH 安装对话框 |
| **重启**（Reboot）                    | 机器立即重启                                            |
| **关机**（Shut down）                 | 机器立即关机                                            |
| **网络唤醒**（Wake-on-LAN）           | 中枢发出魔术包，UDP 端口 9                              |
| **忘记设备**（Forget device）         | 这台设备和它保存的凭据从中枢删除                        |

重启和关机先弹确认框，机器上没保存的内容会丢失。机器不在线时，重启和关机返回 `agent_offline`。

网络唤醒发到哪些网络，取决于中枢的形态。路由器和旁路网关形态下，中枢向它服务的每个网络发包。服务器形态下，中枢向每个开放网口所在的网络发包。魔术包不经 NetBird 或 EasyTier 发送。机器的固件和网卡都开启了网络唤醒，它才会开机。设备从没上报过 MAC 地址时，中枢返回 `wol_no_mac`。

忘记设备不动机器上的被控端。用一条新链接，它就能重新加入。

## 共享桌面

远程桌面用 RustDesk，随被控端安装包一起装。共享由模块页上这台机器的 **Remote desktop** 开关打开和关闭，步骤在[远程桌面](../agent/modules/remote_desktop.md)。抽屉里写着 **共享在这台机器的 Remote desktop 标签页里设置。**（Sharing is set on the machine's Remote desktop tab.），选择它打开那个标签。

共享打开之后，抽屉的 **远程桌面** 一节显示这些内容：

- **ID**，旁边有 **复制 ID**（Copy ID）。
- **直连端口 21118**（Direct port 21118）。
- **由谁共享**（Shared by），也就是正坐在屏幕前登录的那个账户。
- 当前的观看人数。

![抽屉里的远程桌面一节](/guide/zh/devices_drawer_rdp.webp)

坐席密码是客户端的查看器连这台机器时用的密码，由中枢发给查看器。**重置坐席密码**（Reset seat password）让机器立即换一个密码。当前连着的观看者都要重新连。

| 抽屉显示                 | 原因                           | 处理                                                  |
| ------------------------ | ------------------------------ | ----------------------------------------------------- |
| `rdp_nobody_seated`      | 屏幕前没有人登录               | 在那台机器上登录一个账户                              |
| `rdp_screen_not_allowed` | Wayland 会话还没允许屏幕共享   | 在那台机器自己的屏幕上允许一次                        |
| `rdp_permissions_needed` | Mac 上 RustDesk 缺两项系统权限 | 在 Mac 的系统设置里给 RustDesk 打开屏幕录制和辅助功能 |

机器上装了 AnyDesk 或 TeamViewer 时，这一节还显示它的 ID 和 **设置无人值守密码**（Set unattended password）。

## 各系统能跑什么

Windows 和 Mac 上能跑文件共享、终端、远程桌面、Gitea、VS Code 和 CloudCLI，Mac 还能跑 code-server。容器和 ZFS 只有 Linux 版。各模块在每种系统上的要求，见[支持的平台](../reference/platforms.md)。

## 版本不一致的机器

版本和中枢不同的被控端，卡片和抽屉上写着 **这个被控端与中枢的版本不一致。**（This agent is a different version from the hub.）中枢接纳的被控端连上时，自己更新到中枢的版本。自我更新失败时，在抽屉里选择 **重新安装被控端**。

0.5.0 的中枢不接纳 0.3 和 0.4 的被控端。它们连上来时，中枢返回 `protocol_too_old`，设备一直显示离线。这些被控端不能升级过来。在那台机器上装 0.5.0 的被控端，再用一条新链接加入，步骤在[安装被控端](../install/agent.md)。
