# 服务

服务是 hub 发布给客户端的一个条目：网页、端口、AI 网关、共享或共享出来的桌面。**服务**（Services）页列出 hub 自己发现的条目，也能手动声明新的条目。

![服务页的网页、端口、AI 和文件四组](/guide/zh/services_list.webp)

## 类型和按钮

页面上有四组。共享的桌面是第五类，出现在**设备**页的机器抽屉里和客户端里。

| 类型     | 页面上的分组      | 来源                             | 桌面客户端上的按钮  |
| -------- | ----------------- | -------------------------------- | ------------------- |
| 网页     | **网页**（Web）   | Gitea、VS Code，或手动声明       | **打开**（Open）    |
| 端口     | **端口**（Ports） | 容器发布的端口，或手动声明       | **连接**（Connect） |
| AI       | **AI**            | hub 的 AI 网关                   | **配置**（Config）  |
| 文件     | **文件**（Files） | 文件共享模块，或手动声明         | **挂载**（Mount）   |
| 远程桌面 | 无                | 运行了 `nagent rdp start` 的机器 | **连接**            |

客户端只看得到权限允许的类型和设备，权限在[客户端](./clients.md)页设置。每个按钮的具体行为见[桌面客户端](../client/desktop.md)。

## 自动发现的条目

hub 在受管机器上配置的模块，自己发布条目，不用声明。每一行写明来源：

| 行里的描述                                           | 来源                   |
| ---------------------------------------------------- | ---------------------- |
| **由**某台主机**上的 samba 模块发布**                | 文件共享模块的每个共享 |
| **由**某台主机**上的 gitea 模块发布**                | Gitea 模块的地址       |
| **由**某台主机**上的 vscode 模块为**某个账户**发布** | 一个 VS Code 实例      |
| **由容器**某镜像**发布**                             | 容器发布的每个主机端口 |
| **由 AI 网关发布**                                   | hub 的 AI 网关         |

这些行带**模块**（module）标记，内容跟着那台机器上的模块配置走。

## 仅限本机的条目

VS Code 条目仅限本机打开，hub 下发时给它带上 `is_local_only` 标记：浏览器只在电脑自己的 `127.0.0.1` 上打开它。在这一页上，它和别的行一样列在**网页**组里。

桌面客户端上，这个条目的按钮是**本机打开**（Open locally）。客户端把实例的端口转发到本机 `127.0.0.1`，从 hub 取回实例的令牌，再在浏览器里打开转发后的地址。Android 应用把这个条目显示为灰色，带**仅桌面**（Desktop only）标记。实例怎么设置，见 [VS Code](../agent/modules/vscode.md)。

## 手动声明服务

hub 不管理的东西用声明发布出去：一个网页、一个 TCP 端口，或另一台服务器上的 SMB 共享。

1. 点**声明服务**（Declare service）。
1. 填**名称**（Name），选**类型**（Kind）：**网页**、**端口**或**文件**。
1. 填**主机**（Host）和**端口**（Port）。
1. 类型是网页时，选**协议**（Scheme），填**路径**（Path）。
1. 类型是文件时，点**扫描主机**（Scan host）列出服务器上的共享，或在**共享**（Shares）里逐个填写名字。
1. 可选：填**描述**（Description）。
1. 点**声明**（Declare）。

![新建声明的服务表单](/guide/zh/services_add.webp)

文件服务不填端口时用 445，每个共享各成一行。主机填 `127.0.0.1`、`localhost` 或 `0.0.0.0` 时指 hub 自己，每个客户端收到的是它访问 hub 所用的地址。

声明的行上点**删除**（Delete），声明和它发布的每一行一起移除。它指向的那台机器不受影响。

## 健康状态

标题旁的标记写健康的行数和总行数，例如 **4 个中有 3 个健康**。每一行有一个状态点和一个状态词：

| 来源                     | 状态词                                                                                                    |
| ------------------------ | --------------------------------------------------------------------------------------------------------- |
| **模块**                 | **提供服务中**（serving）、**未提供服务**（not serving）                                                  |
| **手动声明**（declared） | **可访问**（reachable）、**不可访问**（unreachable）、**检查中…**（checking…）、**未检查**（not checked） |

hub 通过连接来检查声明的行：端口做一次 TCP 连接，网页发一次 GET，文件共享读服务器的共享列表。**测试**（Test）立即再检查一次。服务器对匿名用户隐藏共享列表时，这一行算健康，另有一行说明共享名没有核实。客户端里不健康的条目显示为灰色，写着**当前无法访问**。
