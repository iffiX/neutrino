# 服务

中枢发布给客户端的条目，网页、端口、AI 网关、文件共享和共享的桌面，都列在 **服务** 页上。中枢自己发现大部分条目，别的可以手动声明。

![服务页的网页、端口、AI 和文件四组](/guide/zh/services_list.webp)

## 类型和按钮

服务页按类型分组，客户端为每种类型开一页，每个条目旁边是一个按钮：

| 服务页上的组 | 条目从哪来                                          | 客户端的页和按钮                                 |
| ------------ | --------------------------------------------------- | ------------------------------------------------ |
| **网页**     | Gitea、VS Code、code-server、CloudCLI，或声明的网址 | **网页** 页，**打开** 在本机浏览器里打开它       |
| **端口**     | 容器发布的端口，或声明的端口                        | **端口** 页，**连接** 把它转发到本机 `127.0.0.1` |
| **AI**       | 中枢的 AI 网关                                      | **AI** 页，开关 **AI 工具使用此网关**            |
| **文件**     | 文件共享模块，或声明的 SMB 共享                     | **文件** 页，先 **配置** 再 **挂载**             |
| **远程桌面** | 打开了共享桌面的机器                                | **远程桌面** 页，**连接** 打开查看器             |

客户端只看得到[客户端](./clients.md)页允许的类型和机器。客户端只连中枢的 8443，这一页上的地址它一个也不拨。

## 自动发现的条目

中枢在受管机器上配置的模块，自己发布条目，不用声明。这些行写着来源，例如 **由 192.168.8.183 上的文件共享模块发布**、**由 192.168.8.52 上的 VS Code 模块为 alice 发布**、**由容器 gitea/gitea 发布**，带 **模块** 标记，内容跟着模块配置走。共享桌面的行写着 **来自 desktop 的共享**，带 **设备** 标记。

## 带令牌的条目

VS Code、code-server 和 CloudCLI 的实例只在所在机器的回环地址上监听，行里的地址用浏览器直接打不开。客户端每按一次 **打开**，先从中枢取一个令牌。code-server 和 CloudCLI 的令牌 60 秒内有效，只能用一次。实例怎么设置，见 [VS Code](../agent/modules/vscode.md)。

## 手动声明服务

中枢不管理的网页、TCP 或 UDP 端口、别的服务器上的 SMB 共享，用声明发布出去。

1. 选择 **声明服务**。
1. 填 **名称**，选 **类型**：**网页**、**端口** 或 **文件**。
1. 填 **主机** 和 **端口**。
1. 类型是端口时，选 **传输协议**，默认是 **TCP**，也可以选 **UDP**。
1. 类型是网页时，选 **协议**，填 **路径**。
1. 类型是文件时，选择 **扫描主机** 列出服务器上的共享，或在 **共享** 里逐个填写名字。
1. 可选：填 **描述**。
1. 选择 **声明**。

![新建声明的服务表单](/guide/zh/services_add.webp)

文件服务不填端口时用 445，每个共享各成一行。主机填 `127.0.0.1`、`localhost` 或 `0.0.0.0` 时指中枢自己。同一个端口号在两种传输协议上都用时，声明两次。

声明的行上选择 **删除**，声明和它发布的每一行一起移除。

## UDP 端口

UDP 端口来自传输协议选 **UDP** 的声明，或容器用 `/udp` 发布的端口，地址写成 `host:port/udp`。客户端把它转到自己 `127.0.0.1` 上的一个 UDP 端口，本机程序把数据报发到这个地址。

客户端开的所有流，走同一条到中枢的 TCP 连接。丢一个包，这条连接上的每条流都要等它重发，UDP 的流也一样。所以经中枢转发的 UDP 端口，适合一问一答、量不大的流量：DNS、校时、设备发现、小型游戏服务器。

语音、视频和快节奏的游戏，要一条直达那台机器的路：在 NetBird 或 EasyTier 的控制台里设成子网路由。中枢自己不管理任何路由。

## 健康状态

标题旁写着健康的行数和总行数，例如 **4 个中有 3 个健康**。每一行有一个状态点和一个状态词：

| 来源         | 状态词                                            |
| ------------ | ------------------------------------------------- |
| **模块**     | **提供服务中**、**未提供服务**                    |
| **手动声明** | **可访问**、**不可访问**、**检查中…**、**未检查** |
| **设备**     | **已共享**                                        |

中枢检查声明的行：TCP 端口做一次连接，网页发一次 GET，文件共享读共享列表。UDP 端口写着 **未检查**，客户端照样能用。**测试** 立即再检查一次。客户端里不健康的条目是灰色，写着 **当前无法访问**。
