# 代理

**代理**（Proxy）页设好之后，你选定的设备和目标经出口节点上网，其余流量直接从上行线路出去。这一页写入 `config/xray/`。每次应用都重启代理，经过代理的连接会断开一下。国内版没有代理，也没有这一页。

标题旁的徽章写着当前哪些流量走代理，以及当前出口的名字。

## 添加出口节点

**出口节点**（Exit nodes）是走代理的流量出网用的服务器。

1. 选择 **添加节点**（Add node）。
1. 在 **分享链接**（Share link）里按服务商给出的原样粘贴 `ss://` 或 `vless://` 链接，选择 **添加**（Add）。
1. 选择 **应用节点**（Apply nodes）。

![出口节点和测量值](/guide/zh/proxy_nodes.webp)

中枢测量每个节点，把评分最高的启用节点定为出口，它的卡片标着 **当前出口**（current exit）。每张卡片有两个时间：

- **连接**（connect）：连到节点自己端口的一次连接。
- **请求**（request）：经这个节点取一次探测地址的完整请求。

下面一行是上次测量的时间、评分和应答率。节点的开关决定中枢能不能把它选为出口。关着的节点照样测量，打开之前就能看到它的数值。

| 设置                                       | 作用                                                                         |
| ------------------------------------------ | ---------------------------------------------------------------------------- |
| **测试**（Test）、**全部测试**（Test all） | 立刻测量一个节点或全部节点                                                   |
| **探测地址**（Probe URL）                  | 经每个节点去取的地址，默认 `https://www.gstatic.com/generate_204`            |
| **参照地址**（Reference URL）              | 不走代理直接去取的地址，用来分辨是节点断了还是上行断了；它不走代理也要能应答 |
| **探测间隔（秒）**（Probe interval (s)）   | 两轮测量之间的秒数，默认 60                                                  |

移除节点时，它的分享链接一起删除。

## 选择谁的流量走代理

**分流**（Route）一节有四个开关，各管各的：

| 开关                                                                                   | 管什么                                                         |
| -------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| **让局域网流量走代理**（Send LAN traffic through the proxy）                           | 中枢服务的网络里的设备；服务器形态没有服务网络，不显示这个开关 |
| **让虚拟网流量走代理**（Send overlay traffic through the proxy）                       | 把中枢定为出口节点的虚拟网成员                                 |
| **让 微子·中枢 自己的流量走代理**（Send Neutrino Hub's own traffic through the proxy） | 中枢这台机器自己的连接和域名解析，任何形态下都有效             |
| **出口节点都不应答时直接放行**（Let traffic out directly when no exit node answers）   | 所有启用节点都不可达时，送往代理的流量怎么走                   |

虚拟网成员要经中枢出网，要在虚拟网自己的管理界面里把中枢定为出口节点。在成员上把网关改成中枢没有用。macOS 和 Windows 上，虚拟网开关和中枢自己的开关一起生效。

中枢自己的开关只管这台机器上的其他程序，例如下载、AI 网关和面板。中枢的 NetBird 和 EasyTier 不论开关怎么设，都直接从上行线路出去。

放行开关关着、所有启用节点都不可达时，送往代理的流量失败，局域网的域名解析也一起失败，因为这些域名在出口解析。放行开关开着时，这些流量用本机自己的地址从 WAN 出去。两种情况下，[总览](./dashboard.md)页和这一页顶部都出现提示。

## 按目标分流

![分流一节和直连列表](/guide/zh/proxy_routing.webp)

**GeoIP 分流**（GeoIP split routing）开着时，命中直连列表的目标直接从 WAN 出去，其余送往代理的流量走出口节点。关掉它，送往代理的流量全部走出口节点。

| 列表                           | 写法                                                |
| ------------------------------ | --------------------------------------------------- |
| **直连域名**（Direct domains） | `geosite:cn`、`domain:example.com`、`keyword:baidu` |
| **直连 IP**（Direct IPs）      | `geoip:cn`、`geoip:private`、`10.0.0.0/8`           |

**更新 geodata**（Update geodata）查询 geoip 和 geosite 两份数据库有没有新发行版，有就装上。按钮旁写着数据库是 **随安装包携带**（as the package carries them）还是 **取自发行版**（taken from a release）。

**DNS** 有两个解析器列表。每行一个地址或 `<address>:<port>`，不写端口就是 53，查询按行的顺序发出：

| 列表                                                                  | 解析什么                                       | 空着时                                                         |
| --------------------------------------------------------------------- | ---------------------------------------------- | -------------------------------------------------------------- |
| **远程解析器（走代理的域名）**（Remote resolvers (proxied names)）    | 不在直连列表里的域名，查询经出口节点发出       | 不能空，应用返回 `resolver_required`                           |
| **直连解析器（绕过代理的域名）**（Direct resolvers (bypassed names)） | 直连列表里的域名、出口节点自己的域名和探测主机 | 写着 **跟随网络层的解析器**（Follows the network's resolvers） |

直连解析器空着时，这些域名交给[网络](./network.md)页上行线路的解析器。不走代理的域名不经过这两个列表。例如局域网开关关着时，服务网络的域名也由网络层解析。

选择 **应用分流**（Apply route），中枢重写路由规则。

## 开 SOCKS 端口

**端口**（Ports）是 SOCKS5 监听端口，给自己设代理的程序用。每个端口二选一：**出口节点**（Exit node）按转发流量同样的规则分流，**直连**（Direct）直接从上行线路出去。

1. 在 **端口** 里填端口号，选 **出口节点** 或 **直连**，选择 **添加**。
1. 选择 **应用端口**（Apply ports）。

端口已经有别的程序在监听时，中枢拒绝并返回 `port_already_in_use`。SOCKS 端口在网络页 **开放范围**（Exposure）勾选的每个网络上监听，开放的虚拟网也算在内。

## 验证

在走代理的设备上，或者在打开了中枢自己开关的这台机器上，查一次自己的公网地址：

```bash
curl ifconfig.me
```

输出是出口节点的地址。要从开放网络里的机器测试一个 **出口节点** 类型的 SOCKS 端口，把 `<hub-address>` 换成中枢的地址，`<port>` 换成端口号：

```bash
curl --socks5 <hub-address>:<port> ifconfig.me
```

在中枢上运行下面的命令，从 `config/` 渲染代理配置并打印出来，正在运行的代理不受影响：

```bash
sudo nhub apply --only xray --dry-run
```
