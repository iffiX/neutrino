# 代理

**代理** 页把选定设备和目标的流量交给出口节点，其余流量直接从上行线路出去。国内版没有代理，也没有这一页。这一页写入 `config/xray/`，每次应用都重启代理，经过代理的连接会断开一下。

标题旁的徽章写着哪些流量走代理，以及当前出口的名字。

## 添加出口节点

**出口节点** 是走代理的流量出网用的服务器。

1. 选择 **添加节点**。
1. 在 **分享链接** 里按服务商给出的原样粘贴 `ss://` 或 `vless://` 链接，选择 **添加**。
1. 选择 **应用节点**。

![出口节点和测量值](/guide/zh/proxy_nodes.webp)

中枢测量每个节点，把评分最高的启用节点定为出口，卡片标着 **当前出口**。卡片上有 **连接** 和 **请求** 两个时间，以及上次测量的评分和应答率。关着的节点照样测量。

| 设置                          | 作用                                                              |
| ----------------------------- | ----------------------------------------------------------------- |
| **测试**、**全部测试**        | 立刻测量一个节点或全部节点                                        |
| **探测地址（probe URL）**     | 经每个节点去取的地址，默认 `https://www.gstatic.com/generate_204` |
| **参照地址（reference URL）** | 不走代理直接去取的地址，用来分辨是节点断了还是上行断了            |
| **探测间隔（秒）**            | 两轮测量之间的秒数，默认 60                                       |

移除节点时，它的分享链接一起删除。

## 选择谁的流量走代理

**分流** 一节有四个开关：

| 开关                              | 管什么                                                       |
| --------------------------------- | ------------------------------------------------------------ |
| **让局域网流量走代理**            | 中枢服务的网络里的设备；服务器模式没有服务网络，不显示这一项 |
| **让虚拟网流量走代理**            | 把中枢定为出口节点的虚拟网成员                               |
| **让 微子·中枢 自己的流量走代理** | 中枢这台机器上的程序，例如下载、AI 网关和面板                |
| **出口节点都不应答时直接放行**    | 所有启用节点都不可达时，送往代理的流量是否改从 WAN 出去      |

服务器模式下，局域网里的设备改用下面的 SOCKS 端口。虚拟网成员要在虚拟网自己的管理界面里把中枢定为出口节点。macOS 和 Windows 上，虚拟网开关和中枢自己的开关一起生效。中枢的 NetBird 和 EasyTier 总是直接从上行线路出去。

放行开关关着、所有启用节点都不可达时，送往代理的流量失败，走代理的域名解析也失败。[总览](./dashboard.md)页和这一页顶部都出现提示。

## 按目标分流

![分流一节和直连列表](/guide/zh/proxy_routing.webp)

**GeoIP 分流** 开着时，命中直连列表的目标直接从 WAN 出去，其余送往代理的流量走出口节点。关掉它，送往代理的流量全部走出口节点。两个直连列表每行写一条：

| 列表         | 写法                                                |
| ------------ | --------------------------------------------------- |
| **直连域名** | `geosite:cn`、`domain:example.com`、`keyword:baidu` |
| **直连 IP**  | `geoip:cn`、`geoip:private`、`10.0.0.0/8`           |

**更新 geodata** 查询 geoip 和 geosite 两份数据库的新发行版，有就装上。按钮旁写着数据库 **随安装包携带** 还是 **取自发行版**。

**DNS** 有两个解析器列表，每行一个地址或 `<address>:<port>`，不写端口就是 53，按行的顺序查询：

| 列表                             | 解析什么                                       | 空着时                                     |
| -------------------------------- | ---------------------------------------------- | ------------------------------------------ |
| **远程解析器（走代理的域名）**   | 不在直连列表里的域名，查询经出口节点发出       | 不能空                                     |
| **直连解析器（绕过代理的域名）** | 直连列表里的域名、出口节点自己的域名和探测主机 | 交给[网络](./network.md)页上行线路的解析器 |

没有送往代理的流量，它的域名解析不经过这两个列表。

选择 **应用分流**，中枢重写路由规则。

## 开 SOCKS 端口

**端口** 是 SOCKS5 监听端口，给自己设代理的程序用。**出口节点** 类型按转发流量同样的规则分流，**直连** 类型直接从上行线路出去。

1. 在 **端口** 里填端口号，选 **出口节点** 或 **直连**，选择 **添加**。
1. 选择 **应用端口**。

SOCKS 端口在网络页 **开放范围** 勾选的每个网络上监听，开放的虚拟网也算在内。别的程序占着这个端口时，页面写着这个端口已经在监听了。

应用失败时，见[故障排查](../reference/troubleshooting.md#中枢拒绝网络设置)。

## 验证

在走代理的设备上，或者在打开了中枢自己开关的这台机器上，查一次公网地址：

```bash
curl ifconfig.me
```

输出是出口节点的地址。从开放网络里的机器测试一个 **出口节点** 类型的 SOCKS 端口，`<hub-address>` 是中枢的地址，`<port>` 是端口号：

```bash
curl --socks5 <hub-address>:<port> ifconfig.me
```

在中枢上运行下面的命令，从 `config/` 渲染代理配置并打印出来，正在运行的代理不受影响：

```bash
sudo nhub apply --only xray --dry-run
```
