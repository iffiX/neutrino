# 远程桌面

把受管机器的桌面共享给这台中枢的客户端，只要一个开关，在模块页的 **远程桌面** 标签上，新机器上默认关着。被控端的安装包里带着 RustDesk，所以这个模块不用安装。

## 共享桌面

1. 在[模块](../modules.md)页的 **远程桌面** 标签上，打开 **共享这台机器的桌面**。
1. 选择 **应用远程桌面**。
1. 在客户端的 **远程桌面** 页上，选这台机器的 **连接**。

![远程桌面标签，共享开关已打开并应用](/guide/zh/modules_remote_desktop_tab.webp)

开关打开后，被控端停掉机器上别的 RustDesk 主机，用 RustDesk 自己的服务名运行它带的那一份，机器重启后共享照样恢复。有人正在用的 RustDesk 查看器保持原样。共享走直连端口 21118，不经过 RustDesk 的服务器。

RustDesk 1.4.9 的主机启动时，向三个公共 STUN 服务器查询本机的 IPv6 地址：`stun.l.google.com`、`stun.cloudflare.com`、`stun.nextcloud.com`。这个请求不带标识，也不登记任何东西，RustDesk 没有关掉它的选项。

客户端看到的，是正坐在屏幕前登录的那个人的桌面。被控端的 RustDesk 服务在运行，标签就读 **运行中**，屏幕前有没有人都一样。

在 Mac 上，开关打开时屏幕上弹出对话框，列出 RustDesk 要的“屏幕录制”和“辅助功能”权限。屏幕前的人授权一次之后，客户端才看得到画面。

Windows 上，这个模块只在 amd64 机器上运行。

## 停止共享

1. 关掉 **共享这台机器的桌面**。
1. 选择 **应用远程桌面**。

被控端的 RustDesk 停下，你原先装的 RustDesk 恢复原样。卸载被控端、机器离开中枢或在[设备](../../hub/devices.md)页上移除机器时，也是这样。

## 失败时

哪一步失败，标签上就写出原因和是哪一步。再选择一次 **应用远程桌面**，就重试这一步。各个原因，以及客户端连不上的原因，见[故障排查](../../reference/troubleshooting.md#远程桌面)。
