# 容器

**容器** 模块在一台受管机器上运行你声明的容器，镜像来自 Docker Hub 或别的镜像仓库。Linux 上，机器自己的 Podman 把每个容器作为 systemd 单元运行。Windows 和 macOS 上，容器运行在 Podman 虚拟机里，这是电脑上某一个账户的 Linux 虚拟机。

容器发布的每个主机端口，都成为客户端 **网页** 页或 **端口** 页上的一项。

![server 的容器标签，两个声明的容器](/guide/zh/containers.webp)

## 各系统的要求

| 系统    | 要求                                                                                    | Podman                                                     |
| ------- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Linux   | 被控端能装的系统都可以                                                                  | 发行版自己的软件包，3.4 及以上，每个版本都一样             |
| Windows | x86-64；Windows 10 2004 版（内部版本 19041）及以上，或 Windows 11；电脑固件里开着虚拟化 | WSL 2 上的 Podman 6，两者都由模块安装                      |
| macOS   | macOS 13 及以上                                                                         | Apple 芯片上是 Podman 6，Intel 上是 Podman 5.8，由模块安装 |

系统版本更低时，模块选择器里的 **容器** 是灰的。Windows 上，WSL 要用的两个 Windows 功能还关着时，第一次安装会打开它们，之后 Windows 要重启一次。

## 安装模块

开始之前，这台机器的被控端要在线。Windows 上，运行容器的那个账户的登录信息，要先存进[凭据](../../hub/credentials.md)页的 **登录信息**。

1. 在[模块](../modules.md)页选中这台机器，再选 **容器** 标签。
1. 选择 **安装**。
1. 如果标签上出现 **Windows 需要重启才能装好 WSL，重启后会接着安装。**，选择 **立即重启**，再在确认框里选择 **重启**。电脑上打开的程序都会关闭，重启后安装自动继续。
1. 选择 **配置**。
1. Windows 和 macOS 上，按下一节填好 **运行设置**。
1. Windows 和 macOS 上，选择 **应用运行设置**。

Windows 和 macOS 上，运行设置应用之前，**正在运行**、**镜像源** 和 **声明的容器** 都写着 **先在“运行设置”里选一个账户。**

第一次 **配置** 把机器上已有的容器和镜像源收为声明，所以第一次应用不改动机器。在 Windows 和 macOS 上重新安装之后，它还把被控端找到的那台 Podman 虚拟机的账户填进运行设置。

## 运行设置

Windows 和 macOS 上，**运行设置** 决定用哪个账户的 Podman 虚拟机运行容器，以及这台虚拟机有多大。Linux 机器没有这一节。

| 字段                         | 设定什么                                                        |
| ---------------------------- | --------------------------------------------------------------- |
| **账户**                     | 用电脑上哪个账户的 Podman 虚拟机运行容器                        |
| 账户名加 **的 Windows 登录** | 只在 Windows 上有：开机时用这条登录信息启动 Podman 虚拟机       |
| **CPU 数**                   | Podman 虚拟机用几个处理器                                       |
| **内存（GiB）**              | Podman 虚拟机用多少内存                                         |
| **磁盘上限（GiB）**          | Podman 虚拟机磁盘的大小，只能改大；字段下面的提示写着现在的大小 |

填 0 就用 Podman 的默认值：电脑一半的处理器、2 GiB 内存；macOS 上磁盘是 100 GiB。Windows 上，**磁盘上限（GiB）** 一开始是 100，至少填 1。第一次应用新建这个账户的默认 Podman 虚拟机，大约要一分钟。账户已经有一台时，被控端直接用它；以这个账户运行 `podman ps`，列出的是同一批容器。

电脑一开机就启动这台 Podman 虚拟机，早于任何人登录；大约 30 秒后，容器的端口就能连上。换成另一个账户后，声明的容器改在新账户的 Podman 虚拟机里运行。旧账户的虚拟机停下，里面的镜像和命名卷留在那个账户的目录里。

::: warning
Windows 上，**CPU 数** 和 **内存（GiB）** 写进这个账户的 `.wslconfig` 文件，这个账户下的所有 WSL 系统都按这两项运行。改 CPU、内存或磁盘，这些 WSL 系统都会重启；新建 Podman 虚拟机的那次应用，也会让它们停下。文件里的其他行保持原样。
:::

macOS 上，改动只重启 Podman 虚拟机，容器会停一会儿。

## 声明容器

1. 在 **声明的容器** 下选择 **添加容器**。
1. 填 **名称** 和 **镜像标签**。
1. 在 **端口** 里添加客户端要用的每个端口。
1. 可选：在 **服务** 里为每个端口选发布方式。
1. 在 **卷** 里添加要长期保存文件的每个文件夹。
1. 可选：填 **环境变量** 和 **命令（可选）**。
1. 可选：关掉 **随机器启动**。
1. 选择 **应用容器**。

列表类的项一次填一行，每填一行选一次 **添加**。

## 名称和镜像标签

**名称** 同时是容器名和它的 systemd 单元名，在这台机器上唯一。它只用小写字母、数字、`_` 和 `-`，以字母或数字开头，最长 64 个字符。客户端里这个容器的条目，标题就是这个名称。

**镜像标签** 写镜像和标签，例如 `redis:7`，中间没有空格。没写仓库地址的镜像，从 `docker.io` 拉取。填了镜像之后出现 **选择标签**：中枢从 Docker Hub 取这个镜像最近更新的 25 个标签，选中一个，冒号后面的部分就换成它。Docker Hub 以外的镜像列不出标签，要自己输入，例如 `:latest`。

## 端口

每行把机器上的一个端口映射到容器里的一个端口，写成 `host_port:container_port`，例如 `8080:80`。UDP 端口在末尾加 `/udp`，例如 `5353:5353/udp`；不加就是 TCP。

| 系统    | 主机端口在哪里能连上                             |
| ------- | ------------------------------------------------ |
| Linux   | 机器的每个地址                                   |
| Windows | 只在电脑自己的 `127.0.0.1` 上，而且只有 TCP      |
| macOS   | 电脑自己的 `127.0.0.1`，经 Podman 自己的转发程序 |

被控端在机器本地连这个端口，再把客户端接过去，所以每个系统上的容器端口，客户端都连得上。局域网里的其他机器，只能经客户端连到 Windows 上的容器端口。Windows 上，被控端拒绝带 UDP 端口的应用，因为 WSL 只转发 TCP。

每个主机端口都成为中枢[服务](../../hub/services.md)页上的一项，标题是容器名称。容器运行时这一项写着 **服务中**，停着时写着 **未提供服务**。在 shell 里手动启动、发布了端口的容器，也有自己的一项。

## 服务一栏

**服务** 里，容器的每个主机端口占一行，可以选 **自动**、**网页** 或 **端口**。

| 选择                                     | 机器怎么发布                 | 客户端在哪里显示                                                |
| ---------------------------------------- | ---------------------------- | --------------------------------------------------------------- |
| **自动**，默认                           | 按 **端口** 列表里那一行发布 | 被控端检测到 http 或 https 时在 **网页** 页，其余在 **端口** 页 |
| **网页**，再选 **http** 或 **https**     | 在 TCP 上发布                | 电脑和手机的 **网页** 页                                        |
| **端口**，勾 **TCP**、**UDP** 或两个都勾 | 在每个勾上的协议上发布       | 桌面客户端的 **端口** 页，每个协议一项                          |

选 **自动** 时，容器每次启动后，被控端把每个发布的 TCP 端口检查一次。先发数据的服务算作 TCP，例如 SSH 和数据库。回应 HTTP 请求的算作 http，经 TLS 回应的算作 https。端口还没打开时，几秒后再查一次。检查之前，这一行写着 **自动：容器运行后检测**；检查之后写着检测结果，例如 **自动：检测到 http**。

选 **端口** 并勾上 **UDP**，这个端口也在 UDP 上发布，和 **端口** 列表里加 `/udp` 的一行效果相同。**端口** 页只在桌面客户端里有，所以端口类的条目只出现在电脑上。

## 卷

每行把机器上的一个来源映射到容器里的绝对路径，写成 `host_path:container_path`。来源是一个文件夹，按这台机器系统自己的写法；也可以是一个 Podman 命名卷，名字的写法和容器名称一样。

| 系统    | 例子                   | 容器能用的文件夹                                  |
| ------- | ---------------------- | ------------------------------------------------- |
| Linux   | `/srv/share:/data`     | 机器上任何从 `/` 开始的文件夹                     |
| Windows | `C:\data:/data`        | 电脑固定磁盘上的文件夹，例如 `C:` 或 `D:` 上的    |
| macOS   | `/Users/me/data:/data` | `/Users`、`/private` 或 `/var/folders` 下的文件夹 |

Windows 和 macOS 上，被控端拒绝其他位置的文件夹，例如网络共享。

**添加** 旁边的 **浏览…** 打开这台机器上的文件夹。进到一个文件夹，选择 **选择这个目录**，这一行就以这个文件夹加冒号开头。在冒号后面填容器里的路径，再选 **添加**。

容器写进这个路径的文件留在机器上；容器重建时，别处的文件全部丢失。Windows 和 macOS 上，命名卷在 Podman 虚拟机的磁盘里。

## 环境变量和命令

**环境变量** 每行一个 `KEY=value`。名字只用字母、数字和 `_`，以字母或 `_` 开头。

**命令（可选）** 是一行命令，用来替换镜像自带的命令，例如 `python3 -m http.server 8000`。留空时，容器运行镜像自带的命令。`debian` 这类基础镜像要在这里写一个长期运行的命令，否则容器启动后马上退出。

## 随机器启动

**随机器启动** 打开时，机器开机后容器跟着启动，每次应用改动了它，它也会启动。关掉时，开机后容器保持停止；新加的容器也一直停着，直到你在 **正在运行** 里选择 **启动**。

## 应用容器时发生什么

**应用容器** 把所有声明发给这台机器。被控端先检查每个字段，有一个写错，就拒绝整次应用并写出出错的字段，机器上什么都不改。检查通过后，被控端逐个处理声明：

- 新加或改过的容器写出单元文件；开着 **随机器启动** 或正在运行的，随即重启。第一次启动要拉取镜像。
- 声明没变的容器照常运行。
- 从列表里删掉的容器停下，单元文件删掉；它的镜像和 Podman 卷留在机器上。

::: warning
应用会重建每个改过的容器，卷以外的文件全部丢失。
:::

标签上出现错误码时，原因和处理办法见故障排查页的[容器](../../reference/troubleshooting.md#容器)一节。

## 正在运行和镜像源

**正在运行** 列出机器上的每个容器，写着镜像和状态，每一行最后标出容器的来历：中枢的模块运行的标 **中枢**，你声明的标 **声明**，手动启动的标 **手动**。运行中的容器有 **日志**、**Shell**、**重启** 和 **停止**，停着的容器有 **日志** 和 **启动**。模块运行的容器写着模块的名字，只有 **日志**。

**中枢的容器** 列出中枢的模块在这台机器上运行的容器，写着镜像、端口和卷。要改它们，到对应模块的标签页里改。

**Shell** 在页面上的一个窗口里打开容器内的终端，各个系统都一样。镜像里有 bash 就用 bash，否则用 sh。选择 **关闭**，或者在里面输入 `exit`，就结束这个 shell 和它在容器里启动的所有程序。

在 **镜像源** 下选择 **添加镜像源**，填地址，再选择 **应用镜像源**。从下一次拉取起，Podman 先按顺序试这些镜像源，最后才用 `docker.io`。

## 卸载

在标签上选择 **卸载**，被控端停下所有声明的容器，卸掉 Podman。装着运行在容器模块上的模块时，先卸载那个模块。容器的数据留在电脑上，中枢也留着这些声明。

| 系统    | 删掉的                                        | 留下的                                                                                                  |
| ------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Linux   | 声明的容器的单元、镜像源文件、Podman 的软件包 | 镜像、卷、手动启动的容器                                                                                |
| Windows | 声明的容器、Podman                            | Podman 虚拟机和它的磁盘、镜像、命名卷、手动启动的容器；WSL 和它的两个 Windows 功能；账户的 `.wslconfig` |
| macOS   | 声明的容器、Podman                            | Podman 虚拟机和它的磁盘、镜像、命名卷、手动启动的容器                                                   |

Windows 和 macOS 上，Podman 虚拟机停下，留在账户的目录里，开机也不再启动。重新安装之后，被控端找回这台虚拟机，下一次应用把声明的容器连同它们的卷一起恢复。
