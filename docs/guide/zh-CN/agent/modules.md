# 模块

**模块**（Modules）页的副标题是 **每台机器配置的功能**（Features configured on each machine）。读完这页，你能在选中的机器上装好要的模块，让它运行或应用它的设置，也读得懂标签上的状态词。模块是你装到自己机器上的一套服务软件，被控端按中枢的配置运行它。

开始之前，这台机器的被控端要在线。被控端离线时，页面显示 **被控端已离线**（The agent is offline），按钮都不可用。

## 页面上有什么

| 从上到下                             | 内容                                       |
| ------------------------------------ | ------------------------------------------ |
| **选择机器**（Which machine）        | 在线的受管机器；离线的机器不在列表里       |
| **全局配置**（Global configuration） | 不属于任何模块的设置，现在只有 AI 工具     |
| **模块配置**（Module configuration） | 这台机器的模块标签，和选中的那个模块的设置 |

AI 工具这一块的用法，见[把一台机器的 AI 工具指向网关](./modules/ai_tools.md)。

## 选机器和模块

1. 在 **选择机器** 里选一台机器。
1. 在 **模块配置** 里选一个标签。

标签按固定顺序排列：File share、Terminal、Remote desktop、Gitea、VS Code、code-server、CloudCLI、Containers、ZFS storage。标签名取自中枢的模块目录，中文界面上也是英文。每个标签上有模块名、一个圆点和一个状态词。

标签行末尾的 **+** 打开模块列表。勾选一项，这台机器就多一个标签；取消勾选，标签就去掉。

![desktop 的模块列表，Containers、ZFS storage 和 code-server 是灰的](/guide/zh/modules_picker_greyed.webp)

机器的系统跑不了的模块，在列表里是灰的，下面写着 **这台机器的系统不支持**（This machine's system cannot run it），也不会成为标签。比如 Windows 机器 `desktop` 上，Containers、ZFS storage 和 code-server 是灰的，Gitea 可以装。各系统能跑哪些模块，见[支持的平台](../reference/platforms.md)。

## 终端和远程桌面

Terminal 和 Remote desktop 用到的程序，都在被控端的安装包里，所以每台受管机器都有这两个标签，**+** 列表里没有它们。这两个标签只显示状态和设置，不带 **安装**、**启动**、**停止**、**卸载**、**配置** 按钮，也没有输出框。

账户和 shell 的设置见[终端（Terminal）](./modules/terminal.md)。共享桌面的开关见[远程桌面（Remote desktop）](./modules/remote_desktop.md)。

## 状态词的意思

| 状态词                                               | 这台机器上                                             |
| ---------------------------------------------------- | ------------------------------------------------------ |
| **未安装**（not installed）                          | 没有这个模块的软件                                     |
| **已安装**（installed）                              | 装着软件，中枢还没配置过它                             |
| **已停止**（stopped）                                | 已应用中枢的配置，服务停着                             |
| **运行中**（running）                                | 已应用中枢的配置，服务在运行                           |
| **安装中**（installing）、**卸载中**（uninstalling） | 正在做这一步                                           |
| **排队中**（queued）                                 | 被控端按固定顺序一次处理一个模块，这个模块排在后面     |
| **失败**（failed）                                   | 上一步失败了，原因写在标签下面                         |
| **不支持**（unsupported）                            | 被控端比这个模块旧；标签里的字段、开关和应用栏全是灰的 |
| **未上报**（never reported）                         | 机器从没上报过这个模块                                 |

## 安装、启动和停止

| 按钮                  | 机器上发生什么               |
| --------------------- | ---------------------------- |
| **安装**（Install）   | 装上软件，不写配置，也不启动 |
| **启动**（Start）     | 装上软件，应用配置，启动服务 |
| **停止**（Stop）      | 应用配置，停止服务           |
| **卸载**（Uninstall） | 移除软件和中枢写下的配置     |

按下按钮后，标签立刻显示下一步的状态词，比如 **排队中** 或 **安装中**。按钮保持灰色，直到机器上报了别的状态，最多两分钟。

安装或卸载进行时，标签下面的 **输出**（Output）框显示过程，旁边的圆点写着 **运行中**、**已完成**（finished）或 **失败**。其余时候，这个框显示模块在机器上最近的日志。有的发行版没有对应当前内核的 ZFS 内核模块，这时 ZFS 的安装要现场编译，花几分钟，过程也打印在这个框里。

安装失败、机器上也没留下任何东西时，标签回到 **未安装**。输出框显示一次失败的原因，直到你下次按按钮，**安装** 照常能按。一个步骤开始后，页面上没有取消它的按钮。

模块目录里没有适合这台机器的构建时，中枢返回 `no_platform_build`。机器离线时，中枢拒绝改动并返回 `agent_offline`，机器回来后再按一次。

VS Code 标签要先接受微软的条款，见 [VS Code](./modules/vscode.md)。

## 失败后重试

标签显示 **失败** 时，再按一次原来那个按钮，就重试这一步。要装的按 **安装**，要运行的按 **启动**，要停的按 **停止**，**卸载** 一直能按。模块设置里的应用按钮和 **配置** 也一样，再按一次就重试。页面上没有单独的重试按钮；没失败的模块，再按一次什么也不改。

## 卸载

**卸载** 弹出确认框，写明模块和机器。你确认之后，机器才开始卸载。

::: warning
软件和中枢写下的配置会删掉。存储池、共享目录、仓库和容器卷留在机器上。
:::

从机器上卸掉被控端本身时，共享和账户也留着。模块加的服务、计划任务和防火墙规则随被控端一起删掉，见 [nagent 命令](../commands/nagent.md)里的 `nagent service uninstall`。

## 配置

**配置**（Configure）先做 **启动** 做的事，再在标签下面展开模块的设置。再按一次，按钮写着 **收起配置**（Hide configuration），设置随之收起。

中枢还没有某个模块的配置时，第一次 **配置** 把机器上已有的东西收为中枢的配置。所以第一次应用不改动机器上原有的内容。

| 标签            | 第一次 **配置** 收下什么                                                            |
| --------------- | ----------------------------------------------------------------------------------- |
| **File share**  | Linux 上，机器已有的共享和账户；Windows 和 macOS 上，只收这个模块以前建的共享和账户 |
| **Gitea**       | 中枢自己装的实例；手工装的 Gitea 只上报端口，设置仍归它自己                         |
| **VS Code**     | 不收                                                                                |
| **code-server** | 不收                                                                                |
| **CloudCLI**    | 不收                                                                                |
| **Containers**  | 机器已有的容器，连同镜像、端口、卷和环境变量，以及镜像源                            |
| **ZFS storage** | 不收；各分区显示机器自报的磁盘情况                                                  |

从此中枢手上这份配置是唯一依据，每次应用都把整份配置写回机器。

## 每个标签打开什么

| 标签               | 里面有什么                                                                                         |
| ------------------ | -------------------------------------------------------------------------------------------------- |
| **File share**     | **共享**（Shares）、**用户**（Users）、**当前连接**（Now serving）                                 |
| **Terminal**       | **账户**（Account）、**Shell 程序**（Shell program）                                               |
| **Remote desktop** | 一个开关，**共享这台机器的桌面**（Share this machine's desktop）                                   |
| **Gitea**          | **接入**（Access）、**管理员**（Administrator）                                                    |
| **VS Code**        | **实例**（Instances）                                                                              |
| **code-server**    | **实例**                                                                                           |
| **CloudCLI**       | **实例**                                                                                           |
| **Containers**     | **正在运行**（Running now）、**镜像源**（Registry mirrors）、**声明的容器**（Declared containers） |
| **ZFS storage**    | **拓扑**（Topology）、**存储池**（Pools）、**数据集**（Datasets）                                  |
