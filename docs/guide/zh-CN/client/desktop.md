# 桌面客户端

桌面客户端装在你自己的电脑上，Linux、Windows、macOS 都能用。每台中枢发一条链接，粘进窗口就加入了那台中枢。之后这台中枢的网页、端口、AI 网关、共享、终端和远程桌面，都在同一个窗口里打开。终端里做同样的事用 `nclient`，见 [nclient 命令](../commands/nclient.md)。

每一页都经中枢连到服务。客户端在本机回环地址 `127.0.0.1` 上开一个端口，连到这个端口的每条连接，客户端都转给中枢的 8443 端口。中枢再把它接到服务上：服务在中枢自己这台机器上就直接连，在别的机器上就经那台机器的被控端连。

## 安装客户端

开始之前，确认这台电脑满足下列条件：

- 系统是下面之一，完整列表见[支持的平台](../reference/platforms.md)：
  - Debian 12、Ubuntu 22.04 或更新版本，带桌面会话
  - RHEL 9、AlmaLinux 9、Fedora 41 或更新版本，带桌面会话
  - x86-64 上的 Windows 10 1809 或更新版本，或 Windows 11
  - Apple 芯片上的 macOS 12.3 或更新版本
- 用你自己的普通账户运行。以 root 运行时，客户端返回 `root_refused`。
- 能访问要加入的每台中枢的 8443 端口：在局域网里直接访问，在外面经[外部访问](../hub/overlay.md)里的任意一种办法访问。

从发布页下载对应系统的包，然后安装。64 位 ARM 的 Linux 机器上，`.deb` 文件名里写 `arm64`，`.rpm` 文件名里写 `aarch64`。

::: code-group

```bash [Debian、Ubuntu]
sudo apt install ./neutrino-client_0.5.0_amd64.deb
```

```bash [RHEL、AlmaLinux、Fedora]
sudo dnf install ./neutrino-client-0.5.0-1.x86_64.rpm
```

```powershell [Windows]
msiexec /i neutrino-client-0.5.0-windows-amd64.msi
```

```bash [macOS]
sudo installer -pkg neutrino-client-0.5.0-macos-arm64.pkg -target /
```

:::

`apt` 和 `dnf` 把依赖和包一起装上：WebKitGTK、托盘库、`cifs-utils`、polkit，以及自带的 RustDesk 查看器要加载的库。

::: warning
`dpkg -i` 和 `rpm -i` 不装依赖。已经用了的话，Debian 系运行 `sudo apt -f install`，RHEL 系用 `sudo dnf install` 装上它列出的包。
:::

Windows 上双击 `.msi` 也是同一个安装程序。勾选 **Add the Neutrino Client to PATH**，任何终端里都能用 `nclient` 命令。机器上缺 WebView2 运行时的话，安装程序会运行微软的引导程序装上它。卸载对话框里有 **Keep my configuration** 一项；勾选它保留配置，下次安装后直接回到原来的中枢。

![Windows 安装程序](/guide/os/win_msi_installer.webp)

macOS 上，安装程序把 **Neutrino Client** 放进 `/Applications`，把 `nclient` 链接到 `/usr/local/bin`。应用只有临时签名，第一次打开时 Gatekeeper 会确认一次。

每个包都登记虚拟网要用的系统服务：NetBird 守护进程，和客户端自带的 EasyTier 守护进程。国内版的包只有 EasyTier 守护进程。Linux 上这个包与 `netbird` 包冲突。macOS 上已经装了 NetBird 的，客户端直接用它。

Windows 上还多登记一个服务 `NeutrinoClientFiles`。它运行文件适配器，**文件**页靠它把共享挂成盘符，见[文件](#文件)。

## 加入中枢

开始之前，先在中枢的面板里建一条客户端链接：打开 **客户端**（Clients），选 **新建客户端链接**（New client link），填这台电脑的名字，再选 **创建链接**（Create link）。链接三十分钟内有效，中枢中途重启也照样有效，只能加入一台电脑。这台电脑能用哪些服务，在[客户端](../hub/clients.md)页上设置。

加入的步骤：

1. 打开客户端：Linux 上在应用菜单里，Windows 上在开始菜单里，macOS 上点应用图标。**中枢**（Hubs）页写着 **尚未加入任何中枢**（No hub joined yet），下面是 **加入中枢**（Join a hub）一行。
1. 把链接粘进那一行的输入框，选 **加入**（Join）。

这台中枢马上多出一行。链接里的地址还没有一个连得上时，这一行写 **已加入，尚未连上中枢**（Joined; the hub has not been reached yet）。连上以后写 **已连接 · 局域网**（Connected · LAN），或别的连接办法的名字，后面是中枢的地址和它运行的软件包。

![加入中枢之后的客户端窗口](/guide/zh/client_connected.webp)

粘的是中枢 **设备**（Devices）页发的链接时，输入框下面写 `link_not_for_client`；链接没粘全时写 `link_unreadable`。链接已用过或已过期时，这一行变成 **未连上**（Not connected），写着 `ticket_spent`。这时在这一行上选 **离开**，再用新链接加入。中枢上失败的加入太多时，这一行写 `admission_paused`，过了码里给的秒数再自己加入。

要再加入一台中枢，在那台中枢的面板里建一条链接，粘进同一行 **加入中枢**。每台中枢各记各的电脑名字，各发布各的服务。每个服务页都按加入的先后列出各个中枢。

## 中枢

窗口标题是 **微子·客户端**（Neutrino client）。左边侧栏依次是 **中枢**、**网页**（Web）、**端口**（Ports）、**AI**、**文件**（Files）、**终端**（Terminals）、**远程桌面**（Remote desktops），隔一条线是 **设置**（Settings）。右上角的 **↻** 让连着的中枢立刻收到一份报告，断开的中枢立刻重连。

### 行的状态

**中枢** 页上一行是一台中枢，写着名字、状态、地址和它运行的软件包。通道开着时，状态写出这次是从哪条路连上中枢的：

| 状态                        | 通道经过                                     |
| --------------------------- | -------------------------------------------- |
| **已连接 · 局域网**（LAN）  | 中枢在它所服务网络上的地址                   |
| **已连接 · 直连**（Direct） | 中枢自己的某个地址，从它所服务的网络之外连上 |
| **已连接 · NetBird**        | 中枢的 NetBird 地址                          |
| **已连接 · EasyTier**       | 中枢的 EasyTier 地址                         |
| **已连接 · 中继**（Relay）  | 中枢的中继服务器上的公网端口                 |

名字前的圆点用颜色表示状态：

| 圆点       | 含义                                                            |
| ---------- | --------------------------------------------------------------- |
| 绿色       | 通道开着                                                        |
| 黄色、闪动 | 正在连接，或这一行上有操作在进行                                |
| 黄色       | 连不上，但没有东西坏，例如 `hub_unreachable`、`client_disabled` |
| 红色       | 要有人改东西才会好，例如 `hub_untrusted`、`binding_unknown`     |
| 灰色       | 还没连上过这台中枢                                              |

### 行上的按钮

| 按钮                      | 何时出现                                                                                | 作用                                                                         |
| ------------------------- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| **面板**（Panel）         | 中枢的客户端页允许这个客户端 **免密码进入中枢面板**（Hub panel without the password）时 | 先写 **打开中…**，再经本机的一个转发在浏览器里打开中枢的面板，打开时已经登录 |
| **重新连接**（Reconnect） | 这一行写着 **已被另一个客户端取代**（Replaced by another client）时                     | 从另一个客户端那里把这台中枢要回来，重新连接                                 |
| **离开**（Leave）         | 一直都在                                                                                | 按一次变成 **再按一次离开**（Press again to leave），五秒内再按才离开        |

在任何连得上中枢的地方，都能用 **面板** 打开面板，所以面板自己的端口只开在局域网里就够了。**免密码进入中枢面板** 默认是关的，要有人在中枢的客户端页上为这台电脑打开。浏览器打开的地址是 `http://panel-<hub-id>.localhost:<local-port>/?tkn=<token>`，macOS 上是 `http://127.0.0.1:<local-port>/?tkn=<token>`。其中 `<hub-id>` 是中枢的 id，`<local-port>` 是这个转发的端口，`<token>` 是一次性的登录凭证，一分钟内有效。面板随后把 `tkn` 从地址里去掉。被拒绝时，例如 `permission_denied`，错误显示在这一行上。离开这台中枢或退出客户端之前，这个转发一直开着。

在终端里，`nclient leave --yes` 不问直接离开，`nclient status --json` 以 JSON 打印每台中枢的状态。离开后这一行立刻消失，中枢有没有应答都一样。这台中枢在本机发布的东西随之撤销：转发（含面板那一个）、挂载、查看器，以及别的中枢不用的虚拟网。

中枢拒绝时，这一行留着并写出错误码，客户端隔一段时间再试，最长隔一分钟。只有一个码会让这一行消失：

| 错误码             | 含义                                         | 怎么办                   |
| ------------------ | -------------------------------------------- | ------------------------ |
| `protocol_too_old` | 客户端的协议号低于中枢接受的下限             | 装新版客户端             |
| `protocol_too_new` | 客户端的协议号高于中枢的                     | 先升级中枢               |
| `hub_untrusted`    | 那个地址上的证书不是链接钉住的那张           | 中枢重置过，用新链接加入 |
| `binding_unknown`  | 中枢的客户端页里已经没有这个客户端，这行消失 | 用新链接重新加入         |

### 虚拟网

客户端的各页只用到中枢的 8443 端口，虚拟网只是从外面连回来的办法之一。中枢发布了 NetBird 或 EasyTier，而且它的客户端页允许这个客户端用虚拟网时，这一行下面多一行 **虚拟网**（Virtual network）。这一行写着状态，连上后再写本机在这个网络里的地址。

要加入这个网络，在这一行上选 **连接**（Connect）：

| 这一行写着                               | 含义                                           | 按钮                   |
| ---------------------------------------- | ---------------------------------------------- | ---------------------- |
| **未连接**（Not connected）              | 本机不在这个网络里                             | **连接**               |
| **连接中…**，下面写 **正在登录 NetBird** | 引擎启动并登录，最多 90 秒                     | **取消**（Cancel）     |
| **连接中…**，下面写 **正在等待中枢应答** | 本机已分到地址，客户端计秒，等中枢从这条路应答 | **取消**               |
| **已连接 ·** 加本机地址                  | 中枢经这个网络应答了                           | **断开**（Disconnect） |

EasyTier 用控制台模式时，原因行写 **本机已登记到控制台，请在控制台里把它挂载到一个网络。**，直到控制台的主人把它挂上。失败时这一行回到 **未连接**，错误码写在下面，客户端不会自己再试。上次连着的电脑，客户端启动时自动连一次。

中枢两种引擎都发布时，按钮旁边有一个选择框，用来选引擎。只有这一行写着 **未连接** 时才能换。

![中枢那一行上的虚拟网选择框](/guide/zh/client_network_picker.webp)

守护进程是系统服务，客户端退出后本机仍在网络里。

| 错误码                    | 含义                                                            |
| ------------------------- | --------------------------------------------------------------- |
| `overlay_other_network`   | 本机在另一个 NetBird 网络里，或接着别的中枢的控制台，先离开那个 |
| `overlay_daemon_down`     | NetBird 或 EasyTier 守护进程没有运行，重装客户端                |
| `bundle_missing`          | 这份安装里没有 NetBird 或 EasyTier，重装客户端                  |
| `overlay_join_failed`     | NetBird 或 EasyTier 没让本机加入，码后面是它自己的原话          |
| `overlay_no_address`      | 90 秒内引擎没有给本机分地址                                     |
| `overlay_console_invalid` | 中枢给的 EasyTier 控制台地址，EasyTier 用不了                   |

## 转发

转发是客户端为一个条目在 `127.0.0.1` 上开的端口。连到这个端口的每条连接，都变成一条去中枢的流，中枢再把流接到服务上。转发开着的行，后面多出 `→ 127.0.0.1:` 和端口号。

| 页面         | 转发开着的时段                     |
| ------------ | ---------------------------------- |
| **网页**     | 从 **打开** 到 **断开**            |
| **端口**     | 从 **连接** 到 **断开**            |
| **AI**       | 客户端开着、而且工具指向这台中枢时 |
| **文件**     | Linux 和 macOS 上，从挂载到卸载    |
| **远程桌面** | 从 **连接** 到查看器关闭           |

转发开着时，本机所有程序和账户都能连上它。退出客户端，所有转发都关闭。

### 本地端口

**网页** 和 **端口** 页上，行里的 **配置**（Configure）打开 **本地端口**（Local port）的选择：

- **自动**（Auto）：本机任何地址上都没有程序以条目的协议监听条目自己的端口时，就用这个端口；否则从 20000 往上找第一个空闲端口。客户端为这个条目记住这个端口，重启后也不变。
- **指定**（Fixed）：用你填的号，范围 1024～65535。同一协议的另一个条目已占用这个号时，对话框写 **端口已被另一个条目占用** 并给出号码。同一个号可以 TCP 用一次、UDP 再用一次。

条目转发着时 **配置** 变灰，原因写 **先断开，才能改本地端口。**

### 转发行上的错误码

转发连不到服务时，这一行写出下面的码之一：

| 错误码               | 含义                                                                                                |
| -------------------- | --------------------------------------------------------------------------------------------------- |
| `connect_failed`     | 中枢或那台机器连不上服务，原因是三者之一：`refused`（端口上没有程序监听）、`timeout`、`unreachable` |
| `agent_offline`      | 提供这个条目的机器现在没有连到中枢                                                                  |
| `port_not_published` | 那台机器现在没有发布这个端口，例如容器或实例停了                                                    |
| `connect_limit`      | 这个客户端经中枢开着的连接已到 256 条，关掉几条再试                                                 |
| `permission_denied`  | 中枢的客户端页不允许这个客户端用这类条目，或不允许用那台机器                                        |
| `service_unknown`    | 中枢已不再发布这个条目                                                                              |

## 网页

**网页** 页列出各个中枢发布的网址：Gitea、VS Code、code-server、CloudCLI，以及在中枢 **服务**（Services）页手动声明的网址。每个地址下面一行写着中枢、机器和模块，例如 **由 Neutrino:Argon:Gitea 提供**。

每一行有三个按钮：

| 按钮                   | 作用                                                         |
| ---------------------- | ------------------------------------------------------------ |
| **打开**（Open）       | 先写 **打开中…**；条目还没有转发时先建转发，再在浏览器里打开 |
| **配置**（Configure）  | 设定这个转发的本地端口                                       |
| **断开**（Disconnect） | 条目转发着时出现，关掉转发                                   |

浏览器打开的地址是 `http://` 加一个 `.localhost` 下的名字和本地端口，两个实例的登录因此互不干扰。macOS 上这个名字是 `127.0.0.1`，因为 Safari 不解析 `.localhost` 下的名字。

VS Code、code-server 和 CloudCLI 的条目要带令牌才能打开。每按一次 **打开**，客户端都向中枢取一个新令牌，加在地址后面。code-server 和 CloudCLI 的令牌 60 秒内有效，只能用一次。中枢没给令牌时，这一行写出 `web_token_missing`。

中枢访问不到的条目变灰，写着 **当前无法访问**（Not reachable now）。页面里一个条目都没有时，写着 **还没有网页服务**。

## 端口

**端口** 页把中枢发布的端口转到本机的回环地址上。条目来自受管机器上容器的主机端口，以及中枢 **服务** 页里手动声明的 TCP 或 UDP 端口。

- 在条目上选 **连接**（Connect）。

按钮先写 **转发中…**，再变成 **断开**（Disconnect），这一行后面多出 `→ 127.0.0.1:` 和本地端口。让本机的程序连这个地址就行。选 **断开** 关掉转发。

UDP 条目写成 `host:port/udp`，连接后写 `→ 127.0.0.1:` 加本地端口和 `/udp`。本机程序把数据报发到这个本地地址，回复也回到它那里。手动声明的 UDP 端口不显示健康状态，**连接** 一直可用。

这个客户端发出的一切都走同一条到中枢的 TCP 连接。所以丢一个包，这条连接上的每条流都要等它重发，UDP 的流也一样。经中枢转发的 UDP 端口，适合一问一答、量不大的流量：DNS、校时、设备发现、小型游戏服务器。语音、视频和快节奏的游戏要有一条直达那台机器的路，这条路由你在虚拟网自己的控制台（NetBird 或 EasyTier 的）里设成子网路由。

## AI

**AI** 页让本机的 Claude Code、Codex 和 Gemini CLI 指向某个中枢的 AI 网关。每个带网关的中枢有一个条目。条目上有 **配置**（Configure）和 **AI 工具使用此网关**（The AI tools use this gateway）开关。同一时间最多开一个。

在要用的网关上打开开关。条目先写 **切换工具中…**，再写 **工具已指向中枢**，原来开着的开关随之关上。客户端为这个网关建好转发，让每个工具带着本客户端的密钥连 `http://127.0.0.1:` 加本地端口。客户端用自带的 cc-switch 改写三个工具各自的配置，其中一个写不进去，三个都保持原样。再选一次开关，每个工具恢复第一次切换前的配置。

条目下面写着 **只有这个客户端开着时，工具才连得到网关。** 用这些工具时，让客户端在托盘里开着。

只有连着的中枢能打开开关，否则客户端返回 `no_exit_hub`。中枢还没给这个客户端发密钥时，返回 `no_endpoint`，到中枢的 **AI** 页发一把。

选模型的步骤：

1. 在条目上选 **配置**，打开 **AI 工具配置**（AI tool configuration）。
1. 在 **Claude Code** 下，选 **默认模型**（Default model）、**Opus 档位**（Opus slot）、**Sonnet 档位**（Sonnet slot）和 **Haiku 档位**（Haiku slot）。
1. 在 **Codex** 下，选 **模型**（Model）和 **推理强度**（Reasoning effort）：`minimal`、`low`、`medium` 或 `high`。
1. 在 **Gemini** 下，选 **模型**。
1. 选 **保存**（Save）。

每一项都能选 **网关默认**（gateway default）。列出的模型是那台中枢自己的。正在用的网关上，保存后立刻改写工具；别的网关上，选择等到打开它的开关时才生效。

## 文件

**文件** 页把中枢发布的 SMB 共享挂到本机：Linux 上挂到家目录下的文件夹，macOS 上成为访达里的一个卷，Windows 上挂到一个盘符。条目来自受管机器上文件共享模块的共享，以及中枢 **服务** 页里手动声明的共享。

挂载的步骤：

1. 在条目上选 **配置**（Configure），这一行下面展开一个表单。
1. 填 **共享用户名**（Share username）和 **共享密码**（Share password），也就是这个共享接受的账号。
1. Linux 上，保留或修改 **挂载路径**（Mount path），它是家目录下的文件夹，例如 `~/nas/media`。**浏览…**（Browse…）可以选或新建文件夹。Windows 上选 **盘符**（Drive）。macOS 上表单里没有位置要选。
1. 选 **保存**（Save）。
1. 选 **挂载**（Mount）。按钮先写 **挂载中…**，最后变成 **卸载**（Unmount）。

![共享已挂载的文件页](/guide/zh/client_files_mounted.webp)

登录信息存在一个只有你的账户能读的凭据文件里，下次 **挂载** 不用再填密码。**卸载** 摘掉共享，登录信息保留。

### 各系统怎么挂载

| 系统    | 挂载方式                                                                                                                                            |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Linux   | 客户端用 `pkexec` 运行自带的挂载助手，从转发的端口挂载 `//127.0.0.1/` 加共享名；polkit 弹一次密码框                                                 |
| macOS   | 由系统从转发上挂载这个卷，和访达的 **连接服务器** 一样；第一次挂载要你确认一次服务器，这一行写出 `/Volumes` 下的挂载点                              |
| Windows | 文件适配器给提供共享的那台机器分一个专用地址，从 `198.19.255.2` 起；Windows 把盘符映射到这个地址，同一个盘符一直对应同一台机器 <!-- scan: allow --> |

macOS 上，这些对话框都由系统弹出：密码不对时弹出系统登录框，在那里选 **取消**，客户端返回 `mount_not_authorized`。客户端最多等系统十分钟，过了就写 `mount_timed_out`。

Windows 上的适配器是一块名为 `neutrino_files` 的网卡，由 `NeutrinoClientFiles` 服务运行。它不接任何网络，只把共享的连接送到中枢。这个服务缺失、停止或出错时，挂载失败，写出 `files_adapter_unavailable` 和服务自己的原话，电脑上别的东西都不变。在 Windows 的 **服务**（Services）管理器里启动 **Neutrino Client Files**，或重装客户端，让服务重新登记上。

![文件资源管理器里映射的盘符](/guide/os/win_explorer_mapped.webp)

| 错误码                        | 含义                                                   |
| ----------------------------- | ------------------------------------------------------ |
| `mountpoint_invalid`          | 路径不在家目录下                                       |
| `mountpoint_not_empty`        | 文件夹里有东西                                         |
| `mountpoint_not_drive_letter` | Windows 上选的不是空闲盘符                             |
| `mountpoint_in_use`           | 这个路径上已经有另一条共享，无论它来自哪台中枢         |
| `credentials_missing`         | 保存的登录信息丢了，在 **配置** 里重新填               |
| `share_login_rejected`        | 用户名或密码不对；**配置** 会打开并填好用户名          |
| `share_access_denied`         | 登录对了，但这个账号不能用这个共享                     |
| `share_not_found`             | 主机上没有这个共享名                                   |
| `share_unreachable`           | 主机没有应答；它恢复后客户端自己再挂载                 |
| `share_session_conflict`      | Windows 已经用另一个账号连着这台服务器，先断开那个连接 |
| `files_adapter_unavailable`   | Windows 上 `NeutrinoClientFiles` 服务缺失、停止或出错  |
| `mount_not_authorized`        | 你关掉了 polkit 授权窗口或 macOS 的登录框              |
| `mount_tooling_missing`       | Linux 上这台电脑没有 `mount.cifs`                      |

## 终端

**终端** 页在受管机器上开一个 shell，显示在窗口的标签页里。中枢的客户端页要允许这个客户端打开终端。

1. 在 **终端** 页上方一排里选中机器。绿色圆点表示机器在线。
1. 选 **新终端**（New terminal）。

shell 在新标签页里打开，敲的每个键都发到那台机器。窗口用客户端自带的 MesloLGS NF 字体显示 shell，powerlevel10k 提示符的图标能正常显示。

![客户端里一个持久终端标签页](/guide/zh/client_terminal.webp)

粘贴时，在 shell 上点右键，或按 Ctrl+Shift+V；macOS 上按 Cmd+V。客户端读不到剪贴板时，shell 下面一行写出 `clipboard_unreadable`。

右键菜单里的 **清屏**（Clear）先给 shell 发 Ctrl+C，再清空屏幕。之后 shell 的输出要安静半秒，最长二十秒；在这之前到的输出全部丢掉，终端里写 **清屏中…**（Clearing…）。

shell 下面一行的末尾是 **持久**（Persistent）开关。打开后，没有窗口连着时机器仍保留这个会话，例如客户端退出之后。保留的会话显示成一个灰色圆点的标签页，选它就连回去，先显示 shell 最近的输出。中枢断线又连上后，机器还保留着的会话自动连回各自的标签页；会话已不存在的标签页写 **已结束**（Ended）。持久标签页上的 **×** 按一次变成 **再按一次结束**（Press again to end），再按一次，机器上的 shell 才结束。面板里同样的会话见[终端](../agent/terminals.md)。

| 错误码              | 含义                                       |
| ------------------- | ------------------------------------------ |
| `permission_denied` | 中枢的客户端页不允许这个客户端打开终端     |
| `agent_offline`     | 那台机器现在没有连到中枢                   |
| `unknown_terminal`  | 中枢没有提供那台机器的终端                 |
| `session_not_owned` | 会话是别的查看者打开的，开关不归这个客户端 |
| `session_unknown`   | 那台机器已经不保留这个会话                 |

## 远程桌面

**远程桌面** 页用客户端自带的 RustDesk 查看器，打开另一台机器的屏幕。受管机器共享桌面时（由中枢模块页上它的 **Remote desktop** 开关打开），条目出现；停止共享或机器离线时，条目消失。

- 在条目上选 **连接**（Connect）。

按钮写 **连接中…**，查看器打开那台机器的桌面，这一行写 **查看器已打开**（Viewer open）。座位密码由中枢设定，随这一次点击交给查看器。查看器连的是这个条目在 `127.0.0.1` 上的转发，查看器关掉，转发也关掉。

两台机器共用剪贴板，一边复制的文字在另一边粘贴。要把文件复制到远端，在查看器的工具栏里选 **传输文件**（Transfer file），把文件拖到那个窗口的远端一侧。Mac 的条目下面有一行提示：画面全黑或鼠标没反应，说明那台 Mac 还没给 RustDesk 开启 **屏幕录制** 和 **辅助功能**。

| 看到的现象                        | 原因                               |
| --------------------------------- | ---------------------------------- |
| 页面写着 **还没有共享的远程桌面** | 没有机器在共享，或共享的机器离线了 |
| `rdp_not_shared`                  | 那台机器停止了共享                 |
| `rdp_no_desktop`                  | 本机这个会话没有屏幕给查看器用     |
| `rdp_launch_failed`               | 查看器没能启动，码后面是原因       |

## 设置

1. 选侧栏分隔线下面的 **设置**。
1. 在 **客户端设置**（Client settings）面板里，选 **语言**（Language）和 **主题**（Theme）：**跟随系统**（System）、**深色**（Dark）或 **浅色**（Light）。
1. 选 **保存**。

语言和主题只管这个窗口，面板有自己的设置。

**关于**（About）卡片列出本机名字和平台、客户端的版本和许可证，以及客户端自带的每个程序的版本、许可证和 **源码**（Source）链接。

## 托盘

关闭窗口只是把它藏起来，客户端继续运行，每台中枢都保持连接，每个转发都开着。托盘图标在 Windows 任务栏的角落，Linux 顶栏的指示器区，macOS 的菜单栏。图标菜单里有 **打开**（Open）和 **退出**（Quit）：前者显示窗口，后者停止客户端。
