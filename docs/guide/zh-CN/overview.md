# 总览

微子（Neutrino）是一台机器上的 hub，外加两个装在别处的程序。hub 管网络、虚拟网、代理和 AI 网关。被控端装在每台要管的 Linux 机器上，提供能力。客户端装在每个人的电脑上，使用这些能力。

## 一台机器四层

hub 上的功能分四层，一层叠在一层之上。网络模型之上的三层各自独立，用不上的就不启用。

![架构](/guide/architecture_zh.svg)

| 层       | 回答的问题                     | 不启用时                           |
| -------- | ------------------------------ | ---------------------------------- |
| 网络模型 | 这台机器在你的网里是什么       | 服务器形态：不做路由，地址一个不改 |
| 虚拟网   | 外面的机器怎么进来             | 外面进不来，局域网里照常           |
| 代理     | 谁的流量从哪个出口出去         | 全部直连                           |
| AI 网关  | 各台电脑的 AI 工具指向哪个地址 | 工具保持各自原来的配置             |

网络模型的形态有服务器、旁路网关和路由器。

- **服务器**（Server）不做路由。
- **旁路网关**（Side gateway）为主机转发，前提是那台主机把网关设成了这台机器。
- **路由器**（Router）在上行网口和它服务的网络之间路由，也是唯一接管网口地址的形态。

## 提供者与使用者

hub 自己只提供一项服务，就是 AI 网关。被控端提供共享、git、容器、存储和远程桌面，运行在拥有那块硬盘或那台显示器的机器上。

![侧栏的两组页面](/guide/zh/sidebar_groups.webp)

| 角色   | 程序              | 提供什么                                 | 使用什么             |
| ------ | ----------------- | ---------------------------------------- | -------------------- |
| hub    | `neutrino-hub`    | AI 网关，以及网络、虚拟网、代理这三层    | 被控端上报的状态     |
| 被控端 | `neutrino-agent`  | Samba、Gitea、Podman、ZFS、RustDesk 主机 | hub 下发的模块和命令 |
| 客户端 | `neutrino-client` | 什么都不提供                             | hub 发布的每一条服务 |

hub 这台机器在初始化时也装上了被控端，所以这台机器同样能当提供者，在设备页里是一台设备。

## 服务怎么从 hub 到按钮

每条服务有一个来源和一个类别；客户端按类别把它显示在对应的面板里。

| 来源     | 谁产生                          | 例子                                   |
| -------- | ------------------------------- | -------------------------------------- |
| 模块发布 | 被控端上启用的模块              | Samba 的共享、Gitea 的网址、容器的端口 |
| 手动声明 | 你在服务页填的表单              | 一个网址、一个 TCP 端口、一个 SMB 共享 |
| 机器自报 | 机器自己运行 `nagent rdp start` | 一个共享出来的桌面                     |

![服务页的四组](/guide/zh/services_list.webp)

五类是网页、端口、AI、文件和远程桌面。服务页只列前四组；远程桌面只出现在设备抽屉和客户端里，因为只有机器自己的被控端能声明它。客户端按同样的五类画五个面板，每条服务下面一行写它由谁发布。

![客户端的五个面板](/guide/zh/client_connected.webp)

## 三个包与一个版本号

| 包                | 装在哪                                | 以什么身份运行   |
| ----------------- | ------------------------------------- | ---------------- |
| `neutrino-hub`    | 一台常开的 Linux 机器                 | root             |
| `neutrino-agent`  | 每台要管的 Linux 机器                 | root，无窗口     |
| `neutrino-client` | 每个人的 Linux、Windows 或 macOS 电脑 | 这个人的普通账户 |

三个包共用一个版本号，一起发布。版本不一致时，面板在设备抽屉里给出升级动作，客户端在窗口里说明该升级哪一边。`config/` 没有迁移脚本，两个版本的结构不保证一样，所以升级顺序是 hub、被控端、客户端。

## 面板的两组页面

面板侧栏分 **Hub** 和 **被控端**（Agent）两组。Hub 组是这台机器自己的事。被控端组的每一页是 hub 在某台被控端机器上驱动的一个模块；hub 这台机器也算一台被控端机器。

![总览页](/guide/zh/dashboard.webp)

| 面板组 | 面板页                                                       | 本站的页                                                                                                      |
| ------ | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| Hub    | 总览、网络、虚拟网、代理、AI、设备、客户端、服务、凭据、设置 | [网络](./hub/network.md) 到 [设置](./hub/settings.md)，总览没有单独的页                                       |
| 被控端 | 终端、文件、Samba、Gitea、容器、ZFS                          | [终端](./hub/terminals.md) 到 [ZFS](./hub/zfs.md)，仍归在本站的 Hub 分组下，因为设置动作都在 hub 的面板里完成 |
