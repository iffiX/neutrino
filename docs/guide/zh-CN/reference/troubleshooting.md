# 故障排查

这一页是全站唯一的错误码表。先在屏幕上找到错误码或那一行字，再按它出现的地方找到下面对应的一节，照“处理”一列做。表里的 `<hub>` 代表中枢那台机器的地址。

## 面板打不开

| 症状                                              | 原因                                                                          | 处理                                                                                     |
| ------------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 浏览器打不开 `http://<hub>:8080`                  | 中枢的服务没在运行、端口改过，或这个网络不在开放范围里                        | 在中枢上运行 `nhub status`，再看 **网络** 页的 **面板端口** 和 **开放范围**              |
| `http://<hub>:8080` 跳到 `https://<hub>` 后打不开 | HTTPS 开着，HTTP 端口把浏览器转到 HTTPS 端口，这里却连不到那个端口            | 看 **面板端口** 里的 **HTTPS 端口**，确认去中枢的路上这个端口是通的                      |
| 改了面板端口后会话断开                            | 面板在新端口上重启；会话 cookie 以端口命名，即 `neutrino_session_<port>`      | 在新地址上重新登录                                                                       |
| 选了 **开启 HTTPS** 或 **关闭 HTTPS** 后会话断开  | 切换结束了会话，离开的那个端口在转走浏览器时删掉 cookie                       | 在页面跳到的地址上重新登录                                                               |
| 关闭 HTTPS 后在 `http://` 上登录，又回到登录卡    | 浏览器还留着 HTTPS 端口的 `Secure` cookie，`http://` 上的新 cookie 替换不了它 | 选登录卡上的 **清掉旧会话**，或打开一次 `https://` 地址，它把浏览器送回来并删掉旧 cookie |

## 浏览器提示证书有问题

这几行针对 HTTPS 端口。它的证书由中枢自己的证书颁发机构签发，浏览器装上这个颁发机构并重启后才信任它。

| 症状                                                       | 原因                                                       | 处理                                                                                                                 |
| ---------------------------------------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 浏览器说证书颁发机构不受信任                               | 这台设备没装颁发机构                                       | 打开 `http://<hub>:8080`，在 **设置** > **HTTPS** 下选 **安装证书**，照这台设备的步骤做，再重启浏览器                |
| **开启 HTTPS** 是灰的，旁边写着 **先安装证书并重启浏览器** | 这个浏览器不认 HTTPS 端口的证书                            | 装上这个系统对应的颁发机构，重启浏览器，再用 `http://` 地址打开                                                      |
| 导入颁发机构之后 Chrome 仍显示“不安全”                     | 导入之前在证书警告页上选过“继续访问”                       | 重启 Chrome                                                                                                          |
| 同一台机器上 Firefox 报警，Chrome 不报                     | Firefox 有自己的一份颁发机构列表                           | 照 **安装证书** 下 **Linux：Firefox** 的步骤做                                                                       |
| 设置页改动之后，每个浏览器又开始报警                       | **重新生成证书** 换了一个新的颁发机构                      | 在每台设备上装新的颁发机构并重启浏览器；HTTPS 开着时，`http://<hub>:8080/api/hub/setting/https/authority` 照样能下载 |
| 浏览器说证书属于别的名字                                   | 地址栏里的地址不在 **证书上的名字** 里；公网地址从不在其中 | 改用那里列出的名字或地址打开面板，局域网里能用 `hub.neutrino.internal`                                               |

## 锁定

| 症状                         | 原因                                                         | 处理                                                                 |
| ---------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------- |
| **多次失败后已锁定。**       | 连续输错密码                                                 | 在中枢上运行 `sudo nhub unlock`，它同时解除 fail2ban 的全部 SSH 封禁 |
| **密码不对。**，而且忘了密码 | 面板密码丢了                                                 | 在中枢上运行 `sudo nhub reset password`，所有会话随之登出            |
| 忘了保险库口令               | 运行中的机器仍用自己的工作密钥读保险库，旧口令做的备份打不开 | 在中枢上运行 `sudo nhub vault rekey` 设新口令，再下载一份新备份      |
| `vault_locked`               | 中枢所在机器上没有保险库数据密钥的工作副本，凭据都读不出来   | 在 **设置** 页恢复一份备份，填做备份时的保险库口令                   |

## 凭据存不进去

| 症状                    | 原因                     | 处理                                                           |
| ----------------------- | ------------------------ | -------------------------------------------------------------- |
| `key_is_public`         | 粘贴的是公钥             | 粘贴配对的私钥，即不带 `.pub` 的那个文件，含 BEGIN 和 END 两行 |
| `key_passphrase_needed` | 私钥有口令保护，口令没填 | 把私钥的口令一起填上                                           |

## 向导和恢复备份

恢复时出现这几个码，中枢什么都不恢复。

| 症状                             | 原因                                               | 处理                                       |
| -------------------------------- | -------------------------------------------------- | ------------------------------------------ |
| `backup_wrong_extension`         | 文件不是面板导出的备份                             | 选面板 **备份配置** 下载的那个文件         |
| `backup_corrupt`                 | 存档已损坏                                         | 换一份备份                                 |
| `vault_passphrase_wrong`         | 口令打不开这份备份                                 | 填做这份备份时的保险库口令                 |
| `backup_mode_unavailable`        | 备份里的模式这台中枢不提供，例如国内版没有旁路网关 | 恢复到提供这个模式的中枢上，比如完整版     |
| 文件已恢复，对话框写着应用没完成 | 应用配置的某一步失败，原因写在对话框里             | 处理好原因，在中枢上运行 `sudo nhub apply` |

## 设备离线

| 症状                                             | 原因                                     | 处理                                                                                              |
| ------------------------------------------------ | ---------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 面板上的操作或客户端里的条目返回 `agent_offline` | 那台机器的被控端没连着中枢               | 在那台机器上以 root 或管理员运行 `nagent status`；服务停着时运行 `nagent start`，等设备行变成在线 |
| 机器在列表里，模块却改不了                       | 离线的机器拒绝一切改动，中枢也不排队     | 让机器重新上线，再应用一次                                                                        |
| 选 **网络唤醒** 时返回 `wol_no_mac`              | 这台机器从没上报过 MAC 地址              | 让机器上线一次，被控端上报 MAC 地址之后再唤醒它                                                   |
| SSH 安装返回 `unsupported_remote_install`        | 对方的系统不是 Linux，SSH 安装只装 Linux | 在那台机器上装被控端，用 **用链接添加** 的链接加入                                                |

## 中枢拒绝被控端或客户端

被控端在 `nagent status` 里显示这些错误码，客户端显示在对应中枢的那一行。

| 症状               | 原因                                                                  | 处理                                                                                                                      |
| ------------------ | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `protocol_too_old` | 程序的协议号低于中枢接受的下限，例如 0.3 或 0.4 的程序连 0.5.0 的中枢 | 在那台机器上装 0.5.0 的包，再用中枢上的新链接加入                                                                         |
| `protocol_too_new` | 程序的协议号高于中枢的，例如 0.5.0 的程序连 0.4 的中枢                | 中枢是 0.5 时，在 **设置** 页升级它。0.4 的中枢不能升级到 0.5.0：删掉它，全新安装 0.5.0，被控端和客户端都用新链接重新加入 |
| `hub_untrusted`    | 中枢重装过，证书换了                                                  | 用新链接重新加入：被控端的链接在 **设备** 页的 **用链接添加** 里，客户端的链接在 **客户端** 页                            |

## 加入中枢失败

这些码写在客户端的加入框下面，或写在 **加入被拒 ·** 后面。

| 症状                  | 原因                                 | 处理                                                      |
| --------------------- | ------------------------------------ | --------------------------------------------------------- |
| `link_not_for_client` | 粘的是 **设备** 页发的被控端链接     | 在 **客户端** 页生成一条                                  |
| `link_unreadable`     | 链接没粘全                           | 从面板复制整条链接                                        |
| `ticket_spent`        | 链接用过，或已过了 30 分钟           | 在中枢那一行选 **离开**，用 **客户端** 页的新链接重新加入 |
| `admission_paused`    | 中枢上失败的加入太多，暂停了新的加入 | 等码里给的秒数过去，客户端自己再加入                      |

## 中枢一行的状态字

这些字写在桌面客户端和 Android 应用中枢那一行的名字下面，两边相同。带倒计时的行到 0 时自动重拨，按刷新按钮也马上重拨。

| 状态行                                                    | 原因                                             | 处理                                                                                |
| --------------------------------------------------------- | ------------------------------------------------ | ----------------------------------------------------------------------------------- |
| 刚加入的一行一直在 **连接中…** 和 **中枢未响应** 之间来回 | 链接里的地址这台设备一个都连不上，比如手机在外面 | 在虚拟网一行选 **连接**，或回到中枢所在的网络；链接的票据留着，连上时才用掉         |
| **中枢未响应 · 5 秒后重试**                               | 这一轮的地址都没连上                             | 确认中枢在运行；在外面时，确认这台设备连着一种外部访问                              |
| **中枢未上虚拟网 · 5 秒后重试**                           | 本机已在中枢的虚拟网里，经这个网仍连不到中枢     | 在面板 **外部访问** 页看这个虚拟网的徽章，再查[外部访问](#外部访问)一节             |
| **无网络**                                                | 本机没有任何网络                                 | 接上网络，客户端马上再拨                                                            |
| **证书不符 · 60 秒后重试**                                | 中枢的证书和链接里钉住的不同                     | 中枢重装过的话，选 **离开**，再用新链接加入                                         |
| **中枢暂停接纳 · 60 秒后重试**                            | 中枢暂停了新的加入，秒数由中枢给                 | 等倒计时到 0，客户端自己再加入                                                      |
| **中枢不认识本机**                                        | 中枢的 **客户端** 页上已没有这个客户端           | 选 **离开**，这一行只剩这个按钮，再用新链接加入                                     |
| **版本太旧**                                              | 客户端和中枢的协议号对不上                       | 装新版客户端或升级中枢，再刷新；见[中枢拒绝被控端或客户端](#中枢拒绝被控端或客户端) |
| **加入被拒 ·** 加原因                                     | 中枢拒收链接里的票据                             | 选 **离开**，再用新链接加入；原因见[加入中枢失败](#加入中枢失败)                    |
| **已被替换 · 重新连接**                                   | 另一个客户端用同一个绑定连上了这台中枢           | 选 **重新连接**，把中枢要回来                                                       |
| **已停用**                                                | 中枢在 **客户端** 页上停用了这个客户端           | 在面板 **客户端** 页的这一行选 **启用**                                             |
| 灰色圆点，一直没连上过                                    | 这台中枢本机从没连上过                           | 照 **中枢未响应** 那一行做                                                          |

## 客户端连不上

| 症状                    | 原因                                         | 处理                                                         |
| ----------------------- | -------------------------------------------- | ------------------------------------------------------------ |
| `hub_unreachable`       | 这台电脑连不上中枢的 8443 端口               | 检查网络，或 **外部访问** 页上用的那条路，以及中枢的开放范围 |
| `client_disabled`       | 这个客户端在 **客户端** 页上停用了           | 在它那一行选 **启用**                                        |
| `permission_denied`     | 客户端的权限不包括这类条目，或不包括那台机器 | 在 **客户端** 页放宽这个客户端的权限                         |
| `client_held`           | 这台电脑上另一个账户的客户端在运行           | 让那个账户退出客户端（托盘菜单的 **退出**），再启动你自己的  |
| `gui_webkitgtk_missing` | Linux 上缺 WebKitGTK                         | 装上提示里列出的包，再启动客户端                             |
| `gui_webview2_missing`  | Windows 上缺 WebView2                        | 装上提示里列出的运行时，再启动客户端                         |
| `root_refused`          | 用 `sudo` 启动了客户端                       | 用你自己的账户启动                                           |

## 虚拟网连不上

这些码写在客户端虚拟网那一行的下面，桌面客户端和手机相同。失败后客户端不自动再试，处理好再选 **连接**。

| 症状                                         | 原因                                                                                    | 处理                                                                                                                                                                                   |
| -------------------------------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `overlay_join_failed`                        | 引擎没让本机加入，码后面是引擎自己的原话                                                | NetBird 上常见的原因是中枢存的 setup key 只能用一次，已经用掉：在 NetBird 控制台建一把可重复使用、不限次数的 key，在 NetBird 卡片上选 **替换** 存进去，见 [NetBird](../hub/netbird.md) |
| `overlay_other_network`                      | 本机已在另一个 NetBird 网络里，或连着别的中枢的控制台；手机上是另一台中枢的虚拟网还连着 | 先断开那个网络，再连这一个                                                                                                                                                             |
| `overlay_no_address`                         | 90 秒内引擎没给本机分地址                                                               | 确认本机能上网，再选 **连接**                                                                                                                                                          |
| `overlay_daemon_down`                        | 虚拟网的守护进程没在运行                                                                | 重装客户端                                                                                                                                                                             |
| `bundle_missing`                             | 这份安装里没有 NetBird 或 EasyTier                                                      | 重装客户端                                                                                                                                                                             |
| `overlay_console_invalid`                    | 中枢给的 EasyTier 控制台地址，本机的 EasyTier 用不了                                    | 在中枢的 EasyTier 卡片上核对控制台地址                                                                                                                                                 |
| `overlay_withdrawn`                          | 中枢不再提供这个网络                                                                    | 在中枢的 **外部访问** 页重新打开它，或改用别的外部访问                                                                                                                                 |
| 一直写 **连接中…**，下面说本机已登记到控制台 | EasyTier 控制台模式下，新设备要由控制台的主人挂到网络上                                 | 在 EasyTier 控制台里把这台设备挂到中枢所在的网络，那一行随即变成 **已连接**                                                                                                            |

## 外部访问

| 症状                                                                   | 原因                                                                 | 处理                                                                                                                                                          |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 打开一个引擎，或保存 EasyTier 设置时，返回 `overlay_subnet_overlap`    | 这个引擎的网段和另一个引擎的网段重叠，或和这台机器所在的某个网络重叠 | 改 EasyTier 的 **本机地址**，或在 **网络** 页改局域网的地址；NetBird 的网段固定是 `100.64.0.0/10`                                                             |
| 页上出现红色的 `overlay_default_route_refused`                         | 某个对端或控制台给了这台机器一条走虚拟网的默认路由，中枢删掉了它     | 在 NetBird 或 EasyTier 的控制台里删掉给中枢的出口路由；这台机器始终从自己的上行出网                                                                           |
| `overlay_route_overlap`，下面写着 **请在管理这个虚拟网的地方撤掉它。** | 一条虚拟网路由和这台机器的某个网络重叠，中枢撤不掉它                 | 到管理这个虚拟网的控制台里修改或删除这条路由                                                                                                                  |
| 保存 **直连** 设置时返回 `direct_host_invalid`                         | 公网地址既不是 IP 地址也不是主机名                                   | 改成 IP 地址或主机名，再应用                                                                                                                                  |
| 保存 EasyTier 设置时返回 `easytier_config_server_invalid`              | **控制台地址** 既不是带令牌的地址，也不是单独一个令牌                | 从 EasyTier 控制台重新复制地址或令牌，再应用                                                                                                                  |
| 保存 EasyTier 设置时返回 `easytier_invalid`                            | 手动模式下一个碰头点都没填                                           | 至少填一个碰头点；网里还没有别的机器时，先在一台公网机器上自建碰头点                                                                                          |
| NetBird 的徽章写着 **未加入**                                          | 中枢没有 NetBird 身份，或上次登录已失效                              | 用一把新 key 再加入                                                                                                                                           |
| NetBird 的徽章写着 **管理面不可达**                                    | 中枢连不上 NetBird 的管理面                                          | 查这台机器的上行和 DNS，确认它能打开管理面的地址；NetBird 卡片上的管理面地址留空时，用的是 netbird.io 的                                                      |
| NetBird 的徽章写着 **未运行**                                          | NetBird 守护进程没有运行                                             | 在 **外部访问** 页关掉再打开 NetBird，选择 **应用外部访问**                                                                                                   |
| NetBird 的 **节点** 是空的                                             | 还没有别的设备登录这个网络                                           | 在另一台设备上用 NetBird 应用登录，或让一个客户端连上虚拟网                                                                                                   |
| 经 NetBird 连得上中枢，局域网里的设备却打不开                          | 控制台里这个网段的资源没有访问策略                                   | 在 NetBird 控制台给这个资源加一条 Access Control Policy，见[经 NetBird 访问没装被控端的设备](../scenarios/netbird_lan_routes.md)                              |
| 经 EasyTier 连得上中枢，局域网里的设备却打不开                         | 中枢没有导出这个网段                                                 | 手动模式下在 **导出的局域网** 里加上它再应用；控制台模式下在控制台给中枢加子网代理，见[经 EasyTier 访问没装被控端的设备](../scenarios/easytier_lan_routes.md) |
| EasyTier 写着 **还没有机器加入。**                                     | 另一台机器的网络名或密码和中枢的不一致                               | 用 **复制（含密码）** 重新复制命令，在那台机器上再运行                                                                                                        |
| 虚拟网上连不到中枢，两种引擎都一样                                     | 虚拟网不在中枢的开放范围里                                           | 在 **网络** 页的 **开放范围** 里勾上它，再应用                                                                                                                |
| SSH 中继的 **状态** 一直是 **连接中**                                  | 转发已启动，第一次检查还没做完                                       | 过一分钟再看                                                                                                                                                  |
| SSH 中继的 **状态** 是 **未配置**                                      | 服务器、账户、密钥或登录信息没填，或者已从凭据里删掉                 | 填好设置，选择 **应用 SSH 中继**                                                                                                                              |
| SSH 中继的 **状态** 是 **保险库已锁定**                                | 这台机器上缺少保险库数据密钥的工作副本                               | 照[锁定](#锁定)一节 `vault_locked` 那一行做                                                                                                                   |
| SSH 中继的 **状态** 是 **认证失败**                                    | 服务器不接受这把密钥或这个密码                                       | 检查 `authorized_keys` 里的公钥行，或者密码和这个账户的 `PasswordAuthentication`                                                                              |
| SSH 中继的 **状态** 是 **服务器不让对外监听**                          | 服务器拒绝监听，或者别的程序占着这个端口                             | 确认 `permitlisten` 里的端口就是对外端口，并在服务器上腾出这个端口                                                                                            |
| SSH 中继的 **状态** 是 **对外端口不通**                                | 转发在运行，公网地址却没有应答，或应答的是别的证书                   | 检查 `GatewayPorts clientspecified`、服务商的防火墙和服务器自己的防火墙                                                                                       |
| SSH 中继的 **状态** 是 **主机密钥已变**                                | 服务器出示的密钥和记下的不一样                                       | 同一地址上重装过服务器时，先按[用自己的 VPS 中继连回家](../scenarios/vps_relay.md)重新设置服务器，再选择 **忘记主机密钥**                                     |
| SSH 中继的 **状态** 是 **连不上服务器**                                | SSH 连不到服务器，或者连接断了                                       | 检查服务器和 SSH 端口，确认服务器在运行                                                                                                                       |

## 中枢拒绝网络设置

| 症状                                                              | 原因                                                                      | 处理                                                            |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 应用 **网络** 页时返回 `network_invalid`，说某个网口的角色是停用  | **开放范围** 里勾着的一个网口，角色是 **停用**                            | 把这个网口的角色改成 WAN 或 LAN，或在 **开放范围** 里取消勾选它 |
| **国家代码** 下面写着 **两个字母，例如 CN。5 GHz 需要国家代码。** | 热点用 5 GHz，国家代码空着或不是两个字母                                  | 填上所在国家的两个字母代码，例如 `CN`，再应用                   |
| 保存一个端口时返回 `port_out_of_range`                            | 端口不在 1 到 65535 之间；面板端口、代理端口、直连和 SSH 中继的端口都一样 | 改成这个范围内的端口，再应用                                    |
| 保存一个端口时返回 `port_already_in_use`                          | 这台机器上已经有别的程序在这个端口上监听                                  | 换一个端口，或先停掉占着它的程序                                |
| 应用 **代理** 页时返回 `resolver_required`                        | **远程解析器（走代理的域名）** 一个都没有                                 | 至少加一个远程解析器，再应用                                    |
