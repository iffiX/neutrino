# 故障排查

本页按问题出现的地方分节，每节一张表；找到屏幕上的错误码或文字所在的那一行，照“处理”一列做。表里的 `<hub>` 代表中枢那台机器的地址。

## 面板打不开

| 症状                                                             | 原因                                                                     | 处理                                                                                                              |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| 浏览器打不开 `http://<hub>:8080`                                 | 中枢的服务没在运行、端口改过，或这个网络不在开放范围里                   | 在中枢上运行 `nhub status`，再看 **网络**（Network）页的 **面板端口**（Panel ports）和 **开放范围**（Exposure）   |
| `http://<hub>:8080` 跳到 `https://<hub>` 后打不开                | HTTPS 开着，HTTP 端口把浏览器转到 HTTPS 端口，这里却连不到那个端口       | 看 **面板端口** 里的 **HTTPS 端口**（HTTPS port），确认去中枢的路上这个端口是通的                                 |
| 改了面板端口后会话断开                                           | 面板在新端口上重启；会话 cookie 以端口命名，即 `neutrino_session_<port>` | 在新地址上重新登录                                                                                                |
| 选了 **开启 HTTPS** 或 **关闭 HTTPS**（Disable HTTPS）后会话断开 | 切换结束了会话，离开的那个端口在转走浏览器时删掉 cookie                  | 在页面跳到的地址上重新登录                                                                                        |
| 关闭 HTTPS 后在 `http://` 上登录，又回到登录卡                   | 浏览器还留着 HTTPS 端口的 `Secure` cookie，不肯换掉它                    | 选登录卡上的 **清掉旧会话**（Clear the old session），或打开一次 `https://` 地址，它把浏览器送回来并删掉旧 cookie |

## 浏览器提示证书有问题

这几行针对 HTTPS 端口。它的证书由中枢自己的证书颁发机构签发，浏览器装上这个颁发机构并重启后才信任它。

| 症状                                                                      | 原因                                                                           | 处理                                                                                                                         |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 浏览器说证书颁发机构不受信任                                              | 这台设备没装颁发机构                                                           | 打开 `http://<hub>:8080`，在 **设置** > **HTTPS** 下选 **安装证书**（Install certificate），照这台设备的步骤做，再重启浏览器 |
| **开启 HTTPS**（Enable HTTPS）是灰的，旁边写着 **先安装证书并重启浏览器** | 这个浏览器不认 HTTPS 端口的证书                                                | 装上这个系统对应的颁发机构，重启浏览器，再用 `http://` 地址打开                                                              |
| 导入颁发机构之后 Chrome 仍显示“不安全”                                    | 导入之前在证书警告页上选过“继续访问”                                           | 重启 Chrome                                                                                                                  |
| 同一台机器上 Firefox 报警，Chrome 不报                                    | Firefox 有自己的一份颁发机构列表                                               | 照 **安装证书** 下 **Linux：Firefox**（Linux, Firefox）的步骤做                                                              |
| 设置页改动之后，每个浏览器又开始报警                                      | **重新生成证书**（Regenerate certificate）换了一个新的颁发机构                 | 在每台设备上装新的颁发机构并重启浏览器；HTTPS 开着时，`http://<hub>:8080/api/hub/setting/https/authority` 照样能下载         |
| 浏览器说证书属于别的名字                                                  | 地址栏里的地址不在 **证书上的名字**（Certificate names）里；公网地址从不在其中 | 改用那里列出的名字或地址打开面板，局域网里能用 `hub.neutrino.internal`                                                       |

## 锁定

| 症状                                                      | 原因                                                         | 处理                                                                 |
| --------------------------------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------- |
| **多次失败后已锁定。**（Locked after repeated failures.） | 连续输错密码                                                 | 在中枢上运行 `sudo nhub unlock`，它同时解除 fail2ban 的全部 SSH 封禁 |
| **密码不对。**（Wrong password.），而且忘了密码           | 面板密码丢了                                                 | 在中枢上运行 `sudo nhub reset password`，所有会话随之登出            |
| 忘了保险库口令                                            | 运行中的机器仍用自己的工作密钥读保险库，旧口令做的备份打不开 | 在中枢上运行 `sudo nhub vault rekey` 设新口令，再下载一份新备份      |

## 设备离线

| 症状                                             | 原因                                 | 处理                                                                                              |
| ------------------------------------------------ | ------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 面板上的操作或客户端里的条目返回 `agent_offline` | 那台机器的被控端没连着中枢           | 在那台机器上以 root 或管理员运行 `nagent status`；服务停着时运行 `nagent start`，等设备行变成在线 |
| 机器在列表里，模块却改不了                       | 离线的机器拒绝一切改动，中枢也不排队 | 让机器重新上线，再应用一次                                                                        |

## 中枢拒绝被控端或客户端

被控端在 `nagent status` 里显示这些错误码，客户端显示在对应中枢的那一行。

| 症状               | 原因                                                                  | 处理                                                                                                                                                   |
| ------------------ | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `protocol_too_old` | 程序的协议号低于中枢接受的下限，例如 0.3 或 0.4 的程序连 0.5.0 的中枢 | 在那台机器上装 0.5.0 的包，再用中枢上的新链接加入                                                                                                      |
| `protocol_too_new` | 程序的协议号高于中枢的，例如 0.5.0 的程序连 0.4 的中枢                | 中枢是 0.5 时，在 **设置**（Settings）页升级它，程序自己重新连上。0.4 的中枢不能升级到 0.5.0：删掉它，全新安装 0.5.0，被控端和客户端都用新链接重新加入 |
| `hub_untrusted`    | 中枢重装过，证书换了                                                  | 用新链接重新加入：被控端的链接在 **设备**（Devices）页的 **用链接添加**（Add by link）里，客户端的链接在 **客户端**（Clients）页                       |

## 外部访问

| 症状                                                                   | 原因                                                                 | 处理                                                                                                                                    |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 打开一个引擎，或保存 EasyTier 设置时，返回 `overlay_subnet_overlap`    | 这个引擎的网段和另一个引擎的网段重叠，或和这台机器所在的某个网络重叠 | 改 EasyTier 的 **本机地址**（This box's address），或在 **网络** 页改局域网的地址；NetBird 的网段固定是 `100.64.0.0/10`                 |
| **外部访问**（Access）页上出现红色的 `overlay_default_route_refused`   | 某个对端或控制台给了这台机器一条走虚拟网的默认路由，中枢删掉了它     | 在 NetBird 或 EasyTier 的控制台里删掉给中枢的出口路由；这台机器始终从自己的上行出网                                                     |
| `overlay_route_overlap`，下面写着 **请在管理这个虚拟网的地方撤掉它。** | 一条虚拟网路由和这台机器的某个网络重叠，中枢撤不掉它                 | 到管理这个虚拟网的控制台里修改或删除这条路由                                                                                            |
| NetBird 的徽章写着 **管理面不可达**（management unreachable）          | 中枢连不上 NetBird 的管理面                                          | 查这台机器的上行和 DNS，确认它能打开管理面的地址；NetBird 卡片上的管理面地址留空时，用的是 netbird.io 的                                |
| NetBird 的 **节点**（Peers）是空的                                     | 还没有别的设备登录这个网络                                           | 在另一台设备上用 NetBird 应用登录，或让一个客户端连上虚拟网                                                                             |
| 客户端扫码加入后，虚拟网那一行写 `overlay_join_failed`                 | 中枢存的是一次性的 setup key，第一台设备已用掉它                     | 在 NetBird 控制台建一把可重复使用、不限次数的 key，在 NetBird 卡片上选 **替换**（Replace）存进去。步骤见 [NetBird](../hub/netbird.md)。 |
| 客户端的虚拟网那一行一直写 **连接中…**，下面说本机已登记到控制台       | EasyTier 控制台模式下，新设备要由控制台的主人挂到网络上              | 在 EasyTier 控制台里把这台设备挂到中枢所在的网络，那一行随即变成 **已连接**                                                             |
| 经 NetBird 连得上中枢，局域网里的设备却打不开                          | 控制台里这个网段的资源没有访问策略                                   | 在 NetBird 控制台给这个资源加一条 Access Control Policy，见“经 NetBird 访问局域网设备”                                                  |
| 经 EasyTier 连得上中枢，局域网里的设备却打不开                         | 中枢没有导出这个网段                                                 | 手动模式下在 **导出的局域网**（Exported networks）里加上它再应用；控制台模式下在控制台给中枢加子网代理，见“经 EasyTier 访问局域网设备”  |
| EasyTier 写着 **还没有机器加入。**（No machine has joined yet.）       | 另一台机器的网络名或密码和中枢的不一致                               | 用 **复制（含密码）**（Copy with the secret）重新复制命令，在那台机器上再运行                                                           |
| 虚拟网上连不到中枢，两种引擎都一样                                     | 虚拟网不在中枢的开放范围里                                           | 在 **网络** 页的 **开放范围** 里勾上它，再应用                                                                                          |
| **SSH 中继**（SSH Relay）卡片的 **状态**（Status）不是 **已连接**      | 中枢到你服务器的 SSH 转发断了，或公网端口不通                        | 对照 [SSH 中继](../hub/relay.md#看懂状态)里的状态表处理，直到状态变回 **已连接**。                                                      |

## 中枢拒绝网络设置

| 症状                                                                             | 原因                                                       | 处理                                                            |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------- |
| 应用 **网络** 页时返回 `network_invalid`，说某个网口的角色是停用                 | **开放范围** 里勾着的一个网口，角色是 **停用**（Disabled） | 把这个网口的角色改成 WAN 或 LAN，或在 **开放范围** 里取消勾选它 |
| **国家代码**（Country code）下面写着 **两个字母，例如 CN。5 GHz 需要国家代码。** | 热点用 5 GHz，国家代码空着或不是两个字母                   | 填上所在国家的两个字母代码，例如 `CN`，再应用                   |

## 模块装不上

| 症状                                                                                                        | 原因                               | 处理                                                                            |
| ----------------------------------------------------------------------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------- |
| `module_fetch_failed`                                                                                       | 中枢取不到这个模块的安装文件       | 确认中枢能上网，再在模块上选 **安装**（Install）                                |
| `no_platform_build`，或模块显示为灰色，写着 **这台机器的系统不支持**（This machine's system cannot run it） | 这个模块没有适合这台机器系统的构建 | 换一台机器；[支持的平台](./platforms.md#各系统能用的模块)列出每个模块能用的系统 |

## 终端关闭

| 症状                | 原因                                                       | 处理                                                      |
| ------------------- | ---------------------------------------------------------- | --------------------------------------------------------- |
| `session_not_owned` | 客户端只能进自己开的会话或共享的会话，这个会话两者都不是   | 让打开它的一方打开 **共享**（Shared），或自己新开一个终端 |
| `session_unknown`   | 会话已结束，或被控端重启、升级过，那台机器上的会话全部结束 | 在那台机器上新开一个终端                                  |
| `shell_unknown`     | 中枢上已经没有客户端要调整大小的那个 shell                 | 在客户端里关掉这个终端，再打开                            |
| `unknown_terminal`  | `nclient terminal` 指定的机器，已加入的中枢都不提供终端    | 换成客户端 **终端**（Terminals）页里列出的机器            |

## 客户端连不上

| 症状                    | 原因                                         | 处理                                                                         |
| ----------------------- | -------------------------------------------- | ---------------------------------------------------------------------------- |
| `hub_unreachable`       | 这台电脑连不上中枢的 8443 端口               | 检查网络，或 **外部访问** 页上用的那条路，以及中枢的开放范围                 |
| `ticket_spent`          | 链接过期或已经用过                           | 在客户端里离开这台中枢，用 **客户端** 页的新链接重新加入；链接三十分钟内有效 |
| `admission_paused`      | 失败的加入太多，中枢暂停了新的加入           | 等码里给的秒数过去，客户端自己再加入                                         |
| `link_unreadable`       | 粘贴不完整                                   | 从中枢上复制整行                                                             |
| `link_not_for_client`   | 这是 **设备** 页给被控端用的链接             | 在 **客户端** 页生成一条                                                     |
| `client_disabled`       | 这个客户端在 **客户端** 页上停用了           | 在它那一行选 **启用**（Enable）                                              |
| `permission_denied`     | 客户端的权限不包括这类条目，或不包括那台机器 | 在 **客户端** 页放宽这个客户端的权限                                         |
| `client_held`           | 这台电脑上另一个账户的客户端在运行           | 让那个账户退出客户端（托盘菜单的 **退出**），再启动你自己的                  |
| `gui_webkitgtk_missing` | Linux 上缺 WebKitGTK                         | 装上提示里列出的包，再启动客户端                                             |
| `gui_webview2_missing`  | Windows 上缺 WebView2                        | 装上提示里列出的运行时，再启动客户端                                         |
| `root_refused`          | 用 `sudo` 启动了客户端                       | 用你自己的账户启动                                                           |

## 客户端的某一页连不到服务

这些码来自中枢，或来自提供这个条目那台机器的被控端，客户端把码写在条目那一行上。

| 症状                                 | 原因                                           | 处理                                         |
| ------------------------------------ | ---------------------------------------------- | -------------------------------------------- |
| `connect_failed`，原因 `refused`     | 那台机器上服务的端口没有程序在监听             | 在那台机器上启动这个服务或模块               |
| `connect_failed`，原因 `timeout`     | 服务 10 秒内没有应答                           | 确认机器和服务都在运行                       |
| `connect_failed`，原因 `unreachable` | 中枢连不到 **服务** 页上手动声明的那个地址     | 核对声明的地址，确认中枢连得到它             |
| `port_not_published`                 | 那台机器不再发布这个端口：容器、实例或共享停了 | 在 **模块** 页上把它重新启动                 |
| `connect_limit`                      | 这个客户端经中枢开着的连接到了 256 条          | 关掉用不着的转发或程序                       |
| `port_taken`                         | 本机别的程序占着 **指定** 的本地端口           | 在条目上选 **配置**（Configure），换一个端口 |

## 电脑上挂不上共享

| 症状                                                 | 原因                                                     | 处理                                                                      |
| ---------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------- |
| `mountpoint_invalid`                                 | 路径不在你的家目录下                                     | 填家目录下的文件夹，例如 `~/nas/media`                                    |
| `mountpoint_not_drive_letter`                        | Windows 上共享挂在盘符上                                 | 选一个空闲盘符，例如 `N:`                                                 |
| `mountpoint_not_empty`                               | 文件夹里有文件                                           | 换一个空文件夹                                                            |
| `mount_not_authorized`                               | polkit 的授权窗口关掉了，或你不在本机的屏幕前            | 再选一次 **挂载**（Mount），在授权窗口里确认                              |
| `mount_tooling_missing`                              | 缺 root 辅助程序或 `mount.cifs`                          | 重装客户端的包，它依赖 `cifs-utils`                                       |
| `pkexec_missing`                                     | Linux 上没有 `pkexec`，挂载要经过它                      | 用发行版的包管理器装上 `pkexec`，再选 **挂载**                            |
| `credentials_missing`                                | 保存登录信息的文件没了                                   | 选 **配置**，重新输入密码                                                 |
| `share_login_rejected`                               | 共享不接受这个用户名或密码                               | 选 **配置**，重新输入两者                                                 |
| `files_adapter_unavailable`                          | Windows 上 `NeutrinoClientFiles` 服务缺失、停止或出错    | 看码后面的原话，运行 `sc query NeutrinoClientFiles`；服务缺失时重装客户端 |
| `files_adapter_in_use`                               | Windows 上文件适配器正归这台电脑上另一个账户的客户端使用 | 让那个账户退出客户端，你的客户端随后自己再挂一次                          |
| 条目变灰，写着 **当前无法访问**（Not reachable now） | 提供共享的机器关着，或没有连到中枢                       | 让那台机器重新上线                                                        |

## 手机上连不上共享

Android 应用的共享出现在系统的“文件”应用里，出错时显示错误码对应的那句话。

| 症状                                              | 原因                                                         | 处理                                                                                                   |
| ------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| `share_unreachable`                               | 手机连不上中枢的 8443 端口，或提供共享的机器关着、没连着中枢 | 先在应用里看中枢那一行：不是 **已连接** 就经 **外部访问** 页上的一条路连上中枢；已连接就让那台机器上线 |
| “文件”里显示 **请先在文件页输入这个共享的密码。** | 这部手机还没有这个共享的登录信息                             | 在应用的文件屏打开这个共享，输入用户名和密码，选 **连接**（Connect）                                   |

## 远程桌面打不开

| 症状                     | 原因                                            | 处理                                                                 |
| ------------------------ | ----------------------------------------------- | -------------------------------------------------------------------- |
| `rdp_viewer_open`        | 这个桌面已经开着一个查看器                      | 关掉那个查看器窗口，再选 **连接**                                    |
| `rdp_nobody_seated`      | 那台机器的屏幕前没有人登录                      | 在那台机器上登录一个桌面会话                                         |
| `rdp_screen_not_allowed` | 那台机器还没在自己的屏幕上允许过屏幕共享        | 在那台机器的屏幕前允许一次屏幕共享                                   |
| `rdp_permissions_needed` | 那台 Mac 还没给 RustDesk 屏幕录制和辅助功能权限 | 在那台 Mac 的系统设置里给 RustDesk 打开 **屏幕录制** 和 **辅助功能** |

## AI 工具没走网关

| 症状                                          | 原因                                                            | 处理                                                                                                                |
| --------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `no_endpoint`                                 | 中枢还没给这个客户端发密钥                                      | 在中枢的 **AI** 页吊销这个客户端的密钥，让中枢重新发一个，或重新加入                                                |
| 选了 **保存**（Save）之后，工具仍用原来的配置 | **配置** 里的 **保存** 只记下选择，不改工具的指向               | 打开条目上的 **AI 工具使用此网关**（The AI tools use this gateway）；`nclient service ai show` 打印工具现在指向哪里 |
| 面板上写着 `gateway_unreachable`              | 网关进程没在运行                                                | Linux 上运行 `systemctl status neutrino_hub_cliproxyapi`；其他系统上看 **AI** 页的 **日志**（Journal）              |
| 某个工具什么都连不上                          | 工具指向客户端在 `127.0.0.1` 上的转发，客户端开着时这个转发才在 | 启动客户端，让它在托盘里一直开着                                                                                    |
| `login_expired`                               | 订阅登录拖得太久，这次登录过期了                                | 在 **AI** 页重新选 **登录**（Sign in），尽快走完                                                                    |
| 某个账户写着 `cc_switch_download_failed`      | 那台机器的被控端没能从中枢取到 cc-switch                        | 确认中枢能上网，再在 **全局配置**（Global configuration）里把开关关掉再打开                                         |
| `ai_tools_managed`                            | 这台电脑装了被控端，AI 工具由中枢设置                           | 在面板的 **模块**（Modules）页选这台电脑，在 **全局配置** 里设它的 AI 工具                                          |

| 想看什么               | 在哪                                                                                                                                                                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 初始化的过程           | 中枢上的 `/var/log/neutrino/hub/setup.log`                                                                                                                                                                                   |
| Linux 上的中枢         | 各单元的 journal：`journalctl -u neutrino_hub_web -n 200`，其他单元同理，例如 `neutrino_hub_xray`、`neutrino_hub_dnsmasq`、`neutrino_hub_cliproxyapi`、`neutrino_hub_netbird`、`neutrino_hub_easytier`、`neutrino_hub_relay` |
| macOS 上的中枢         | `/Library/Logs/Neutrino/hub/`，每个进程一个 `<name>.log`                                                                                                                                                                     |
| Windows 上的中枢       | `C:\ProgramData\Neutrino\hub\log\`，每个进程一个 `<name>.log`                                                                                                                                                                |
| 一次中枢升级           | Linux 上 `journalctl -u neutrino_hub_update`；macOS 和 Windows 上中枢日志目录里的 `hub_update.log`                                                                                                                           |
| Linux 上的被控端       | 在那台机器上运行 `journalctl -u neutrino_agent -n 200`                                                                                                                                                                       |
| Windows 上的被控端     | `C:\ProgramData\Neutrino\agent\log\agent.log`                                                                                                                                                                                |
| macOS 上的被控端       | `/Library/Logs/Neutrino/agent/agent.log`                                                                                                                                                                                     |
| Linux 上的桌面客户端   | `~/.config/neutrino/client/client.log`                                                                                                                                                                                       |
| macOS 上的桌面客户端   | `~/Library/Logs/Neutrino/client/client.log`                                                                                                                                                                                  |
| Windows 上的桌面客户端 | `%LOCALAPPDATA%\Neutrino\client\client.log`                                                                                                                                                                                  |
| 面板里看 AI 网关       | **AI** 页的 **日志**（Journal）                                                                                                                                                                                              |
| 一次渲染会生成什么     | 中枢上的 `sudo nhub apply --dry-run`                                                                                                                                                                                         |
