# 故障排查

按屏幕上出现问题的地方找到对应一节，再按看到的错误码或文字找到那一行，行里写着原因和处理办法。表里的 `<hub>` 代表 hub 那台机器的地址。

## 面板打不开

| 症状                                       | 原因                                                 | 处理                                                                                                                               |
| ------------------------------------------ | ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 浏览器打不开 `http://<hub>:8080`           | 面板单元没在运行、端口改过，或这个网络不在开放范围里 | 在 hub 上运行 `systemctl status neutrino_hub_web`，再看**网络**（Network）页的**面板端口**（Panel port）和**开放范围**（Exposure） |
| 一种协议打开是空白或连接重置，另一种能打开 | 面板在端口上只用 HTTPS 或 HTTP 中的一种              | 换另一种协议打开；**设置**（Settings）> **HTTPS** 下的**协议**（Scheme）显示当前用的是哪种                                         |
| 改了面板端口后会话断开                     | 会话 cookie 以端口命名，即 `neutrino_session_<port>` | 在新地址上重新登录                                                                                                                 |

## 浏览器提示证书有问题

这几行只在开启 HTTPS 后出现。面板的证书由 hub 自己的证书颁发机构签发，每个浏览器装上这个颁发机构后才信任它。

| 症状                                   | 原因                                                                            | 处理                                                                                                 |
| -------------------------------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 浏览器说证书颁发机构不受信任           | 这台设备没装颁发机构                                                            | 在**设置** > **HTTPS** 下选择**安装证书**（Install certificate），照这台设备的步骤做，然后重启浏览器 |
| 同一台机器上 Firefox 报警，Chrome 不报 | Firefox 有自己的一份颁发机构列表                                                | 照**安装证书**下 **Linux：Firefox**（Linux, Firefox）的步骤做                                        |
| 设置页改动之后，每个浏览器又开始报警   | **重新生成证书**（Regenerate certificate）换了一个新的颁发机构                  | 在每台设备上装新的颁发机构                                                                           |
| 浏览器说证书属于别的名字               | 地址栏里的地址不在**证书上的名字**（Certificate names）里；公网地址从来不在其中 | 改用那里列出的名字或地址打开面板，在局域网里可以用 `hub.neutrino.internal`                           |

## 锁定

| 症状                                                      | 原因                                                           | 处理                                                                  |
| --------------------------------------------------------- | -------------------------------------------------------------- | --------------------------------------------------------------------- |
| **多次失败后已锁定。**（Locked after repeated failures.） | 连续输错密码                                                   | 在 hub 上运行 `sudo nhub unlock`，它同时解除 fail2ban 的全部 SSH 封禁 |
| **密码不对。**（Wrong password.），而且忘了密码           | 面板密码丢了                                                   | 在 hub 上运行 `sudo nhub reset password`，所有会话随之登出            |
| 忘了保险库口令                                            | 运行中的机器仍用自己的工作密钥读保险库；用旧口令做的备份打不开 | 在机器上运行 `sudo nhub vault rekey` 设一个新口令，再下载一份新备份   |

## 设备离线

| 症状                                                                                | 原因                                                              | 处理                                                                            |
| ----------------------------------------------------------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 操作返回 `agent_offline`                                                            | 被控端没连上                                                      | 在那台机器上运行 `sudo nagent status`；显示服务已停时，运行 `sudo nagent start` |
| 机器在列表里，模块却改不了                                                          | 离线机器拒绝一切改动，hub 也不排队                                | 让机器重新上线，再应用一次                                                      |
| 模块显示为灰色，写着**这台机器的系统不支持**（This machine's system cannot run it） | 这个模块没有适合这台机器系统的构建，即 `no_platform_build` 的情形 | 换一台机器；[支持的平台](./platforms.md#各系统能用的模块)列出每个模块能用的系统 |

## hub 拒绝被控端或客户端

被控端在 `nagent status` 里显示这些错误码，桌面客户端显示在对应 hub 的那一行。

| 症状               | 原因                                                     | 处理                                                                                                                                                        |
| ------------------ | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `protocol_too_old` | 程序的协议号低于 hub 接受的下限；0.3 和 0.4 的包都是这样 | Linux 机器在**设备**（Devices）页的抽屉里选择**重新安装被控端**（Reinstall agent），它通过 SSH 安装；Windows、macOS 和所有客户端手动装 0.5.0 的包；绑定不变 |
| `protocol_too_new` | 程序的协议号高于 hub                                     | 在**设置**页升级 hub；绑定不变，程序会重新连上                                                                                                              |
| `hub_untrusted`    | hub 重置或重装过，证书换了                               | 用新链接重新加入：被控端的链接在**设备**页的**用链接添加**（Add by link）里，客户端的链接在**客户端**（Clients）页                                          |

## 虚拟网

| 症状                                                                | 原因                                                                 | 处理                                                                                                                |
| ------------------------------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 打开一个引擎，或保存 EasyTier 地址时，返回 `overlay_subnet_overlap` | 这个引擎的网段和另一个引擎的网段重叠，或和这台机器所在的某个网络重叠 | 改 EasyTier 的**虚拟网地址**（Overlay address），或在**网络**页改局域网的地址；NetBird 的网段固定是 `100.64.0.0/10` |
| **虚拟网**（Overlay）页上出现红色的 `overlay_default_route_refused` | 某个对端或控制台给了这台机器一条走虚拟网的默认路由，hub 删掉了它     | 在 NetBird 或 EasyTier 的控制台里删掉给 hub 的出口路由；这台机器始终用自己的上行出去                                |
| `overlay_route_overlap`，后面写着 **hub 撤不掉它**                  | 一条虚拟网路由和这台机器的某个网络重叠，hub 没能撤掉它               | 到管理这个虚拟网的地方修改或删除这条路由                                                                            |
| NetBird 的徽章写着**管理面不可达**（management unreachable）        | hub 从所在位置连不上管理面                                           | 在**代理**（Proxy）页打开**让 微子·中枢 自己的流量走代理**                                                          |
| NetBird 的**节点**（Peers）是空的                                   | 还没有别的设备登录                                                   | 在另一台设备上用 NetBird 应用登录                                                                                   |
| NetBird 路由已列出，局域网却访问不到                                | 控制台里这个子网没有 Access Control Policy                           | 给这个 Resource 加上策略                                                                                            |
| EasyTier 写着**还没有机器加入。**（No machine has joined yet.）     | 另一台机器的网络名或密码不一致                                       | 用**复制（含密码）**（Copy with the secret）重新复制命令                                                            |
| EasyTier 对端已加入，局域网却访问不到                               | 这个子网没有导出                                                     | 在**导出的局域网**（Exported networks）里加上它，然后应用                                                           |
| 两种引擎下，这台机器在虚拟网上都没有响应                            | 虚拟网不在开放范围里                                                 | 在**网络**页的**开放范围**里勾上它                                                                                  |

## 终端关闭

| 症状               | 原因                                                           | 处理                                                   |
| ------------------ | -------------------------------------------------------------- | ------------------------------------------------------ |
| `session_taken`    | 另一个窗口或设备连上了同一个会话；一个会话同一时间只连一个终端 | 再点一次这个会话的标签把它连回来，另一边的终端随之关闭 |
| `session_unknown`  | 会话已结束，或被控端重启、升级过；那台机器上的会话因此全部结束 | 在那台机器上新开一个终端                               |
| `shell_unknown`    | hub 上已经没有客户端要调整大小的那个 shell                     | 在客户端里关掉这个终端，再打开                         |
| `unknown_terminal` | `nclient terminal` 指定的机器，已加入的 hub 都不提供终端       | 换成客户端**终端**（Terminals）页里列出的机器          |

## 客户端连不上

| 症状                    | 原因                                         | 处理                                       |
| ----------------------- | -------------------------------------------- | ------------------------------------------ |
| `hub_unreachable`       | 这台电脑连不上 hub 的 8443 端口              | 检查网络或虚拟网，以及 hub 上的开放范围    |
| `enroll_refused`        | 链接过期或已经用过                           | 在**客户端**页生成新链接；链接五分钟内有效 |
| `link_unreadable`       | 粘贴不完整                                   | 从 hub 上复制整行                          |
| `link_not_for_client`   | 这是**设备**页的链接                         | 在**客户端**页生成一条                     |
| `client_disabled`       | 这个客户端在**客户端**页上停用了             | 在它那一行选择**启用**（Enable）           |
| `permission_denied`     | 客户端的权限不包括这类条目，或不包括那台机器 | 在**客户端**页放宽这个客户端的权限         |
| `gui_webkitgtk_missing` | Linux 上缺 WebKitGTK                         | 装上提示里列出的包，再启动客户端           |
| `gui_webview2_missing`  | Windows 上缺 WebView2                        | 装上提示里列出的运行时，再启动客户端       |
| `root_refused`          | 用 `sudo` 启动了客户端                       | 用你自己的账户启动                         |

## 电脑上挂不上共享

| 症状                                                | 原因                                           | 处理                                        |
| --------------------------------------------------- | ---------------------------------------------- | ------------------------------------------- |
| `mountpoint_invalid`                                | 路径不在你的家目录下                           | 填家目录下的文件夹，例如 `~/nas/media`      |
| `mountpoint_not_drive_letter`                       | Windows 把共享挂在盘符上                       | 选一个空闲盘符，例如 `N:`                   |
| `mountpoint_not_empty`                              | 文件夹里有文件                                 | 换一个空文件夹                              |
| `mount_not_authorized`                              | 关掉了 polkit 的授权窗口，或你不在本机控制台前 | 再选一次**挂载**（Mount），在授权窗口里确认 |
| `mount_tooling_missing`                             | 缺 root 辅助程序或 `mount.cifs`                | 重装客户端的包，它依赖 `cifs-utils`         |
| `credentials_missing`                               | 保存凭据的文件没了                             | 选择**配置**（Config），重新输入密码        |
| `share_login_rejected`                              | 共享不接受这个用户名或密码                     | 选择**配置**，重新输入两者                  |
| 条目变灰，写着**当前无法访问**（not reachable now） | 提供共享的机器关着，或这个网络不在开放范围里   | 让那台机器重新上线，或在 hub 上开放这个网络 |

## 手机上连不上共享

Android 应用的共享出现在系统的“文件”应用里，出错时显示错误码对应的那句话。

| 症状                                             | 原因                                                     | 处理                                                                                                              |
| ------------------------------------------------ | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `share_unreachable`，手机不在局域网里            | 手机的虚拟网没开                                         | 在应用里点 hub 那一行的**虚拟网**（Virtual network）开关，等它显示**已加入**（on）                                |
| 虚拟网**已加入**，仍是 `share_unreachable`       | 虚拟网不在开放范围里，或虚拟网没有路由到共享所在的局域网 | 在**网络**页的**开放范围**里勾上虚拟网；EasyTier 在**导出的局域网**里加上那个局域网，NetBird 加一条路由和它的策略 |
| “文件”里显示**请先在文件页输入这个共享的密码。** | 这台手机还没有这个共享的登录信息                         | 在应用的文件页打开这个共享，输入用户名和密码，选择**连接**（Connect）                                             |

## AI 工具没走网关

| 症状                                         | 原因                                           | 处理                                                                                                                    |
| -------------------------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `no_endpoint`                                | hub 还没给这个客户端发密钥                     | 在 hub 的 **AI** 页撤销这个客户端的密钥，让 hub 重新发一个，或重新加入                                                  |
| 选了**保存**（Save）之后，工具仍用原来的配置 | **配置**里的**保存**只记下选择，不改工具的指向 | 打开条目那一行的 **AI 工具使用此网关**（The AI tools use this gateway）；`nclient service ai show` 打印工具当前指向哪里 |
| 面板上写着 `gateway_unreachable`             | 网关进程没在运行                               | 在 hub 上运行 `systemctl status neutrino_hub_cliproxyapi`                                                               |
| 改过端口后某个工具连不上                     | 那台机器上的端点还是旧端口                     | 在每个客户端上重新应用这个条目，手动配置的工具里换上新端点                                                              |

## 日志在哪

| 想看什么           | 在哪                                                                                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 初始化的过程       | hub 上的 `/var/log/neutrino/setup.log`                                                                                                                                          |
| hub 自己的日志     | hub 上的 `/var/log/neutrino/`                                                                                                                                                   |
| hub 的某个单元     | `journalctl -u neutrino_hub_web -n 200`，其他单元同理：`neutrino_hub_xray`、`neutrino_hub_dnsmasq`、`neutrino_hub_cliproxyapi`、`neutrino_hub_netbird`、`neutrino_hub_easytier` |
| 一次 hub 升级      | hub 上的 `journalctl -u neutrino_hub_update`                                                                                                                                    |
| Linux 上的被控端   | 在那台机器上运行 `journalctl -u neutrino_agent -n 200`                                                                                                                          |
| Windows 上的被控端 | `%ProgramData%\Neutrino\agent\agent.log`                                                                                                                                        |
| macOS 上的被控端   | `/Library/Logs/neutrino_agent.log`                                                                                                                                              |
| 面板里看 AI 网关   | **AI** 页的**日志**（Journal）                                                                                                                                                  |
| 一次渲染会生成什么 | hub 上的 `sudo nhub apply --dry-run`                                                                                                                                            |
