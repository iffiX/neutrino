# 中文写法

中文页面由中文写作者按本文写成，从共享的大纲出发，从中文资料取句法。英文页面的句子不进入中文页面。

| --- | --- |

## 语气与人称

| 规则 | 原因 |
| --- | --- |
| 称读者为“你”，全文一致，不用“您”，不混用。 | 人称变来变去，读者不知道在对谁说。 |
| 作者不出现：不用“我们”“让我们”“笔者”。 | 作者并不在读者身边。 |
| 平实、直接、对话式，但不口语：没有“聊到这里”“接下来看看”。 | 口语句冗长而无信息。 |
| 说明事实，不推销；不用反问句，不用感叹句。 | 反问让读者觉得被质疑，感叹让读者觉得被责备。 |
| 不用“请”“抱歉”，除非确实给读者造成了困扰。 | 步骤是指令，不是请求。 |
| 不拟人：程序返回、写入、启动、停止、以错误码拒绝；程序不等待、不想要、不询问、不回答、不决定。 | 拟人掩盖是哪个组件在动作。 |

## 句子

| 规则 | 原因 |
| --- | --- |
| 无标点的单句或逗号分开的分句不超过 20 字；30 到 39 字必须语义明确；40 字以上一律拆开。 | 长句读到句尾忘了句头。 |
| 逗号串起的长句总长不超过 100 字或三行。 | 超过三行读者要回头找主语。 |
| 用简单句和并列句，少用复合句。 | 复合句把修饰塞进主语。 |
| 同一意思用肯定句，不用否定句，不用双重否定。 | “确认电源已关闭”比“确认没有接通电源”少一次转折。 |
| 主动语态；被字句不出现。英文的 is rejected 在中文是“中枢拒绝……”或“返回 `<code>`”。 | 汉语被字句带负面含义，与英文被动式不对应。 |
| 一个名词前最多两个“的”；第三个“的”出现就拆句。 | 的字链让读者数不清哪个修饰哪个。 |
| “其”“该”“此”“这”所指只能有一个；有歧义就重复名词。 | 代词歧义在技术文档里是事故。 |
| “对……进行……”改为动词直接带宾语；“可以”只在说明可选项时出现。 | 多余的字对表达没有作用。 |
| 的、地、得各归其位。 | 用错一处，句子成分就错位。 |
| 一段一个主题，中心句在段首；一段不超过七行，四行最佳。 | 段首句就是读者要不要读下去的依据。 |

## 标题、界面名、占位符、代码

| 项目 | 规则 |
| --- | --- |
| 标题 | 末尾无标点；不跳级；同级不能只有一个；下级不重复上级的名字；最深到四级 |
| 界面名 | 加粗，与界面显示完全一致；首次出现时括注英文原文：**保存**（Save） |
| 错误码 | 行内代码原样引用，后面最多跟一个短语解释一次 |
| 占位符 | 只在代码里出现，形如 `<kebab-case>`；首次出现前一句说明它代表什么；正文用名词，如“中枢地址” |
| 代码块 | 标注语言；不带 `$` 提示符；输出放在紧随其后的 `text` 块 |
| 有序列表 | 每项都写 `1.`，由渲染器编号；一项一个动作；一个步骤序列不超过九步 |
| 列表标点 | 各项统一：都是句子就都用句号，都是词组就都不加 |

## 排版与数字

| 规则 | 出处 |
| --- | --- |
| 中文与英文、中文与数字之间一个半角空格；数字与单位之间一个空格；百分号和度数除外。 | 排版指北，阮一峰 字间距 |
| 中文句子用全角标点；整句英文用半角标点；全角标点前后不加空格。 | 阮一峰 标点 |
| 并列词用顿号；引号用“ ”，内层用‘ ’。 | 阮一峰 标点 |
| 括号内全是英文用半角括号且前后各一个空格；括号内含任何中文用全角括号且不加空格。 | yikeke 中英混排 |
| 句子中间不用破折号；用逗号、句号或括号。 | 本仓库规则 |
| 阿拉伯数字一律半角；数值范围用“～”连接，两端都带单位。 | 阮一峰 数字 |
| 增加写“增加了”或“增加到”，减少写“降低了”或“降低到”；不写“降低 N 倍”。 | yikeke 语法 |
| 专有名词大小写与官方一致：GitHub、macOS、NetBird。 | 排版指北 |

| 中文 | 说明 |

| hub 或 中枢 | 一页里只用一种 |

## 禁用词与改写

| 禁用 | 改写 |
| --- | --- |
| 赋能 | 让用户能 X |
| 闭环 | X 之后 Y 也接进去了 |
| 抓手 | 能改的那个变量是 X |
| 打通、链路打通 | A 现在能调用 B |
| 沉淀 | 记录到 docs/X |
| 落地 | 在 A 模块实现 |
| 底座、底层逻辑 | 基础设施层是 X；这件事成立的前提是 Y |
| 生态 | 列出具体依赖、用户类型或集成方 |
| 心智、认知负担 | 需要记住 X 个步骤 |
| 收口 | 所有 X 都走 Y 一个入口 |
| 加持 | 加了 X 之后能 Y |
| 极致、丝滑、顺畅 | 具体指标：延迟多少，步骤几步 |
| 深度集成、一站式 | 集成点的具体范围；在 A 入口能完成 B、C |
| 颠覆、重塑 | 删除 |
| 很值得、非常值得 | 值得在哪个维度，写出来 |
| 最佳、最好、最先进、最新技术 | 删除评价，留事实 |
| 很好地、较多、大量、一些、几乎、数倍 | 具体数字或实例 |
| 显然、真正、很清楚、说明了一件事 | 删除，直接写结论和证据 |
| 很现实、很重、很顺 | 先写条件，再写对象，最后写判断 |
| 魔改、打到 60%、童鞋、同学 | 网络用语和论坛称呼不出现：特殊优化，使用率为 60%；称呼读者只用“你” |

## 禁用句式

| 句式 | 识别 | 改法 |
| --- | --- | --- |
| 不是……而是……、不在……而在…… | 先否定一个没人提出的说法 | 只写肯定的那半句 |
| 评价腔 | 句子只有作者感受，没有约束或数字 | 写条件、对象、判断三段 |
| 排比、三段式 | 三个并列短句押同一节奏 | 写实际数量的项目，节奏不同 |
| 口号式标题 | 标题是宣传语，不是内容名 | 标题写这一节是什么 |
| 过场句、主持句 | 删掉不影响论证 | 直接删除，不改写成另一句过场话 |
| 数字引领 | “有三个方面”“分两步”后接列表 | 删掉数字，列表自己显示长度 |
| 反问句 | 句末问号，作者已知答案 | 陈述句 |
| 隐喻动作 | 散落、收拢、延展、落在、停在 | 提供了、整理出、集中到、最终生成 |
| 英文直译词 | “变得很现实”“实现了”对应 real、realize | 写具体约束 |
| 被字句 | 句中有“被” | 主语换成动作方，或用错误码 |
| 拟人 | 程序等待、询问、拒绝回答 | 程序返回、拒绝并给出错误码 |
| 空冒号句 | “结论：要测试。” | 带动词的完整句 |
| 结尾总结 | “综上”“总之”“以上就是” | 删除整段 |

## 句式范例

每条是范例，适合所标场合，一页最多用一次。用其形，不用其词。

| 范例 | 场合 |
| --- | --- |
| `nhub apply --dry-run` 渲染所有模块，对系统不做任何改动。 | 参考条目的第一句 |
| 读完这一页，被控端已经在向中枢汇报。 | 操作指南或快速开始的开头 |
| 开始之前，这台机器要能访问中枢。 | 步骤前的前提条件 |
| 在**网络**（Network）面板中，选择**应用**（Apply）。 | 界面内的一步 |
| 如果这台机器只有一个网口，跳过这一步。 | 条件步骤 |
| 运行 `sudo systemctl restart neutrino_hub_web`。面板会断开当前会话，需要重新登录。 | 结果不可见时的一步 |
| 地址可以在面板里设置，也可以写在 `config/network/lan.json` 里。 | 说明可选项 |
| 令牌超过有效期时，中枢拒绝请求并返回 `token_expired`。 | 排障页里的原因句，错误码为示例 |
| 配置集是一组有名字的路由，客户端整体应用它。 | 参考或概述中的定义句 |
| 面板只以 `config/` 为准，所以备份这个目录就能复原整台机器。 | 设计页里带原因的规则 |
