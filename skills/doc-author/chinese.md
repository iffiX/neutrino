# 中文写法

中文页面由中文写作者按本文写成，从共享的大纲出发，从中文资料取句法。英文页面的句子不进入中文页面。

## 语气与人称

| 规则 | 原因 |
| --- | --- |
| 称读者为“你”，全文一致，不用“您”，不混用。 | 人称变来变去，读者不知道在对谁说。 |
| 作者不出现：不用“我们”“让我们”“笔者”。 | 作者并不在读者身边。 |
| 平实、直接、对话式，但不口语：没有“聊到这里”“接下来看看”。 | 口语句冗长而无信息。 |
| 说明事实，不推销；不用反问句，不用感叹句。 | 反问让读者觉得被质疑，感叹让读者觉得被责备。 |
| 不用“请”“抱歉”，除非确实给读者造成了困扰。 | 步骤是指令，不是请求。 |
| 不拟人：程序返回、写入、启动、停止、以错误码拒绝；程序不等待、不想要、不询问、不回答、不决定。人做的事，主语是“你”。 | 拟人掩盖是哪个组件在动作，也让读者分不清哪一步要自己做。 |

## 句子

| 规则 | 原因 |
| --- | --- |
| 无标点的单句或逗号分开的分句不超过 20 字；30 到 39 字必须语义明确；40 字以上一律拆开。 | 长句读到句尾忘了句头。 |
| 逗号串起的长句总长不超过 100 字或三行。 | 超过三行读者要回头找主语。 |
| 用简单句和并列句，少用复合句。 | 复合句把修饰塞进主语。 |
| 同一意思用肯定句，不用否定句，不用双重否定。 | “确认电源已关闭”比“确认没有接通电源”少一次转折。 |
| 主动语态；被字句不出现。英文的 is rejected 在中文是“中枢拒绝……”或“返回 `<code>`”。 | 汉语被字句带负面含义，与英文被动式不对应。 |
| 一个名词前最多两个“的”；第三个“的”出现就拆句。 | 的字链让读者数不清哪个修饰哪个。 |
| “其”“该”“此”“这”所指只能有一个；有歧义就重复名词。 | 代词歧义在技术文档里是事故。 |
| “对……进行……”改为动词直接带宾语；“可以”只在说明可选项时出现。 | 多余的字对表达没有作用。 |
| 的、地、得各归其位。 | 用错一处，句子成分就错位。 |
| 一段一个主题，中心句在段首；一段不超过七行，四行最佳。 | 段首句就是读者要不要读下去的依据。 |

## 标题、界面名、占位符、代码

| 项目 | 规则 |
| --- | --- |
| 标题 | 末尾无标点；不跳级；同级不能只有一个；下级不重复上级的名字；最深到四级 |
| 界面名 | 加粗，与界面显示完全一致；只在面板本身显示英文的地方括注英文，其余一律不括；全站一张中英术语表 |
| 错误码 | 只在故障排查页出现，行内代码原样引用，后面最多跟一个短语解释一次；指南页每节末尾一句「失败时见故障排查」；概述页不出现错误码 |
| 占位符 | 只在代码里出现，形如 `<kebab-case>`；首次出现前一句说明它代表什么；正文用名词，如“中枢地址” |
| 代码块 | 标注语言；不带 `$` 提示符；输出放在紧随其后的 `text` 块 |
| 有序列表 | 每项都写 `1.`，由渲染器编号；一项一个动作；一个步骤序列不超过九步 |
| 列表标点 | 各项统一：都是句子就都用句号，都是词组就都不加 |

## 排版与数字

| 规则 | 出处 |
| --- | --- |
| 中文与英文、中文与数字之间一个半角空格；数字与单位之间一个空格；百分号和度数除外。 | 排版指北，阮一峰 字间距 |
| 中文句子用全角标点；整句英文用半角标点；全角标点前后不加空格。 | 阮一峰 标点 |
| 并列词用顿号；引号用“ ”，内层用‘ ’。 | 阮一峰 标点 |
| 括号内全是英文用半角括号且前后各一个空格；括号内含任何中文用全角括号且不加空格。 | yikeke 中英混排 |
| 句子中间不用破折号；用逗号、句号或括号。 | 本仓库规则 |
| 阿拉伯数字一律半角；数值范围用“～”连接，两端都带单位。 | 阮一峰 数字 |
| 增加写“增加了”或“增加到”，减少写“降低了”或“降低到”；不写“降低 N 倍”。 | yikeke 语法 |
| 专有名词大小写与官方一致：GitHub、macOS、NetBird。 | 排版指北 |

## 产品用语

| 中文 | 说明 |
| --- | --- |
| 微子 | 产品名；“中微子”不出现 |
| 中枢 | 中文里一律写中枢，不写 hub；英文里一律写 hub |
| 被控端 | agent |
| 客户端 | client |
| 面板 | hub 的网页界面 |
| 系统 | 加入中枢的一台电脑；正文不写“机器”，加粗的屏幕原话除外 |
| 安装 | 不写“装上” |
| 使用 | 应用页的标题写“使用”，不写“打开”或“连接” |

## 禁用词与改写

| 禁用 | 改写 |
| --- | --- |
| 赋能 | 让用户能 X |
| 闭环 | X 之后 Y 也接进去了 |
| 抓手 | 能改的那个变量是 X |
| 打通、链路打通 | A 现在能调用 B |
| 沉淀 | 记录到 docs/X |
| 落地 | 在 A 模块实现 |
| 底座、底层逻辑 | 基础设施层是 X；这件事成立的前提是 Y |
| 生态 | 列出具体依赖、用户类型或集成方 |
| 心智、认知负担 | 需要记住 X 个步骤 |
| 收口 | 所有 X 都走 Y 一个入口 |
| 加持 | 加了 X 之后能 Y |
| 极致、丝滑、顺畅 | 具体指标：延迟多少，步骤几步 |
| 深度集成、一站式 | 集成点的具体范围；在 A 入口能完成 B、C |
| 颠覆、重塑 | 删除 |
| 很值得、非常值得 | 值得在哪个维度，写出来 |
| 最佳、最好、最先进、最新技术 | 删除评价，留事实 |
| 很好地、较多、大量、一些、几乎、数倍 | 具体数字或实例 |
| 显然、真正、很清楚、说明了一件事 | 删除，直接写结论和证据 |
| 很现实、很重、很顺 | 先写条件，再写对象，最后写判断 |
| 魔改、打到 60%、童鞋、同学 | 网络用语和论坛称呼不出现：特殊优化，使用率为 60%；称呼读者只用“你” |

## 禁用句式

| 句式 | 识别 | 改法 |
| --- | --- | --- |
| 不是……而是……、不在……而在…… | 先否定一个没人提出的说法 | 只写肯定的那半句 |
| 评价腔 | 句子只有作者感受，没有约束或数字 | 写条件、对象、判断三段 |
| 排比、三段式 | 三个并列短句押同一节奏 | 写实际数量的项目，节奏不同 |
| 口号式标题 | 标题是宣传语，不是内容名 | 标题写这一节是什么 |
| 过场句、主持句 | 删掉不影响论证 | 直接删除，不改写成另一句过场话 |
| 数字引领 | “有三个方面”“分两步”后不接名字 | 删掉数字；要写数量，就紧接着写出名字，再每项一个列表项 |
| 反问句 | 句末问号，作者已知答案 | 陈述句 |
| 隐喻动作 | 散落、收拢、延展、落在、停在、铸、递给、扛、承载、跑在 | 提供了、整理出、集中到、最终生成、生成、发给、运行在 |
| 英文直译词 | “变得很现实”“实现了”对应 real、realize | 写具体约束 |
| 被字句 | 句中有“被” | 主语换成动作方，或用错误码 |
| 拟人 | 程序等待、询问、拒绝回答 | 程序返回、拒绝并给出错误码 |
| 空冒号句 | “结论：要测试。” | 带动词的完整句 |
| 结尾总结 | “综上”“总之”“以上就是” | 删除整段 |

## 手册的坏模式

手册是技术文档，读者要知道一样东西是什么、怎么用。下面的坏例子都来自手册草稿。

| 坏模式 | 坏例子 | 改法 |
| --- | --- | --- |
| 无头开头：标题下第一句没有主语，接不上标题 | 微子·中枢是什么：把应用部署到自己的电脑上，从任何地方安全地使用，也能分享给别人。 | 第一句以标题说的东西开头，说它是什么，或者对“你”说话：微子·中枢是开源、自托管的应用部署面板。 |
| 目录式开头：第一句罗列这一页的话题 | 中枢、被控端和客户端怎么配合，一条连接从手机走到应用要经过哪里。 | 直接写内容：设备只连接中枢的一个端口，中枢检查权限后连接应用。 |
| 自问自答：用问句引出事实 | 宽带有公网地址？手机直接连回来，不经别人的服务器，也不用账号。 | 写条件句：如果你的宽带有公网地址，可以用直连。 |
| 使动定义：用“把”代替“是” | 文件共享把系统上的文件夹变成笔记本上的一个盘、手机上的一个位置。 | 写“X 是……的功能”，一句说完：文件共享是把你的系统上的文件夹挂载到客户端的某个路径或者盘符来直接读写的功能。 |
| 数量不接名字，并列项挤成一段 | 共享分两种。主目录就是账户自己的文件夹，比如 Linux 上的 `/home/lab`，主目录共享会把它整个共享出去。文件夹共享只共享你选的一个文件夹。 | 紧接着写名字，每种一个列表项：共享分两种：主目录共享和文件夹共享。 |
| 自说自话：谈论文档本身，或者不对任何人说话 | 微子·中枢的设计可以用一句话概括。这一页按这条线讲清楚每一步。这一页说明默认的安全模型。 | 删掉，直接写事实；读者要做事时写“你”。 |
| 把东西写活：设备或程序做了只有人能做的事 | 这台设备要先安装客户端。 | 人做的事，主语是“你”：你要在这个设备上安装客户端。程序写它实际执行的动作。 |
| 口语词代替术语 | 钥匙也在你自己的设备上。手机用加入链接里的公钥认出中枢。 | 用中文技术文档的常用词，见下表。 |
| 缺衔接词：结果句硬接在动作后面 | 你安装被控端之后，设备页里就多出这个系统。 | 适当加“会”这类衔接词：你安装被控端之后，设备页里就会多出这个系统。 |
| 条件句没有主语：读者不知道在说谁 | 不想让人开终端，就取消勾选账户。打不开时，查看故障排查。 | 写“如果你……”，并说清对象：如果你不想让人使用某个账户的终端，就取消勾选账户。如果你打不开终端，查看故障排查。 |
| 单句口语回答 | 什么都看不到。 | 写完整句和机制：连接的前几个字节不对时，中枢不回应，5 到 30 秒后断开连接。 |
| 给别人打广告：第三方服务的页面在讲它的好处 | 不买服务器也行：开个免费账号，外面的同学也打得开链接。 | 只写它是什么、中枢怎么用它：SakuraFrp 是第三方隧道服务，中枢运行 frpc 连接它的节点，由节点转发连接。免费额度放在开头的小表格里，写明读取日期，不写好处。 |
| 推销腔：首页的写法进了手册 | 登录就看到流量、系统和 AI 用量，不用到处点。 | 写页面显示什么、怎么操作：**总览** 显示流量、系统和 AI 用量。 |
| 整页口语：安全模型、工作原理这类页面从头到尾是问答 | 我电脑上的其他程序能碰到吗 | 口语回答集中放在“快速回答”一节；“技术架构”一节面向有技术背景的读者，写协议、路由和架构图。 |
| 写出防护的具体数值：容易让人据此调整攻击 | 每条连接随机读取 20 到 100 字节，保持 5 到 30 秒后重置；未准入的连接最多 128 个。 | 只写机制，可以省的数字都省略：随机读取一定数量的字节，随机保持一段时间后重置；未准入的连接有总数上限。读者操作时要用到的数值照写，如链接 30 分钟内有效。 |
| 写日期：页面描述的是现在的产品 | 下面是 2026-10-26 的实测结果。 | 删掉日期：实测结果如下。只有调查厂商的表格写读取日期。 |
| 用情绪写条件 | 不要了；想反悔；不想等了 | 如果不再需要；如果你要放弃 |
| 结果句口语收束 | 这时就安装好了。 | 这时安装完成。 |
| 表格里写“同上” | 同上 | 写全内容，读者不用回头找 |
| 定义后接宣传半句 | code-server 是开源的网页版 VS Code，不用接受微软的条款，手机上也能写代码。 | 定义到句号为止，后面的事实另起一句，对“你”说。 |
| 一个东西多个叫法 | 人在外面时，要给中枢开一条连回来的路。 | 一个东西一个名字，用界面上的名字：你不在这个网络时，要开启一种外部访问。 |
| 指代不明：它、那边、这边、对面没有明确对象 | 那边连上或断开时，App 会再试一轮。 | 写出名词：NetBird 或 EasyTier 连接或断开时，App 会重新尝试连接。 |
| 主语错位：动作不是主语做的 | 分享的访客不留记录，也不留地址。 | 主语换成动作方：中枢不记录分享访客的身份和地址。 |
| 没有主语的“要”句 | Windows 上要先在账户表单里填这个账户的密码。 | 写“你要”：在 Windows 上，你要先在账户表单里填写这个账户的密码。 |
| 空句引出下文 | 状态的意思是这样的。 | 写主题和“如下”：各状态的含义如下。 |
| 句尾口语收束 | 已经填好了默认值，看一眼就行。 | 删掉“就行”“就好”“一下”“看一眼”，写动作：确认默认值。 |
| 口语小节标题 | 差在哪；以后；试一下；小心 | 标题写这一节是什么：不同点；后续维护；验证连接；风险。 |
| 用猜测的语气写原因 | 多半是链接过期或用过了。 | 通常是链接过期或者已经用过。 |
| 产品名时长时短 | 微子不带它。 | 写全名“微子·中枢”；界面原话 **微子** 除外。 |
| 默认读者在某个地方 | 别的照旧走家里的线路。 | 写具体对象：其余流量走这台电脑自己的线路。 |
| 问题问了几样，回答少一样 | 问题问了聚合工具和 Claude 自带的远程，回答只说了聚合工具。 | 问了几样就答几样。 |
| 只有一步的编号列表 | 只有一项的 `1.` | 写成一句话，不编号。 |

## 句式范例

每条是范例，适合所标场合，一页最多用一次。用其形，不用其词。

| 范例 | 场合 |
| --- | --- |
| `nhub apply --dry-run` 渲染所有模块，对系统不做任何改动。 | 参考条目的第一句 |
| 你安装被控端之后，面板左侧栏就会多出这个系统，下面的每一步都在这个系统的页面上做。 | 操作指南的开头（每页各写各的，不套这一句） |
| 开始之前，你要确认这个系统能访问中枢。 | 步骤前的前提条件 |
